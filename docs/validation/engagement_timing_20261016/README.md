# 전함 전투 기능 유지시간과 요격함 강습 도착 — 2026-10-16

요격함이 도착하기 전에 전함 교전이 끝나는 문제를 분리 시험했다. 승률 50%를 강제하는 조정이 아니라, 주력함과 요격함이 같은 시간대에 싸울 기회를 늘리는 첫 조정이다. 대규모 전투 전체의 균형이 해결됐다는 뜻은 아니다.

## 적용 데이터

- 지구·화성 전함의 기존 모듈 HP ×3, 구조 HP ×3, 실드 **용량만** ×4. 지구 구조 7,200→21,600 / 실드 1,200→4,800, 화성 구조 5,400→16,200 / 실드 816→3,264.
- 전함 탄약고·반응로·발전기·전력망의 치명타 에너지 문턱 ×2. 기존 치명 파괴 확률, 복구 후 위험 증가, 이미 파괴된 부위의 구조 피해, 구조 피해의 복구 불가 규칙은 그대로다. 비치명 모듈에 새 유폭 확률을 주지 않았다.
- 실드 재생, 응급복구 횟수·시간, 무장 성능·탄약, 어뢰 구조 피해 보너스, 호위함과 요격함의 내구도는 유지했다. 상위 전함 변형과 선체 연구 개량 수치를 재생성했다.
- 기본 요격함의 자동 강습 계획 거리: 지구 85→136km, 화성 100→160km. **아군 보호 기준점에서 관측된 표적까지의 접근 계획 거리**이며 어뢰 사거리가 아니다. 식별·호위망 관측·편대 상태·직접 명령·발사 잠금/사거리 검사를 계속 사용한다. 정찰함은 계속 정찰 임무를 우선한다.
- 새 `Ai.AssaultReachMeters`가 없거나 0이면 기존 설계 계통별 범위를 쓴다. 실제 좌표를 읽어 미탐지 적 호위함의 존재를 알아내지는 않는다.

이는 소폭 HP 조정이 아니다. HP/실드 하나만 소폭 보강해서는 결과가 안정적으로 개선되지 않아, 계통 기능과 구조를 함께 보강한 후보를 선택했다. 장전·명중 오차는 이번에 더 조정하지 않았다.

## 시험과 선택

양측 전함 1+호위함 2, 요격함 없음/양측 각각 5척. 시작 거리 20/70/130km, Blue/Red 교환 및 공간 교환, 최대 25분, 기존 섬멸전 규칙. 위치·방향·호출부호·난수 소비는 후보 간 고정한다. 수치 후보는 카탈로그를 변경하지 않고 복제 정의로 실행했다.

1. 시드 1·2에서 기준 및 후보 탐색. `pilot-*`는 핵심부 HP/실드/구조/전진 배치/접근 거리 분리 시험이다.
2. `window-*`에는 전투 기능 유지시간과 실제 어뢰 발사 순간의 양측 전함 상태 계측을 추가했다. 핵심부만 보강하면 포탑·전력망을 잃은 채 잔해처럼 오래 남는 경우가 있어 개선 지표를 바꿨다.
3. `all3-structure3`를 선택한 뒤 **별도 시드 3~8**, 기준·후보 각각 144판 확인. 추가 시드 결과로 후보를 다시 탐색하지 않았다.
4. 실제 JSON 적용 후 시드 1~8, 192판 재실행. 실행시간을 제외한 함선 통계·사건·승패·어뢰 기록·발사 순간 상태가 후보와 모두 일치한다.

12km 전진 배치는 일부 승패를 바꾸지만 강습과 전함 교전을 안정적으로 겹치게 하지 못해 적용하지 않았다. 더 강한 전체 HP ×4 후보도 시험했으나 더 작은 ×3 후보로 별도 시드의 개선을 확인했다. 이전 단계의 수치와 결과는 삭제하지 않았다.

`FightingSeconds`는 `Squadron.Active`이고 주무장 기능 비율이 10%를 넘는 틱의 합계다. **계속 발사했다는 시간은 아니며**, 잠금 유무도 포함하지 않는다. 어뢰 발사마다 양측 전함이 이 조건을 만족하는지를 별도로 기록한다(60Hz 틱 단위). 전투 종료 시 남은 함선의 시간은 종료 시점에서 관측이 끊긴다. 섬멸전 종료 문턱과 편대 추가 전력 때문에 단순 전투시간/격침시간만 생존성으로 해석하지 않는다.

## 기본 요격함 포함 결과

각 거리 32판(8개 시드 × 팀·공간 교환). 서로 독립적인 시드 32개는 아니다.

| 시작 거리 | 지구:화성 승수 전→후 | 지구 전함 기능 유지 중앙값 | 화성 전함 기능 유지 중앙값 | 양측 전함 기능 유지 중 어뢰 전→후 |
|---|---|---|---|---|
| 20km | 32:0 → 32:0 | 46→68초 | 6→9초 | 0→0발 |
| 70km | 29:3 → 31:1 | 142→181초 | 16→25초 | 0→48발 |
| 130km | 3:29 → 11:21 | 62→190초 | 392→227초 | 0→198발 |

130km의 동시 교전 어뢰 198발은 지구 46발/5판, 화성 152발/16판이다. 모든 전투에서 합동 강습이 성립한 것은 아니다. 지구 전함 무사격은 **4/32척→0/32척**. 같은 거리 전체 어뢰 명중/발사는 지구 13/41→137/222, 화성 14/64→54/184다. 이 명중 수에는 전함 무력화/격침 후 공격도 포함되므로 198발의 명중률로 사용하면 안 된다.

별도 시드만 보면 130km 지구 전함 기능 유지 중앙값 **63→190초**, 동시 교전 어뢰 **0→127발**, 승수 **3:21→10:14**다. 중근거리 지구 과우세는 남고, 70km 승수는 오히려 더 기울었다. 20km 화성 전함은 32척 모두 격침되던 상태에서 19척 격침·13척 무력화로 바뀌었으므로, 이 구간에서 잔해 생존 증가를 기능 개선으로 포장하지 않는다.

## 전함 단독 및 24척 함대전 확인

추가 시드 1~4·팀/공간 교환, 거리 3개, 단독/양측 호위 2척으로 96판 확인했다. 전함 단독의 지구:화성 승수는 20km **4:12→10:6**, 70km **10:6→5:11**, 130km **1:15→1:15**. 중근거리 결과도 바뀌므로 전함끼리 어디서나 화성이 조금 우세해졌다고 주장하지 않는다. 같은 시드의 호위 조합은 15:1→15:1 / 16:0→13:3 / 5:11→5:11이다(`solo-comparison.json`).

24척은 이전 검증과 동일한 150km, 양측 전함 1+호위함 6+소형함 5다. 지구 소형함은 정찰 T3, 화성은 강습 T3로 서로 다른 임무 편성이다.

| 편성 | 이전 지구:화성 | 적용 후 지구:화성 |
|---|---|---|
| 지구 Blue / 화성 Red, 8판 | 4:4 | 0:8 |
| 화성 Blue / 지구 Red, 8판 | 1:6, 무1 | 2:6 |
| 비대칭 합계 | 5:10, 무1 | 2:14 |

지구 전함 대응 사격은 16/16척 유지됐지만 **전체 함대전 승패는 악화**됐다. 화성 강습 T3 어뢰는 6발/3명중→174발/6명중으로 공격 기회가 늘어난 반면 대부분은 명중으로 이어지지 못했다. 지구 정찰 T3는 정찰 역할을 유지해 양쪽의 어뢰 기여를 동등하게 기대할 편성이 아니다. 지구 대칭 4판은 Blue:Red 3:1→2:2, 화성 대칭 4판은 0:4→1:3이다.

전용 갈래만 이전 접근 범위로 되돌린 분리 시험도 했다(`specialist-pilot/`, 8판 + 동일 복제 검증 2판). 새 범위/기존 범위 모두 화성 6승·지구 2승으로 합계는 같고 팀별 승패만 엇갈려, 범위 상속만을 원인으로 판단하거나 원복하지 않았다. 복제 대조군 48개 함선 행은 원래 실행과 일치했다. 이 분리 시험은 새 후보 선택의 근거로 사용하지 않는다.

이 패치는 **기본 요격함의 장거리 합동 교전 기회 개선**으로 한정한다. 전용 정찰·강습 편성의 지원 효과, 중근거리 첫 관통으로 인한 기능 상실, 전함 단독의 거리별 편중은 후속 조정 과제다. 큰 HP 조정과 24척 결과의 악화를 감안해 최종 밸런스 수치로 고정하지 않는다.

## 기능 검증

- 전체 **5,607,966개 / 59개 묶음** 통과. 접근 계획 신규 47개에 큰 좌표·미관측 표적·직접 복귀·식별된 호위망과 180초 자동 운용 검사를 포함한다.
- 기존 요격 임무의 140km 고정 회귀는 새 화성 접근 범위 안에 들어간다. 그 검사는 명시적인 기존 범위(0)로 호환성을 검증하고, 새 범위의 관측된 호위망 차단은 별도 검사한다. 검사의 성공 조건을 삭제하지 않았다.
- 선체 연구가 이전 구조 HP를 절대값으로 덮어쓰는 문제를 검사에서 발견해 연구 데이터도 재생성했다. 전함/상위 변형의 선체 개량 +8% 유지.
- 연구 생성기의 입문 함체 재생성이 이전 센서/핍 값까지 바꾸는 것을 해시 감사로 발견했다. 입문 함체는 작업 전 해시와 정확히 일치하도록 복원했고 `--research-only`를 추가했다. 전체 검사 이후 이 보존 조치에 대해 연구/티어 검사를 별도로 다시 실행했다. 이후에는 티어 변형 생성 다음 `python tools/generate-progression-data.py --research-only`로 연구 패치만 갱신한다.
- 배치 fixture/읽기 전용 계측 **330개** 통과(요격 239 + 호위 91). 기본값 호환성, 잘못된 배율 거부, 카탈로그 비변경, 모듈 배치/유폭 확률 보존 포함.
- 게임·배치·검사 빌드 경고/오류 0. 실제 데이터 192판 및 변경 전 스냅샷 재현 8판 일치. 전투 자동검사 외 측정 **1,434판**(기본/후보/최종 1,296 + 단독/호위 96 + 이전 기준 재현 8 + 24척 24 + 전용 갈래 10).

## 재현과 자료

현재 데이터에는 조정이 이미 적용돼 있다. 과거 후보를 재현할 때 반드시 `before-ships.json`을 함께 전달한다. 배율을 현재 값에 다시 곱하지 않는다.

```powershell
dotnet build tools/BattleBatch/BattleBatch.csproj -c Release --no-restore -v:q
dotnet tools/BattleBatch/bin/Release/net8.0/BattleBatch.dll --wing-trials-check
dotnet tools/BattleBatch/bin/Release/net8.0/BattleBatch.dll --wing-trials --seeds 3,4,5,6,7,8 --jobs 3 --primary-only --definition-baseline docs/validation/engagement_timing_20261016/before-ships.json --timing-tuning docs/validation/engagement_timing_20261016/candidates/all3-structure3.json --output shots/timing-replay.json.gz
dotnet tools/BattleBatch/bin/Release/net8.0/BattleBatch.dll --wing-trials --seeds 1,2,3,4,5,6,7,8 --jobs 3 --primary-only --output shots/timing-current.json.gz
python tools/check-engagement-timing.py
dotnet tests/SimChecks/bin/Release/net8.0/SimChecks.dll
```

- `comparison.json`: 전체/별도 시드 전후 비교. `final-summary.json`: 격침 원인·첫 사격/강습·어뢰 결과 포함.
- `before-ships.json`: 조정 전 6개 기본 함체의 절대 데이터. `before-hashes.json`: 조정 전 소스/데이터/모델 142개.
- `pilot/window/holdout/final*.json.gz`: 완주한 주 실험 원자료 1,296판. `pilot-*`에는 후에 추가한 발사 순간 상태가 없어 동시 교전 판정에 사용하지 않는다. 단독 96판과 이전 기준 재현 8판은 별도 파일이다.
- `audit.json`: 실제 적용 192판 재현 및 데이터·모델 보존 검사. Blender/GLB/배치 등 23개 해시 보존, 6개 기본 함체의 좌표·무장·기타 필드 비교.
- `fleet/`: 이전과 같은 24척 편성의 24판. 기본 요격함 대신 지구 정찰 T3 / 화성 강습 T3를 사용하며 별도 결과로 해석한다.

10:10 편대, 소행성, 직접 조종 체감은 이 측정으로 확정하지 않는다. 배포 EXE·커밋·푸시는 별도다.
