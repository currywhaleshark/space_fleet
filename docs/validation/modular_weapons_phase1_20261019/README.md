## 새 검사 묶음이 확인하는 것

- 카탈로그: 14부품 로드, 기본 부품 7종이 기준 함급의 현재 탄도·레이저 수치 11항목과 같음(상대 오차 1e-4), 탄창 동일.
- 기본 동일성: 플레이 가능한 모든 함급에서 `MainGuns` 전부 null·전부 기본 부품 ID 둘 다 정의 JSON과 LoadoutId가 그대로이고, 기본 장착이 크기·용적·전력 검사를 통과.
- 교체 20조합(소켓 0번에 맞는 비기본 부품): 정의 왕복 직렬화, 모듈·선체·비행·전력 예산 불변, 나머지 소켓 실행값 불변, 티어·연구 비율이 새 부품에 그대로 곱해짐, 탄창 비례.
- 거부: 중형 소켓의 대형 레이저, 대형 소켓의 화성 특대 결전포, 무장 용적 초과(채널을 200 MW로 올린 시험 함체에서 4+4 > 7), 정격 전력 초과(4+3 용적은 맞지만 70+45 > 100 MW), 다른 진영, 연구 불가 함종, 레이저·레일건 혼합, 소켓 수 불일치, 없는 부품, 고정 축선 다연장, 교체 계통 주포와 동시 선택, 포신 수와 포구 수가 다른 수동 JSON.
- 혼합 구경 실사격: 지구 T4 전함에 240 mm 3연장 + 기본 240 mm 2연장 + 100 mm 2연장. 7발 모두 자기 소켓에서 나가고, 탄마다 자기 부품의 에너지·관통·탄속을 갖고, 장전 시간도 소켓별, 발열은 부품별 합. 기본 소켓은 기존 실행값과 같음.
- 계통 전환: 방공순양함(T3·T5)이 100 mm 2연장 레일건 두 기로 바뀌면 실탄 300발씩, 레이저 함체 비율은 에너지에만 넘어가고 장전은 부품 값.

## 재현

```
dotnet run --project tests/SimChecks/SimChecks.csproj -c Release -- --main-gun-parts
dotnet run --project tests/SimChecks/SimChecks.csproj -c Release
```

정의 스냅샷은 `tools/DefSnap` 콘솔 프로젝트를 `-p:Root=<트리> -p:Tag=<이름>`으로 변경 전(7c8c771)·후 트리에 각각 빌드해 실행하고 두 TSV를 비교했다. `GodotSharp.dll`은 각 트리의 `.godot/mono/temp/bin/Debug/`에 있어야 한다.

## 남은 것

- 무장 용적 한도는 기본 장착 사용량이다. 그래서 지금은 상위 부품을 달려면 다른 소켓을 낮춰야 한다. 티어별 그릇(§3)은 3단계.
- 최소 티어·연구 해금은 아직 검사하지 않는다(카탈로그 값만 있음). 격납고 선택 UI와 저장도 3단계.
- 공급 전력 → 장전·과충전, 구경별 외형과 연출은 2단계.
- `ShipBody.Railgun`(첫 소켓)을 쓰는 AI 판단은 혼합 구경에서 첫 소켓 기준이다. 4단계에서 맞춘다.
- 새 부품 수치는 출발점이며 전투 균형은 검증하지 않았다.
- 혼합 구경 함선의 실제 렌더러 외형은 확인하지 않았다(모델은 소켓별 바인딩을 따르지만 구경별 생김새는 2단계).
