## 1차 — 공통 장애물 자료와 공간 질의

- `src/Sim/Obstacles.cs`: 고정 구/캡슐 묶음, 위치·자세·경계 구, 순서가 결정적인 첫 선분 충돌/근접 질의, OBB 접촉. 절대 위치를 float로 바꾸지 않고 double 회전·선분/상자 거리 계산을 사용한다. 빈 목록은 즉시 반환하며 기존 전투 루프는 아직 연결하지 않는다.
- `tests/SimChecks/ObstacleChecks.cs`: 180개 검사. 내부/외부 0 길이, 접선/스침, 양 끝 뚜껑과 축 평행 캡슐, 퇴화 캡슐, 삽입 순서와 무관한 첫 충돌, 실제 열린 고리, 회전·±1e12 m 좌표, OBB 접촉·탈출 법선 포함.
- 결과: 섬멸전 20/20, 기함전 20/20, 점령전 20/20 요약 JSON **바이트 일치**.
- 점령전 기준/1차 모두 Blue 8승·Red 12승·무승부 0, 판정 시각 중앙값 640.100초.
- 단독 Release 시드 1 `All/Tick`: 섬멸전 **241.874→234.520µs**, 점령전 **261.720→270.478µs**. 동시 전투 처리량은 성능 비교에 사용하지 않았다. 아직 장애물 질의가 전투에 연결되지 않아 단일 실행의 시간 변동을 알고리즘 효과로 해석하지 않는다.
- 원자료와 구간별 계측: [stage1.json](validation/environment_stage1_20261011/stage1.json), [로그/CSV](validation/environment_stage1_20261011/stage1-evidence.zip).
- 다음: 실제 거점 구조물의 모양 연결. 화면·충돌·사격·센서 연결과 수동 플레이 체감은 아직 미확인.

## 2차 — 점령 거점의 고정 모양과 확인 표시

- `ZoneStructureShapes.cs`가 A 자원기지의 바위/시설/적재 부두, B 정거장의 허브/고리/바퀴살/모듈, C 저장고의 척추/탱크/관제 시설을 정의한다. `BattleSetup`이 점령전에서만 3개를 생성한다. 태양광·방열판은 제외한다.
- `ObstacleWireframe`, `CaptureZoneView`, `ModelGallery`가 같은 정의로 `--show-obstacles`를 표시한다. `tools/gallery.ps1 zone-A -ShowObstacles`로 재현 가능하다.
- 정거장 고리는 32개 캡슐(중심 반경 1490m, 반경 118m)로 근사한다. 110m 단면의 고리에 대한 현 간격 오차는 7.18m다. 바퀴살과 부착 시설까지 회전하던 외형은 고정하고 회전 대칭 고리만 돌려 고정 판정과 불일치하는 벽을 방지했다. 내부 열린 구역은 통과 검사로 확인했다.
- 세 곳의 실제 렌더러 스크린샷 확인. A 바위의 구형 근사는 오목한 굴곡 일부를 채우며 표면에 여유가 남는다. B 고리/바퀴살, C 탱크 위치는 일치한다. 정확한 메시 충돌을 주장하지 않는다. 스크린샷은 아래 원자료 ZIP에 포함했다.
- 공간/배치 검사 199개, 장면 흐름 49개 통과. 섬멸전·기함전 40/40 및 점령전 20/20 요약 바이트 일치. 점령전은 아직 물리·가림 연결 전이므로 Blue 8/Red 12, 중앙값 640.100초 그대로다.
