# AI 슬롭(Slop) UI/UX 진단 및 방지 표준

버전: 1.0 · 공통 설계 기준 · 2026-10-16

## 0. 정의와 핵심 판단

**AI UI 슬롭**이란, 특정 프로젝트의 목적·콘텐츠·사용자 행동에 근거하지 않고 익숙한 UI 패턴을 관성적으로 합성하여 생긴 **획일성, 장식 과잉, 정보 위계 부재, 형식적인 콘텐츠, 상호작용의 빈약함**을 말한다.

슬롭은 'AI가 만들었다'는 사실이나 '보라색을 썼다'는 이유만으로 성립하지 않는다. 핵심은 **디자인의 각 선택이 프로젝트에 고유한 필요에서 출발했는가**이다.

슬롭의 네 축:

- **시각적 평균화:** 색, 글꼴, 카드, 그리드, 그림자, 장식이 항상 같은 유행 템플릿으로 수렴한다.
- **의미 없는 부풀리기:** 정보 대신 추상적인 카피, 의미 없는 배지, 가짜 상태값, 장식용 숫자가 늘어난다.
- **사용 흐름과의 단절:** 사용자가 실제로 할 일보다 화면의 그럴듯한 구성이 앞선다.
- **정체성 결여:** 제목과 로고만 바꿔도 다른 프로젝트에 그대로 들어맞는 화면이 된다.

이는 미니멀리즘의 반의어가 아니다. 과잉 장식도 슬롭이고, 필요한 정보를 삭제한 텅 빈 화면도 설계 실패다. 목적은 시각적 빈곤이 아니라 **필요한 밀도, 분명한 위계, 고유한 표현**이다.

### 빠른 진단 4문항

1. **치환 테스트:** 프로젝트 이름/로고를 바꿔도 다른 앱과 구별되지 않는가?
2. **삭제 테스트:** 카드/배지/영문 문구/장식을 지워도 이해와 조작에 아무 영향이 없는가?
3. **3초 테스트:** 사용자가 3초 안에 화면의 주목적과 첫 행동을 추측할 수 있는가? (정밀한 연구 측정이 아닌 실무 휴리스틱)
4. **진실성 테스트:** 숫자·진행·상태·버튼·정보 출처가 실제 서비스와 대응하는가?

## 1. 반복되는 슬롭의 징후와 수정 기준

### 1-1. 무엇을 만들든 SaaS 랜딩페이지가 나온다

**징후:** 거대한 중앙 헤드라인, 보라/청록 그라데이션, '경험 시작하기' CTA, 똑같은 3개 기능 카드, 후기·통계·설명 카드·푸터가 기본 세트로 등장한다.

**문제:** 학습 활동, 게임, 작업 도구, 포트폴리오, 시뮬레이션의 과업 차이를 지운다.

**수정:** 처음 보이는 화면에서 사용자가 실제로 실행할 주 작업을 먼저 배치한다. 기능을 설명해야 하는 랜딩페이지가 필요한 경우에만 사용하며 섹션 수와 순서는 실제 콘텐츠량으로 결정한다.

### 1-2. 디폴트 시각 효과를 이유 없이 중첩한다

**징후:** 보라→파랑 그라데이션, 네온 헤일로, 반투명 유리 패널, 배경 블러, 흐릿한 그림자, 큰 라운딩, 강조색 3~5종이 함께 등장한다.

**문제:** 화면의 역할 차이를 표현하지 못하고 모든 제품에 같은 분위기를 씌운다. 흐린 텍스트와 저대비 컨트롤이 생길 수 있다.

**수정:** 프로젝트의 매체와 세계관에 맞는 색·표면·질감·모서리·그림자 규칙을 선택한다. 선택 이유를 설명할 수 없으면 중립적인 기본값을 우선한다. 특정 색이나 효과 자체를 절대 금지하지는 않는다.

### 1-3. 모든 것을 카드로 만든다

**징후:** 한 줄짜리 정보도 테두리+그림자+둥근 모서리 카드, 카드 안의 카드, 모든 목록 항목이 같은 크기·높이의 카드다.

**문제:** 실제 정보의 소속과 중요도가 보이지 않고, 공간을 많이 쓰며, 목록을 훑기가 어려워진다.

**수정:** 단순 목록에는 행·구분선·정렬·여백을 쓰고, 독립적인 상호작용이나 풍부한 미리보기가 필요한 경우 카드로 묶는다. 그룹의 의미가 카드 여부를 결정한다.

### 1-4. 장식용 메타텍스트가 증식한다

**징후:** `SYSTEM ONLINE`, `EXPLORE`, `DISCOVER`, `IMMERSIVE EXPERIENCE`, `PROJECT 001`, `ACTIVE`, `v0.1`, 의미 없는 영문 대문자·식별번호·좌표가 반복된다.

**문제:** 사용자의 주의를 소모하고 중요 정보처럼 오해될 수 있으며, 실제 프로젝트의 언어와 어긋난다.

**수정:** 작업상 유용한 버전·상태·번호만 보여 준다. 한국어 사용자를 위한 인터페이스에는 기능적 이유 없이 영문 레이블을 더하지 않는다. 작품 세계관의 일부인 진짜 게임 HUD, 기록물 메타데이터, 개발자용 상태 정보는 예외다.

### 1-5. 설명은 풍부한데 정보가 없다

**징후:** '경계를 허무는 혁신', '가능성을 발견하세요', '당신만의 여정', '새로운 차원의 경험', '스마트한 솔루션'과 같은 범용 문장을 제목·버튼·설명에 남발한다.

**문제:** 어떤 동작을 할 수 있고 어떤 결과를 얻는지 알려 주지 못한다.

**수정:** 명사와 동사를 실제 행동에 맞춘다. 예: '학습 경험 시작' → '모둠 만들기'; '프로젝트 탐험하기' → '작품 보기'; '인사이트 확인' → '라운드별 매출 보기'. 안내문은 작업 설명, 입력 제약, 피드백 중 하나를 담당해야 한다.

### 1-6. 아이콘·배지·일러스트가 텍스트를 장식한다

**징후:** 모든 소제목 앞에 반짝이 아이콘, 제목 위에 작은 카테고리 배지, 같은 의미의 그림과 텍스트가 반복되며 의미 없는 이모지·스톡 일러스트가 빈 공간을 채운다.

**문제:** 시각적 우선순위를 흐리고, 카테고리 표시와 장식을 구분하기 어렵다.

**수정:** 아이콘은 기능을 식별하거나 상태를 구별할 때, 배지는 분류·상태 정보를 전달할 때 사용한다. 아이콘이 없어도 충분히 이해된다면 생략을 우선 검토한다. 실제 작품 썸네일과 사용자가 만든 콘텐츠는 장식 이미지보다 우선한다.

### 1-7. 가짜 대시보드와 수치가 신뢰감을 연출한다

**징후:** 출처가 없는 '이용자 12.5K', 증가율, 실시간 처리 그래프, 임의의 만족도·완료율, 의미가 없는 파형과 프로그레스 바.

**문제:** 잘못된 판단을 초래하며 제품의 신뢰를 훼손한다.

**수정:** 실제 데이터만 쓰고 단위·기간·분모·기준을 표시한다. 시연용 모형은 '예시/샘플 데이터'로 명확히 구분한다. 지표는 사용자의 다음 판단에 유용할 때만 넣는다.

### 1-8. 정보 위계를 크기·색·여백으로 표현하지 않는다

**징후:** 모든 카드가 강조되고 제목/본문 크기 차이가 작으며 주요 행동과 보조 행동이 비슷한 버튼으로 나타난다. 반대로 비어 있는 공간이 지나치게 커서 기능을 찾기 어렵기도 하다.

**문제:** 무엇을 읽고 눌러야 하는지 비용이 늘어난다.

**수정:** 화면의 주 작업, 부 작업, 부가 정보, 설정과 도움말을 구분한다. 제목, 본문, 메타정보와 조작 컨트롤에 분명한 규칙을 만들고 일관되게 사용한다. 정보량에 맞게 밀도를 결정한다.

### 1-9. 애니메이션이 행동보다 존재감을 과시한다

**징후:** 모든 카드 호버 시 떠오름, 모든 숫자 카운트업, 스크롤마다 페이드인, 필요 없는 페이지 전환, 반짝이는 버튼.

**문제:** 산만함, 멀미·접근성 부담, 지연 체감이 생긴다.

**수정:** 상태 전환·공간적 관계·행동 결과를 명확히 하는 애니메이션만 사용한다. 사용자의 감소된 움직임 설정을 존중한다. 게임의 타격감이나 월드 피드백에 필요한 움직임은 유지한다.

### 1-10. 상호작용의 껍데기만 존재한다

**징후:** 클릭 가능한 것처럼 생긴 정적 카드, 기능 없는 검색·필터·버튼, 오류 메시지 없는 실패, 저장 여부 불명, 뒤로가기·취소의 부재, 의미 없는 로딩 상태.

**문제:** 미감 문제가 아닌 직접적인 UX 실패다.

**수정:** 실제 동작에 맞는 어포던스를 제공한다. 기본 상태뿐 아니라 선택·비활성·로딩·성공·오류·빈 결과·복구 경로를 설계한다. 가짜 인터랙션은 만들지 않는다.

### 1-11. 반응형이 단순 축소판이다

**징후:** PC 3열 카드가 모바일에서 너무 작은 2~3열로 압축되고, 헤더·사이드바·모달이 화면을 가리며, 터치 영역이 비좁고 글씨가 작아진다.

**문제:** 실제 사용 흐름이 막힌다.

**수정:** 우선순위에 따라 모바일 정보 순서를 다시 설계한다. 데스크톱과 모바일의 UI 구성은 달라도 과업·기능은 같아야 한다. 실제 주요 뷰포트와 터치 입력으로 검증한다.

### 1-12. 도구가 정체성 대신 인터페이스를 결정한다

**징후:** 기본 컴포넌트 라이브러리의 radius·shadow·padding·타이포·그래프 스타일을 조정 없이 전체 제품에 투입한다.

**문제:** 서로 다른 프로젝트가 같은 템플릿으로 보인다.

**수정:** 라이브러리는 기능 구현에 활용하되, 시각 규칙과 화면 구조는 프로젝트의 사용 시나리오·실제 콘텐츠·기존 정체성에서 결정한다. 단순히 폰트와 버튼 색만 바꾸는 것으로 충분하지 않다.

### 1-13. '있어 보임'을 위해 기능과 단계를 추가한다

**징후:** 한 번의 선택으로 끝날 작업에 온보딩·설정 페이지·확인 모달·사이드바·탭을 만든다.

**문제:** 실질적 작업 속도가 느려지고 사용자가 불필요한 결정을 요구받는다.

**수정:** 작업의 불가역성·위험·복잡성을 기준으로 단계를 추가한다. 단순 행동은 짧고 직접적인 흐름을 제공한다. 핵심 선택·위험 확인·복구 수단은 삭제하지 않는다.

### 1-14. 실제 콘텐츠 대신 플레이스홀더와 가짜 세계를 보여 준다

**징후:** 미리보기 없는 작품 카드에 추상 일러스트, 존재하지 않는 후기·팀원·기능·수치·브랜드, 맥락과 동떨어진 영문 가상 이름을 채운다.

**문제:** 실제 콘텐츠를 가리고 신뢰를 떨어뜨린다.

**수정:** 실제 이미지·문구·기능·데이터를 사용한다. 미완성 영역은 명시적으로 '준비 중'을 표시하거나 설계상 생략한다. 더미 데이터를 실 데이터처럼 노출하지 않는다.

## 2. 긍정 설계 원칙 — 무엇으로 대체할 것인가

### 2-1. 내용과 작업을 먼저 설계한다

최초 설계 시 다음을 확인한다: 누구의 화면인가 / 가장 중요한 작업은 무엇인가 / 지금 어떤 상태인가 / 주 행동을 어디에 두는가 / 실패했을 때 어떻게 회복하는가. 그 후 레이아웃을 정한다. 공간을 채우기 위해 새 정보를 만들지 않는다.

### 2-2. 표현은 제품과 매체의 성격을 따른다

- 진지한 기록물이나 개인 아카이브: 실제 콘텐츠를 전면에, 편집물 같은 구성과 절제된 설명.
- 학습 도구: 교사의 운영 흐름과 학생의 명확한 행동, 충분한 글씨·터치 영역·복구.
- 경영·도시 시뮬레이션: 시뮬레이션 화면과 수치가 중심, 판단에 필요한 정보만 제공.
- 우주 함대전·전술 게임: 세계관에 맞는 전술 HUD, 거리·위협·타깃·상태 등 실제 게임 정보가 중심. 게임 내 장식은 몰입과 판독성을 해치지 않는 범위에서 허용.
- 역사 인물 대화형 체험: 인물·대화·질문이 중심. 공간의 시대감은 가능하되 기능 없는 기계식 계기판이나 장식 메타데이터는 지양.

'항상 미니멀하게'는 잘못된 공통 규칙이다. **매체에 따른 기능적 밀도**가 우선이다.

### 2-3. 유형·밀도·대비의 규칙을 만든다

- 제목, 본문, 부가 정보 사이에 구별 가능한 서체 크기·굵기·간격을 사용한다.
- 기능이 같으면 같은 시각 규칙, 중요도가 다르면 다른 강조 강도를 적용한다.
- 색을 쓰는 이유(주 행동/경고/선택/진영/분류)를 정의한다.
- 카드보다 목록이나 표가 정보를 더 잘 전달하면 목록·표를 사용한다.
- 빈 공간은 관련 항목을 묶고 위계를 만드는 데 쓰며, 무조건 고급스러워 보이기 위한 여백은 지양한다.

### 2-4. 콘텐츠는 진짜이고 구체적이어야 한다

- 추상적 문구보다 구체적 동작명을 사용한다.
- 작품·데이터·상태·이미지는 가능하면 실제 프로젝트 소스와 연결한다.
- 가짜 지표·가짜 실시간 정보·가짜 상호작용을 금지한다.
- 보조 설명의 양은 사용자의 지식수준과 과업 난이도에 따라 정한다. 아동에게 필요한 안내까지 삭제하지 않는다.

### 2-5. UX의 완결성이 시각적 매끄러움보다 먼저다

- 기본, 선택, 호버(해당 시), 초점, 비활성, 로딩, 빈 상태, 성공, 오류, 복구 경로를 고려한다.
- 표와 그래프는 단위·기간·범례가 필요하면 명시한다.
- 키보드 조작과 초점 표시를 제공한다.
- 화면이 줄어들 때 기능을 단순 숨기지 않고 사용 가능한 위치로 재배치한다.
- 중요한 작업은 저장·종료·뒤로가기·재개 동작을 확인한다.

## 3. 접근성·사용성 기준

아래는 슬롭 여부와 별개로 반드시 고려할 기본 품질 조건이다.

- WCAG 2.2 AA 기준을 목표로 한다. 일반 본문 텍스트의 명암 대비는 대체로 **4.5:1 이상**, 큰 텍스트는 **3:1 이상**을 기준으로 점검한다(기준에서 정한 예외 제외).
- 포인터 입력 대상 크기는 WCAG 2.2 AA의 **최소 24×24 CSS px** 또는 인정되는 충분한 간격 등 예외 조건을 만족한다. 모바일 주요 컨트롤은 가능한 한 **44×44 CSS px 이상**을 권장한다(후자는 강화된 AAA 기준에 해당).
- 마우스 없이 핵심 조작이 가능해야 하며, 키보드 포커스가 가시적이어야 한다.
- 의미 있는 이미지와 아이콘에는 접근 가능한 이름·설명을 제공한다.
- `prefers-reduced-motion`을 고려하고, 장식 애니메이션으로 작업을 방해하지 않는다.
- 실제 타깃 기기의 대표 크기에서 가로 넘침·겹침·잘림을 확인한다.

## 4. 프로젝트별 예외와 금지선

| 프로젝트 유형 | 억제할 슬롭 | 보존·강화할 개성 |
|---|---|---|
| 개인 포트폴리오·아카이브 | 장식용 영어, 가짜 성과·KPI, 범용 CTA, 불필요한 카드 | 실제 작품 이미지, 편집 디자인, 아카이빙 구조, 절제된 메타데이터 |
| 교육용 활동 웹앱 | 교육 효과 없는 장식, 중복 설명, 모호한 시작 버튼 | 충분한 안내, 큼직한 컨트롤, 학생 피드백, 교사 운영 도구 |
| 경영·도시 시뮬레이터 | 가짜 대시보드, 실측 불가능한 지표, 화면보다 큰 장식 | 실제 시뮬레이션·결과·원인관계·변화의 시각화 |
| 전술·전략 게임 | 실제 플레이에 기여하지 않는 임의 HUD·깜빡임 | 조작 피드백, 세계관 분위기, 전술 판독성, 몰입 가능한 연출 |
| 역사 인물 대화형 도구 | 시대감과 무관한 미래지향적 HUD, 장식용 상태값 | 질문·답변 흐름, 초상·역사적 시각언어, 출처와 불확실성 표시 |

예외를 적용하더라도 실제 기능이 없거나 진실성을 위반하는 인터페이스는 허용하지 않는다.

## 5. 실무 진단 프로토콜

### 5-1. 순서

1. **맥락 확보:** 사용 대상, 과업, 프로젝트 성격, 기존 콘텐츠·디자인 자산을 파악한다.
2. **화면 순회:** 첫 화면, 대표 작업 화면, 결과 화면, 모바일 화면, 오류·빈 상태를 확인한다.
3. **문제 기록:** 징후, 화면/컴포넌트 위치, 사용자에 미치는 영향, 수정 방향을 구체적으로 적는다.
4. **우선순위 분류:** P0 기능·사실 오류 및 심각한 조작성, P1 주요 UX·정보 위계, P2 반복적인 시각 슬롭, P3 취향 기반 미세 조정.
5. **최소 변경:** 기능·콘텐츠·정체성을 보존하면서 원인이 되는 설계를 교정한다.
6. **검수:** 주요 흐름, 모바일, 데이터의 진실성, 접근성, 변경 전후의 명료성을 확인한다.

### 5-2. 보고 형식

문제별로 다음을 짧게 기록한다.

- **위치:** 예) 홈 > 첫 화면 > 오른쪽 상단 `ACTIVE` 배지
- **유형:** 장식용 상태값 / 정보 위계 / 카드 과잉 / 조작성 등
- **근거:** 상태값의 출처·실제 기능이 없고 사용자 행동과 무관함
- **영향:** 정보처럼 오인되며 핵심 버튼에 대한 집중이 줄어듦
- **조치:** 배지 삭제, 핵심 컨트롤 정렬
- **검증:** 모바일/데스크톱에서 주요 작업 흐름 확인

'AI 느낌이 난다', '더 고급스럽게', '세련되게'와 같은 추상 평가만으로 변경을 정당화하지 않는다.

### 5-3. 인수 조건

- [ ] 화면마다 사용자와 가장 중요한 행동이 정의되었다.
- [ ] 목적 없는 장식·영문 메타텍스트·배지·카드를 제거하거나 이유를 설명할 수 있다.
- [ ] 중요한 정보가 먼저 읽히며, 행동 버튼 문구가 구체적이다.
- [ ] 표시된 데이터·상태·그림·버튼이 실제로 존재하고 작동한다.
- [ ] 빈/로딩/성공/오류/복구 상태를 필요한 범위에서 확인했다.
- [ ] 모바일에서 핵심 기능이 손실되지 않고 누르기 쉽다.
- [ ] 해당 프로젝트만의 성격이 드러난다.
- [ ] 잘 작동하던 기능과 실제 콘텐츠를 불필요하게 훼손하지 않았다.

## 6. 금지 규칙의 오용 방지

이 문서를 읽고 다음을 수행하면 **그 자체로 실패**다.

- 모든 화면을 검정 글씨+흰 배경+직각 버튼으로 획일화한다.
- 카드가 문제라고 게임 유닛 카드, 작품 미리보기 카드, 실제 대시보드 위젯까지 삭제한다.
- '영어 금지'를 문자 그대로 적용하여 고유명사, 국제 표준, 코드, 실제 게임 용어를 제거한다.
- '아이콘 금지'를 문자 그대로 적용하여 텍스트보다 빨리 인지되는 핵심 도구 아이콘을 없앤다.
- 애니메이션을 없애면서 사용자 피드백과 게임의 타격감까지 없앤다.
- 여백을 줄이면서 모바일 조작 밀도를 무리하게 높인다.
- AI 슬롭 검토를 핑계로 요청받지 않은 대규모 리디자인을 진행한다.

핵심은 **유행하는 스타일의 일괄 금지**가 아니라 **근거 없는 선택의 금지**다.

### 기존 화면 슬롭 제거

> `AGENTS.md`와 `docs/ANTI_SLOP_UI_UX_STANDARD.md`를 기준으로 기존 UI를 점검하라. 모든 화면을 재설계하지 말고 슬롭 징후가 관찰되는 구체적 컴포넌트, 위치, 근거, 사용자 영향을 먼저 목록화하라. P0/P1 문제를 우선하고 P2 시각적 교정을 수행하되 실제 콘텐츠, 기존 기능, 프로젝트 고유의 미감, 게임·교육적 장치를 보존하라. 기능·데이터·상태를 지어내지 말고 모바일 및 핵심 작업을 검증하라. 변경 내용과 검증 불가능한 항목을 보고하라.`
