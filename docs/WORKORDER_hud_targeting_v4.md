# Project Fleet — HUD 간소화 · 관측 단계별 3D 표적 · 포탑별 사격통제

대상 저장소: `https://github.com/currywhaleshark/space_fleet`
기준: 2026-10-23 기획 논의. 저장소의 실제 최신 구현·데이터 구조를 확인한 뒤 작업.

## 작업 목표

- HUD에 계속 덧붙은 글과 별도 패널을 줄인다. 정보 삭제가 아니라 계층화(항상 / 상황별 / 요청 시 상세).
- **요격함**: 기수 방향과 중앙 조준선 기반, 선행점은 별도 표시.
- **전함·호위함·순양함**: 표적의 **포탑별 선행 사격해**를 향해 움직이는 개별 포신 조준표식. 포탑마다 선회속도·포각·상태가 다르다.
- 적함의 실제 관측 시야를 반영한 축소 3D 모형을 우상단에 배치. **접촉 → 식별 → 잠금**의 센서 상태에 따라 렌더 품질과 부위 선택 권한을 달리한다.
- 내부 장비를 직접 지정하지 않고, **선체 밖으로 실제 노출된 장비만** 선택한다. 내부 반응로·탄약고·전력 버스는 기존 관통 경로의 결과로만 손상한다.

## 시안 파일 사용법

`HUD_Prototype_v4.html`을 브라우저에서 열면 동작하는 UI 시안을 확인할 수 있다. `Overview_contact_identified_locked.png` 및 `screenshots/`는 핵심 상태 비교용이다.

이 HTML은 **디자인 및 인터랙션 레퍼런스**다. HTML의 축소 함선은 실제 게임 GLB가 아닌 시연 모델이며, 배경 이미지도 게임 엔진 렌더가 아니다. HTML 내부의 임의 피해/상태/측면 전환은 테스트 전용이다. Godot에서는 실제 관측 정보와 진짜 함선 형상·부품 상태로 구현한다.

시안의 버튼/문자/배경을 1:1 복제하지 않는다. **시각적 계층, 3단계 변화, 클릭 허용 조건, 포탑 상태**를 우선한다.

## 1. 센서 단계를 UI 상태로 활용

| 상태 | 3D 표적 영역 | 조작 허용 |
| --- | --- | --- |
| 미탐지 `None` | 모형 자체 비표시 | 조준 불가 |
| 접촉 `Contact` | 흐릿한 신호, 비고유 실루엣, 위치 오차 시각화 | 정확한 함종·장비 노출 금지, 부위 지정 불가 |
| 식별 `Identified` | 식별된 함급의 실제 GLB/실루엣, 최근 *관측된 자세* | 형체 파악은 가능, 외부 부위 직접 조준 불가 |
| 잠금 `Locked` | 같은 모형 + **관측으로 확인되는** 외부 장비 선택 표식 | 시야·가림·장비 크기 대비 조준 오차가 허용할 때 정밀 조준 가능 |
| 신호 소실 | 마지막 관측 자세/상태를 유지하고 품질 저하를 표시 | 라이브 상태 갱신 금지, 새로운 부위 조준 잠금 금지 |

- 관측자와 표적 사이의 상대방향 및 *센서가 관측한 자세*로 표적을 표현한다. 카메라 각도를 보기 좋게 임의로 돌리지 않는다.
- 관측각 버튼은 HTML 시연용으로만 사용. 실제 게임은 플레이어 함선과 표적의 상대 각도를 실시간 계산한다.
- 아군 데이터링크를 이용할 때 **내 함선 시선에 가려진 면을 투시하는 것**과 **다른 관측자가 확보해 공유한 정보**를 구분한다. 실제로 검증 가능한 관측 출처/품질에 따라 정보와 선택 가능 여부를 제한한다. 표적 자체가 장애물에 가려진 경우에도 실제 시각/센서 규칙을 우회하지 않는다.
- `Locked`는 사격해를 얻었다는 뜻이지 센서 마스트 등 작은 장비에 대한 정밀 조준 보증이 아니다. `FiringSolution.ErrorMeters`와 부위의 실효 투영 크기·노출 면적을 비교한다.
- 표적이 식별되기 전에도 GLB/모듈 구조로 함급을 맞힐 수 없도록 할 것.

## 2. 선택 가능한 외부 장비

- 기본값: `선체 전체`(특정 내부 모듈 중심을 조준하지 않음).
- 선택 후보: 외부 노출 주포·부포/방공 포탑, 엔진 노즐·외부 추진기, 외부 센서 마스트/어레이, 외부 방열판, 외장으로 구현된 기타 장비.
- **불가**: 내부 반응로, 탄약고, 배전망, 매립 센서, 내부 발전기·냉각기·전술 모듈 등.
- `ModuleKind`나 피해 모듈의 `Center`만 보고 외부 장비로 취급하지 않는다. **공개 외장 형상 ↔ 소켓/하드포인트 ↔ 피해 모듈**의 명시적 연결 메타데이터가 필요하다.
- 실제 형상/간략 충돌 형상에 대한 레이/깊이 검증으로 현재 화면에서 가려진 외부 장비의 선택을 막는다. 포탑이 선체 후면에 가려지면 마커도 숨긴다.
- 화면의 선택 영역은 원래 소켓 식별자를 유지. `주포 1/2/3`은 회전 중에도 같은 포탑을 의미한다. 수리 가능 여부와 파괴 여부는 실제 관측된 한도 내에서만 노출한다.
- `Y` 키는 **현재 선택 가능한 외부 대상들 + 선체 전체**를 순환. 가려진 장비를 키보드만으로 타깃할 수 없도록 한다. 표식 직접 클릭도 동일한 권한 검사 통과해야 한다.
- 외부 장비를 향한 조준은 정확한 관통/파괴 보증이 아니다. 실제 포신 발사와 `DamageRay`의 실드·장갑·관통·모듈 충돌을 그대로 사용한다.

## 3. 포탑별 사격통제 HUD

- 요격함의 고정 전방포는 기존 **중앙 기수 조준**, 필요 시 별도 선행점 사용.
- 전함/순양함/호위함은 선택 표적의 선행 조준점을 기준으로 **개별 포탑 조준표식이 실제 포각 내에서 따라온다**.
- 포탑마다 설치 좌표·현재 yaw/elevation·선회 속도·포각 한계·탄속·사격해가 다를 수 있다. 한 개의 대표 포탑 상태로 모두 표시하면 안 된다.
- 포탑 방향 표식은 물리 상태에서 읽은 값만 그린다. 외형/시연용 임의 보간으로 실제 선회 가능성을 왜곡하지 않는다.
- 파괴/손상/전력 불능/장전/탄약 소진/사선 가림/포각 밖을 구분:
  - 선회 중: 표식이 목표에 접근
  - 정렬: 표식이 유효한 개별 선행점에 수렴
  - 포각 밖: 포각 한계에서 멈춤
  - 사선 가림: 차단 표식
  - 포탑 파괴: 움직이는 조준표식 제거, **고정 번호에 X**
  - 장전/전력 저하: 파괴와 다른 비활성·진행 표시
- 다중 포탑 조준표식은 작게. 동일 지점에 겹칠 때 표시를 합칠 수 있지만, 살아 있는 포탑 수와 파괴된 번호를 잃어서는 안 된다.
- 기존 대형 사격통제 구체는 상시 표시하지 않고 상세 정보로 옮긴다(필요하면 접근 가능 유지).

## 4. HUD 전체 간소화

### 상시
레이더, 현재 무장 1~3·전술 4~7의 통합 바, 최소 기동 게이지, 자함 실드·구조, 표적 이름·거리·센서 등급, 최소 전력·열 경고, 목표 진행, 간결한 포탑 상태.

### 사건 시
명중/격침 리본, 고장·과열 경고, 적 미사일 접근, 응급복구 진행, 모듈 준비/발동/실패 정보.

### 펼침
자함 계통별 상세, 5채널 전력 상세, 드론 개별 상황, 편대원 상세, 표적 외부 장비 설명, 누적 전과 등.

표적 이름/거리/잠금 상태를 상단·우측·하단에 중복 상시 표시하지 않는다. 긴 문자열을 기본 HUD에서 줄이고 정렬·색·아이콘·수치로 전달한다. 우상단 모델이 주목적일 때 다른 표적 패널의 내용을 압축한다.

사용자 언어는 한글, 현행 HUD의 색상 계층을 최대한 재사용. 과도한 박스, 뱃지, 음영과 인위적인 대시보드 디자인을 피한다.

## 5. 데이터·구현 연계

기존 경로를 먼저 조사해 재사용:

- `src/Sim/SensorNet.cs`, `src/Sim/FireControl.cs`: 관측 단계·측정 품질·실제 사격해
- `src/Sim/Subsystems.cs`: 기존 `AimSubsystem` 및 `Pick()` 변경. **실제 파괴 목록과 외부 선택 목록 분리**
- `src/Sim/Railgun.cs`, `src/Sim/Gunnery.cs`: 개별 포탑 실제 방향/발사 가능 상태, `FireControl.Solve(..., weapon: gun)`
- `src/Sim/SimAI.cs`: 플레이어와 동일한 외부 대상/노출/정밀도 규칙, 미관측 모듈 정보 치트 차단
- `src/Sim/DamageRay.cs`: 기존 피해 판정 보존
- `src/Game/Hud.cs`, `GunneryHud.cs`, `CombatHud.cs`, `AimPartHud.cs`, `TargetSelectionHud.cs`, `DamageHud.cs`, `CombatHudLayout.cs`: 기존 HUD/입력/배치 재편
- `src/View`의 기존 함선 GLB·부품·하드포인트 렌더링 및 소켓 연결 재사용

실제 3D 표적 모형은 **선택한 1척**을 위한 재사용 가능한 작은 `SubViewport` 권장. GLB 렌더마다 생성/폐기 금지. 불필요한 그림자/발광/파티클/포스트프로세싱 끄고 렌더 FPS·비용을 측정.

## 6. 안전/회귀 조건

- 기존 센서/데이터링크/ECM/소행성 차폐 정보제한을 위반하지 않는다.
- UI의 내부 모듈 비노출과 무관하게 내부 장비는 정상적인 관통 후 피해받는다.
- 미확인/미관측 적의 실시간 자세, 실제 HP, 내부 파괴 여부를 UI/AI가 몰래 참조하지 않는다.
- 후방 가려진 포탑, 외부 비노출 부위는 클릭/키보드 순환에서 선택되지 않는다.
- 조종권 인계 후 HUD 모델, 포탑 번호, 센서 상태가 새 조종함으로 올바르게 변경된다.
- 파괴된 포탑/탄약 소진/열·전력 문제의 표시가 정확하고 별개다.
- 고정 기수포·복수 포탑·서로 다른 탄속·레이저·상하 포탑 등 경계조건 검사.
- 사격 결과/AI/승패의 기존 기초 회귀; 변경이 의도된 부위 조준 로직에서만 발생하는지 비교.
- 1280×720 및 1600×900, 글자 100%/130%, 망원, 리본/전술 1~7바, 복구·드론·과열 동시 표시 검사.
- 24척 및 약 80척 혼성전에서 HUD 렌더 비용, 게임 FPS, sim tick 측정.

## 구현 우선순위

1. 외부 장비 노출·지정 가능 판정 계층과 AI 제약(피해 모듈과 구분)
2. 센서 등급별 미리보기와 실제 관측각, 모델/가림/선택
3. 포탑별 물리 조준 표식/파괴·선회·장전·포각 상태
4. 전체 HUD 중복 정보 제거와 상세 패널/반응형 배치
5. 자동 회귀·실제 GPU 스크린샷·전후 성능 기록

완료 후 게임 실제 렌더 화면 스크린샷과 주요 테스트 로그를 `docs/validation/`에 기록한다. 임시 HTML 시안처럼만 보여주고 실제 Godot 연동을 하지 않는 상태는 완료로 보지 않는다.
