기준 커밋 `ffb00a1` (2026-10-11). 지시서 `WORKORDER_environment_stage1.md`의 1~6차를 차례로 구현한다. 기준 빌드, 전체 SimChecks, 실제 렌더러 scene-flow 검사 통과 후 별도 실행 어셈블리를 저장했다. 기준 3개 모드 각각 시드 1~10 × 정/역배치 20판, 총 60판과 단독 시드 1 구간 계측을 보관했다.

## 1차 — 공통 장애물 자료와 공간 질의

- `src/Sim/Obstacles.cs`: 고정 구/캡슐 묶음, 위치·자세·경계 구, 순서가 결정적인 첫 선분 충돌/근접 질의, OBB 접촉. 절대 위치를 float로 바꾸지 않고 double 회전·선분/상자 거리 계산을 사용한다. 빈 목록은 즉시 반환하며 기존 전투 루프는 아직 연결하지 않는다.
- `tests/SimChecks/ObstacleChecks.cs`: 180개 검사. 내부/외부 0 길이, 접선/스침, 양 끝 뚜껑과 축 평행 캡슐, 퇴화 캡슐, 삽입 순서와 무관한 첫 충돌, 실제 열린 고리, 회전·±1e12 m 좌표, OBB 접촉·탈출 법선 포함.
- 결과: 섬멸전 20/20, 기함전 20/20, 점령전 20/20 요약 JSON **바이트 일치**.
- 점령전 기준/1차 모두 Blue 8승·Red 12승·무승부 0, 판정 시각 중앙값 640.100초.
- 단독 Release 시드 1 `All/Tick`: 섬멸전 **241.874→234.520µs**, 점령전 **261.720→270.478µs**. 동시 전투 처리량은 성능 비교에 사용하지 않았다. 아직 장애물 질의가 전투에 연결되지 않아 단일 실행의 시간 변동을 알고리즘 효과로 해석하지 않는다.
- 원자료와 구간별 계측: [stage1.json](validation/environment_stage1_20261011/stage1.json), [로그/CSV](validation/environment_stage1_20261011/stage1-evidence.zip).
- 다음: 실제 거점 구조물의 모양 연결. 화면·충돌·사격·센서 연결과 수동 플레이 체감은 아직 미확인.

## 2차 — 점령 거점의 고정 모양과 확인 표시

- `ZoneStructureShapes.cs`가 A 자원기지의 바위/시설/적재 부두, B 정거장의 허브/고리/바퀴살/모듈, C 저장고의 척추/탱크/관제 시설을 정의한다. `BattleSetup`이 점령전에서만 3개를 생성한다. 태양광·방열판은 제외한다.
- `ObstacleWireframe`, `CaptureZoneView`, `ModelGallery`가 같은 정의로 `--show-obstacles`를 표시한다. `tools/gallery.ps1 zone-A -ShowObstacles`로 재현 가능하다.
- 정거장 고리는 32개 캡슐(중심 반경 1490m, 반경 118m)로 근사한다. 110m 단면의 고리에 대한 현 간격 오차는 7.18m다. 바퀴살과 부착 시설까지 회전하던 외형은 고정하고 회전 대칭 고리만 돌려 고정 판정과 불일치하는 벽을 방지했다. 내부 열린 구역은 통과 검사로 확인했다.
- 세 곳의 실제 렌더러 스크린샷 확인. A 바위의 구형 근사는 오목한 굴곡 일부를 채우며 표면에 여유가 남는다. B 고리/바퀴살, C 탱크 위치는 일치한다. 정확한 메시 충돌을 주장하지 않는다. 스크린샷은 아래 원자료 ZIP에 포함했다.
- 공간/배치 검사 199개, 장면 흐름 49개 통과. 섬멸전·기함전 40/40 및 점령전 20/20 요약 바이트 일치. 점령전은 아직 물리·가림 연결 전이므로 Blue 8/Red 12, 중앙값 640.100초 그대로다.
- 단독 `All/Tick` 기준→2차: 섬멸전 **241.874→238.772µs**, 점령전 **261.720→266.029µs**. 상세 [stage2.json](validation/environment_stage1_20261011/stage2.json), [검사/전투/스크린샷](validation/environment_stage1_20261011/stage2-evidence.zip).

## 3차 — 고정 장애물 접촉·회피

- `ObstacleCollision.cs`, `ShipCollision`, `SimWorld`: 240Hz 현재 자세 OBB의 연속 이동과 캡슐/구 거리로 첫 접촉을 찾는다. 경계 구/선분으로 먼저 거르고, 보수적 전진과 거의 접하는 경우의 볼록 거리 최소화로 관통을 막는다. 기존 반발 0.05·마찰 0.15·8회 겹침 해소를 사용한다. `CollisionDamage`의 기존 피해 경로에 함선 질량 전체의 소산 에너지를 전달한다.
- `ObstacleAvoidance.cs`: 10초 앞 이동 선분과 기본형의 최근접 접근을 계산하고 기존 안전 여유 규칙으로 회피한다. 정면 접근에는 옆 방향을 더해 정지 상태에 머물지 않게 한다. 경로 탐색은 추가하지 않았다. 목표 방향 진척이 30초 이상 없으면 한 번 기록하고 진척 회복 시 새 구간을 시작한다.

## 4차 — 관측 차폐와 60초 전술 추적 기억

- `SensorNet`/`SmallContactSensors`에서 관측함·프로브별 시선을 검사한다. 다른 각도의 관측과 아군 데이터링크는 유지하며, 화성 호위 재머도 각 관측자까지의 시선으로 계산한다. 미사일·프로브의 소형 접촉은 차폐 직후 유효성을 잃는다.
- `SensorMemory`는 마지막 관측 위치·속도·시각만 저장하는 별도 질의다. 차폐 때문에 접촉을 잃은 경우에만 생성하고, 60초 만료 또는 재획득 시 제거한다. 거리·신호만으로 소실된 접촉에는 생성하지 않는다. 오차 증가율은 `max(100m/s, 마지막 속력 × 0.5)`를 사용했다. 느린 주력함도 60초 뒤 최소 6km, 고속 요격함은 더 큰 오차를 갖는다. 보장된 도달 영역이 아닌 속도 불확실도 근사다.
- `SimAI`, 편대/화성 교리와 점령 명령은 기억된 표적을 유지하되 사격·반물질 준비는 중단한다. 점령 편대는 거점 대기점을 계속 지킨다. 구조물이 있는 전장에서 적 회피도 관측값/예측값을 사용한다. 숨은 실제 위치·속도·격침 여부가 기억 추적에 영향을 주지 않는 검사를 포함했다.
- `BattleLog.SensorOcclusion`과 별도 환경 CSV에 진영별 잠금 소실 횟수·시간·재획득을 기록한다. 시간은 여러 표적을 합산한 **표적·초**로, 전투 경과 시간을 초과할 수 있다.
