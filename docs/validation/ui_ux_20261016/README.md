# UI/UX 점검 및 수정 — 2026-10-16

사용자가 제공한 `anti_slop_ui_ux_pack.zip` 기준을 격납고 → 부품 교체·연구 → 전투 HUD 순서로 적용했다.
원본 공통 정책은 루트 `AGENTS.md`, 상세 기준은 `docs/ANTI_SLOP_UI_UX_STANDARD.md`, 점검 프롬프트는 `docs/EXISTING_PROJECT_AUDIT_PROMPT.md`에 반영했다. 기존 UTF-8 재읽기 규칙을 보존했다.

## 대상과 근거

사용 흐름은 **함급·편대 선택 → 프리셋/계통 교체 → 필요한 연구 → 출격 → 무장 선택**이다.
전술 정보, 실제 함선 미리보기와 베이 좌표는 이 흐름에 필요한 정보다. 게임의 기존 배치와 기능을 유지하면서 비교·조건·초점·경고 표시를 수정했다.

Godot 4.7.2 Mono / Vulkan / RTX 2060에서 변경 전 6장, 변경 후 13장을 직접 렌더하고 저장된 PNG를 확인했다. 해상도는 1600×900, 1280×720이다.
캡처는 별도 테스트 프로필을 사용한다. 격납고의 34/34 보유, 연구소의 450 RP, 교체 시안의 100,000 RP 등은 **검증용 상태**이며 실제 사용자 저장 데이터가 아니다. `--shot`과 기존 흐름 검사는 플레이어의 격납고 저장을 변경하지 않는다.

단면 전환 버튼은 현재 상태를 반복하는 대신 **단면으로 보기 / 외형으로 보기**라는 행동명으로 바꿨다.
가속 막대는 기본 성능의 125% 이상을 축 범위로 사용해 기본 성능 선과 증가분을 구분한다.
연구 오류는 한 상태 표시 영역을 갱신하므로 반복 실패 메시지가 겹쳐 쌓이지 않는다.

## 수치 비교의 범위

`ComponentComparison`은 `FleetLoadouts.ResolveFit` 결과에서 읽는다. 기본 카탈로그 배율을 현재 수치에 다시 곱하지 않는다.

| 계통 | 화면에 상시 표시하는 값 |
|---|---|
| 주포 | 발당 에너지, 포신 수, 관통, 장전 시간 |
| 부포/PD | 연사, 사거리, 미사일·어뢰 피해, 드론 피해 |
| 엔진 | 전진·횡이동·제동 가속 |
| 센서 | 센서 강도, 노출 신호, 센서 전력 |
| 발전기 | 발전량, 냉각, 열용량 |
| 실드 | 용량, 초당 재충전, 재충전 지연 |

전력 수요·질량 비교와 카탈로그의 기타 이득/대가는 버튼 및 설명 툴팁에서 확인할 수 있다. 기본형 복귀도 툴팁으로 비교한다.
이 수치는 손상이 없는 정격 성능이다. 전투 중 핍·손상·과열·센서 환경에 따른 순간 실효 성능을 예측한 값은 아니다.
예산 조건을 충족하지 못해 완전한 fit을 만들 수 없는 후보에는 거짓 수치를 만들지 않고 기존 카탈로그 설명과 장착 불가 사유를 표시한다.

추가 화면: [PD](after-hangar-pd.png), [엔진](after-hangar-engine.png), [센서](after-hangar-sensor.png), [발전기](after-hangar-generator.png), [1600×900 전투](after-combat.png).

## 검증

- `dotnet build SpaceFleet.csproj --no-restore -v minimal`: 성공, 컴파일 오류 0. 기존 NuGet 취약성 조회 연결 경고 NU1900 2건. [로그](build.log)
- 격납고·미리보기·장착·출격·인계 **35개 통과**. RP 부족 표기, 버튼을 통한 프리셋 변경 후 초점, 3연장 장착 상태에서 단장 후보 비교를 추가 확인했다. [로그](hangar-checks.log)
- 연구·구매·출격·결과·재출격 **32개 통과**. 선행 연구 조건과 구매 버튼을 통해 함급을 해금한 뒤 편성 버튼으로 초점이 복원되는지 추가 확인했다. [로그](progression-checks.log)
- 무기 선택·망원·요격·피해복구 입력 **276개 통과**. [로그](weapon-input-checks.log)
- 13개 최종 캡처의 Godot 오류·예외 없음. SAFE 격리용기 80% 경고와 ARMED 100% 상태는 이미지와 [경고 로그](after-am-warning.log), [준비 로그](after-am-ready.log)로 확인했다.
- 불투명 메뉴 색상쌍 계산: 보조 본문/화면 8.75:1, 비활성 글자/버튼 8.31:1, 출격 글자/채움 9.56:1. [계산값](contrast.json)

실제 운영체제 입력으로 모든 Tab 순서·장시간 전투를 수동 플레이한 검증은 아니다. 버튼 신호·Godot 초점·기존 입력 라우팅 자동검사와 렌더 검사를 수행했다. 다른 DPI·울트라와이드·모든 HUD 중첩 상태 및 화면 읽기 지원을 포함한 전체 접근성 적합 판정은 범위에 포함하지 않는다. 1280×720의 일부 보조 글자는 여전히 작으므로 UI 배율 기능을 별도 설계할 때 추가 검토할 수 있다.

## 재현

저장소 루트에서:

```powershell
dotnet build SpaceFleet.csproj --no-restore -v minimal
powershell -ExecutionPolicy Bypass -File docs/validation/ui_ux_20261016/check-flows.ps1
powershell -ExecutionPolicy Bypass -File docs/validation/ui_ux_20261016/capture.ps1 -Phase after
```

특정 상태는 `-Only hangar-pd`, `-Only am-warning`처럼 지정한다. `before-*.png`는 수정 전 코드에서 저장한 비교 근거이므로 현재 코드로 덮어쓰지 않는다.
