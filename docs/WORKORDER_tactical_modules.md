# Project Fleet — 부품·전술 모듈 분리 및 단축키 개편

## 1. 작업 목적

기존 Project Fleet의 부품 교체 시스템과 모듈 장착 시스템이 모두 기본 능력치 강화에 집중되어 있어 기능이 중복된다.

이를 다음과 같이 재정의한다.

**부품(Parts)**

함선을 구성하는 무장·센서·발전·방어 등의 실제 장비. 기본 성능과 물리적인 구성에 영향을 준다.

**전술 모듈(Tactical Modules)**

기존 장비의 운용 방법을 강화하거나 새로운 전투 능력을 추가하는 장치. 액티브 스킬 또는 패시브 효과를 제공한다.

전술 모듈을 통해 같은 함급·같은 주포를 사용하더라도 서로 다른 전투 운용이 가능해야 한다.

이번 작업에는 기존 장비의 이관, 신규 전술 모듈, 스킬 단축키, 격납고 UI, 전투 HUD, AI 운용, 저장 데이터 호환성 및 자동검증을 포함한다.

기존 전투 규칙과 무장·피해·센서 시스템을 가능한 한 재사용한다.

## 2. 전투 단축키 개편

### 2.1 확정 기본 배치

| 키 | 변경 후 기능 |
|---|---|
| 1 | 주포 선택 |
| 2 | 미사일 선택 |
| 3 | 반물질 강습어뢰 선택 |
| 4 | 전술 스킬 슬롯 1 |
| 5 | 전술 스킬 슬롯 2 |
| 6 | 전술 스킬 슬롯 3 |
| 7 | 전술 스킬 슬롯 4 |
| F | 전력 배분 라디얼 |
| B | 사격통제 라디얼 |
| N | 편대 명령 라디얼 |
| K | 드론 방어구역 라디얼 |
| L | 응급복구 라디얼 |

기존 4번 드론 메뉴는 K로, 5번 응급복구 메뉴는 L로 변경한다.

나머지 비행·사격·지도·디코이·표적 선택 조작은 유지한다.

특히 다음 기존 기능을 변경하지 않는다.

- F1 도움말
- M 전체 지도
- R 표적 선택
- C 디코이
- Backspace 반물질탄 비상 투기
- F6 개발용 전체 복구
- G/H/J 개발용 편대 명령

K와 L은 기본값으로 사용하며 추후 키 설정 기능에서 재할당할 수 있는 구조를 유지한다.

### 2.2 전술 스킬 발동 규칙

4~7번은 무장 선택이 아니라 **즉시 능력 발동**에 사용한다.

키를 누르면 해당 슬롯의 모듈이 발동한다.

- 단발 능력은 한 번만 발동
- 지속형 능력은 활성 상태로 진입
- 토글형 능력은 다시 눌러 종료
- 재사용 대기시간 중에는 발동하지 않음
- 모듈이 파괴되거나 전력 공급이 끊기면 사용 불가
- 모듈 미장착 슬롯은 아무 효과 없음

키를 누르고 있을 때 반복 발동하지 않도록 입력 반복을 차단한다.

### 2.3 스킬 슬롯과 장착 슬롯의 분리

전술 모듈을 최대 4개까지 단축키에 할당할 수 있는 입력 구조를 마련한다.

다만 모든 함선이 전술 모듈 4개를 장착할 수 있는 것은 아니다.

실제 장착 개수는 함선의 전술 모듈 베이, 규격, 전력과 기타 제약에 따른다.

패시브 전술 모듈은 스킬 단축키를 차지하지 않는다.

액티브 모듈만 4번부터 차례대로 할당하고, 격납고에서 필요하면 활성 스킬 순서를 변경할 수 있게 한다.

예:

- 4 — 발전기 과부하
- 5 — 긴급 열 배출
- 6 — 단거리 초공간도약
- 7 — 미장착

### 2.4 입력 충돌 방지

`InputSetup.cs`, `RadialCommands.cs`, `ScaleTest.cs`의 기존 입력 경로를 점검한다.

전술 스킬은 다음 상황에서 발동하지 않는다.

- 라디얼 메뉴 사용 중
- 전체 지도 조작 중
- 도움말 및 기타 UI 입력 중
- 일시정지
- 전투 종료
- 관전 중
- 조종 불가능 상태

조종권 인계 시 현재 새 함선의 전술 모듈 슬롯을 읽어 표시한다.

요격함의 마우스 캡처를 유지하고, 스킬 사용으로 기수가 갑자기 선회하거나 무기가 발사되지 않도록 한다.

K/L 라디얼은 기존 메뉴의 입력 캡처 복구 및 발사 입력 차단 규칙을 그대로 사용한다.

## 3. 기존 강화 모듈의 부품 이관

현재 다음 장비는 `data/modules/`에 성능 강화 모듈로 정의되어 있다.

| 기존 모듈 | 새 분류 |
|---|---|
| 고용량 실드 | 실드 부품 |
| 고출력 센서 | 센서 부품 |
| ECM 증폭기 | 전자전 부품 |
| 방어 드론 격납고 확장 | 드론·격납고 부품 |

새 부품은 기존 능력치 변화, 전력 소비, 발열, 질량, 모듈 손상 및 드론 소유권 규칙을 보존해야 한다.

단순히 JSON의 분류 이름만 바꾸지 말고 실제 부품 카탈로그와 격납고 장착 경로에 연결한다.

특히 드론 격납고는 파괴 시 운용이 중단되고 탄약이 재보급되지 않는 기존 규칙을 유지한다.

기존 센서·실드·발전기 교체 계통과 새 부품이 효과를 이중으로 적용하지 않도록 한다.

### 베이 재정비

기존 `EquipmentBay`는 위치·크기·전력망·충돌 및 피해 판정 구조를 이미 제공한다.

이 물리적 구조를 전술 모듈 장착에도 활용한다.

다만 부품 장착점과 전술 모듈 장착점은 논리적으로 분리한다.

- 주포·센서·실드·드론 등은 해당 장비의 전용 부품 장착점
- 전술 모듈은 전술 모듈 베이
- 기존 베이 위치와 새 부품이 겹치지 않도록 배치 검증
- 필요하면 함급별 모듈 베이의 위치·규격을 재정의

전술 모듈 역시 함선 내부의 실제 장치로 존재할 수 있으며, 설치 위치에 따라 적 공격으로 파괴될 수 있다.

## 4. 전술 모듈의 유형

전술 모듈은 세 가지로 나눈다.

### 패시브

장착하면 지속적인 운용 효과를 제공한다.

예: 긴급복구 키트 증가, 미사일 급속 장전.

전력·장비 상태에 따라 효과가 약화되거나 비활성화될 수 있다.

### 액티브

플레이어가 발동하는 특수 능력이다.

예: 발전기 과부하, 긴급 열 배출, 초공간도약.

준비시간, 지속시간, 소모량, 재사용 대기시간을 가진다.

### 복합형

기본적으로 지속 효과를 제공하면서 별도의 발동 능력도 가진다.

예: 방공 통제기가 평상시에는 위협 탐색을 보조하고, 발동 중에는 특정 방어구역으로 센서·사격통제를 집중하는 방식.

첫 구현에서는 지나치게 복잡한 복합형보다 패시브와 액티브를 우선한다.

## 5. 신규 전술 모듈 목록

수치는 최초 구현 및 밸런스 시험을 위한 제안값이다. 실제 전투 결과에 따라 조정한다.

### A. 예비 복구 자재고

**유형:** 패시브

긴급복구 키트 수 +2.

기존 함선의 키트 최대치에 추가한다.

추가 키트는 전투 시작 시 한 번 제공되며, 모듈 손상·복구를 반복해도 재보급되지 않는다.

추가 키트 보관 구획이 파괴되면 미사용 예비분의 접근을 제한할 수 있다. 이미 소비한 키트는 복구되지 않는다.

추가 질량과 모듈 베이 점유를 대가로 한다.

### B. 긴급복구 통제기

**유형:** 패시브

기존 긴급복구 작업 시간을 25% 단축한다.

`DamageControlState`의 기존 작업 진행, 피격 후 재개 대기 및 응급복구 상한을 유지한다.

모듈이 파괴되면 남은 작업은 기본 복구 속도로 진행한다.

무력화 상태에서 복구 가능한 유예시간을 늘리는 효과는 작업 시간 단축과 구별한다. 필요하면 별도 개량형으로 60초 기본 유예시간을 연장하도록 설계한다.

### C. 발전기 과부하 제어기

**유형:** 액티브

| 속성 | 초기 제안 |
|---|---|
| 발동 준비 | 즉시 |
| 지속시간 | 8초 |
| 발전 출력 | +25% |
| 재사용 대기시간 | 90초 |
| 대가 | 발전·발열 부담 증가 |

현재 `ShipPower`의 가용 발전량과 공급률 계산에 연결한다.

전력 핍 개수를 늘리는 방식이 아니라 일정 시간 실제 가용 발전 출력을 증가시킨다.

과부하 중에도 기존 과열 제한이 정상적으로 작동해야 한다.

발전기 또는 관련 전력망이 파괴되면 과부하 능력을 잃는다.

과부하가 끝난 직후에는 전력과 열 상태가 정상적인 물리 계산으로 복귀한다.

### D. 긴급 열 배출 장치

**유형:** 액티브

| 속성 | 초기 제안 |
|---|---|
| 발동 준비 | 즉시 |
| 발동 효과 | 열용량 기준 열 30% 제거 |
| 재사용 대기시간 | 100초 |
| 대가 | 일시적인 적외선 신호 증가 |

현재 축적된 열을 기준으로 최대 제거량을 제한한다.

모든 과열 상태를 무조건 해제하는 만능 장치로 만들지 않는다.

열 배출 중 강한 적외선 신호가 발생하도록 하고 기존 센서 탐지 계산에 반영한다.

일정 시간 센서에 쉽게 포착되는 대가를 제공한다.

시각효과는 함체 방열판·배출구에서 발생하도록 한다.

### E. 확장 방공 통제기

**유형:** 패시브 또는 복합형

아군 방어권의 미사일 위협 정보 수집 및 교전 배분 능력을 확장한다.

단순히 PD의 명중거리 수치를 무조건 증가시키지 않는다.

효과는 다음에 집중한다.

- 더 먼 위협 정보의 수신과 분석
- 방공 목표 할당 범위 확장
- 아군 방어 대상의 위협 우선순위 개선
- 중복 요격 감소
- 드론과 PD의 연계 운용 개선

실제 포탄·레이저·요격탄의 사거리, 탄속, 포탑 선회 제한은 유지한다.

아군 센서망에 없는 적 미사일 위치를 알아내는 기능은 금지한다.

기본 센서나 PD 장비가 손상되면 실제 사용 가능한 방공 능력도 감소해야 한다.

### F. 미사일 급속 장전기

**유형:** 패시브

미사일 발사기 재장전 시간 약 15% 단축.

기존 발사기 및 탄종별 실제 재장전 값에 적용한다.

미사일 탑재량, 탄두 피해량, 유도 능력은 변경하지 않는다.

추가 전력 소비 또는 폐열 부담을 부여한다.

여러 발사기가 있는 함선에서도 재장전 감소가 중첩되지 않도록 한다.

발사기가 파괴되거나 탄약이 소진된 경우에는 효과가 없다.

### G. 집중 탐색 통제기

**유형:** 액티브

| 속성 | 초기 제안 |
|---|---|
| 지속시간 | 10초 |
| 재사용 대기시간 | 60초 |
| 효과 | 지정 방향 탐지·식별 능력 강화 |
| 대가 | 다른 방향의 관측 품질 저하 또는 신호 노출 |

현재 센서망과 데이터링크 구조를 사용한다.

지정 방향에 관측 자원을 집중하며, 기존 센서 손상·ECM·소행성 차폐를 무시하지 않는다.

효과가 있는 동안 정찰 지원 기록도 실제 센서 출처와 연결되어야 한다.

### H. 단거리 초공간도약 장치

**유형:** 액티브

이전의 초공간도약 구상을 전술 모듈로 구현한다.

| 속성 | 초기 제안 |
|---|---|
| 준비시간 | 3초 |
| 최대 도약거리 | 10km |
| 재사용 대기시간 | 120초 |
| 도약 후 속도 | 기존 관성 유지 |
| 도약 후 자세 | 기존 자세 유지 |

사용 흐름:

1. 플레이어가 스킬을 발동한다.
2. 현재 진행 방향 또는 지정한 안전한 방향으로 도약 목적지를 설정한다.
3. 도약 준비 상태에 진입한다.
4. 고에너지 신호와 시각적인 준비 효과가 나타난다.
5. 준비가 완료되면 도착 위치를 최종 검사한다.
6. 도약에 성공하면 해당 위치로 순간 재배치한다.
7. 재사용 대기시간에 들어간다.

도약 목적지 지정은 기존 조준 방향과 전술지도를 재사용할 수 있도록 설계한다.

**필수 제한**

- 도착 지점에 소행성·정거장·대형 잔해가 있으면 도약 불가
- 아군·적군 함선 내부로 도약 불가
- 도약 준비 중 해당 장치가 파괴되면 발동 취소
- 전력 부족이나 전투불능 등 발동 조건 검사
- 도약 준비 중 무장 사용 제한
- 실패한 도약에서 부당한 탄약·재사용 대기시간 소모 방지
- 실제 도약 시 기존 속도와 자세 보존
- 도약 후 미사일·센서·AI의 위치 인식 정상 갱신

도약은 기존 6DOF 관성 운동과 전장 충돌 체계를 우회하는 무제한 순간이동이 되어서는 안 된다.

도약 경로상의 장애물과 도착 지점 장애물은 별개로 취급한다. 초공간을 통한 장애물 우회는 가능하지만 도착 위치의 안전성은 반드시 보장한다.

소행성대에서의 도약, 기함전 도약 이탈, 점령전 재배치 등을 실제로 시험한다.

도약관문이나 중력우물에 의한 도약 간섭은 추후 전장 확장 시 추가한다.

## 6. 모듈 장착과 전투 상태

### 장착 제약

전술 모듈은 다음 제약을 따른다.

- 베이 크기 및 장착 가능 분류
- 함급·티어별 호환성
- 진영별 연구 조건
- 소비 전력
- 추가 질량
- 발열
- 동일 계열 중복 제한
- 파괴 위험과 전력망 연결

모든 함급이 모든 모듈을 반드시 장착할 수 있게 만들 필요는 없다.

다만 역할별 전술 선택이 가능하도록 함급의 크기와 장비 구조를 바탕으로 제한한다.

### 런타임 상태

액티브 모듈마다 다음 상태를 둔다.

- 준비 완료
- 준비 중
- 발동 중
- 재사용 대기
- 사용 불가
- 파괴 또는 기능 상실

횟수 제한형은 잔여 사용 횟수도 가진다.

재사용 대기시간과 소모 횟수는 함선에 귀속된다.

모듈이 손상되었다가 긴급복구되어도 재사용 대기시간이 초기화되거나 소모 횟수가 복구되지 않도록 한다.

단순히 모듈을 다시 활성화하는 것으로 전투 중 장비를 재보급할 수 없어야 한다.

### 전술 모듈의 피해 처리

전술 모듈은 기존 선체 피해 레이와 모듈 손상 시스템을 사용한다.

파괴되면 해당 효과가 비활성화된다.

발동 중 파괴된 모듈은 사용 중인 능력을 안전하게 중단한다.

응급복구로 기능이 일부 회복되면 능력 사용 가능 여부를 다시 계산한다.

발동 상태, 남은 시간, 재사용 대기와 소모량은 임의로 초기화하지 않는다.

## 7. 격납고 UI 변경

현재 주포·부포·미사일·발전 등은 부품 중심 메뉴로 통합되어 있으므로 그 구조를 유지한다.

격납고에 명확한 **전술 모듈** 영역을 마련한다.

### 부품 교체

주포, PD, 발사기, 탄종, 엔진, 센서, 발전·냉각, 실드, 드론 등 기본 장비를 교체한다.

각 부품의 성능·질량·전력·열·규격을 비교한다.

주포는 앞서 논의한 마운트 직접 클릭 방식과 연동 가능한 구조를 유지한다.

### 전술 모듈

기존 함선 베이 위치를 확인하고 해당 구역에 전술 모듈을 장착한다.

모듈을 선택하면 다음을 표시한다.

- 모듈 이름과 용도
- 패시브/액티브 구분
- 전투 중 발동 효과
- 지속시간과 재사용 대기
- 장착 규격과 요구 전력
- 추가 질량과 발열
- 위험과 제약
- 현재 장착 모듈과의 차이
- 연구 및 장착 비용

액티브 모듈은 사용 단축키를 함께 표시한다.

예:

`4 · 발전기 과부하`

`5 · 긴급 열 배출`

`6 · 초공간도약`

패시브 모듈에는 단축키를 부여하지 않는다.

전투에 사용할 액티브 스킬의 순서는 장착 화면에서 변경할 수 있게 한다.

기존 프리셋 3개와 개별 편대원 장착 방식에 연결한다.

장착 결과는 즉시 시뮬레이션 정의로 검증하고, 확인 전에는 RP나 저장 내용을 변경하지 않는다.

## 8. 전투 HUD

전술 모듈용 작은 스킬 슬롯 표시를 추가한다.

### 스킬 표시 예시

| 슬롯 | 장착 스킬 | 상태 |
|---|---|---|
| 4 | 발전기 과부하 | 사용 가능 |
| 5 | 긴급 열 배출 | 42초 후 |
| 6 | 초공간도약 | 준비 중 |
| 7 | 미장착 | 비어 있음 |

게임 화면에는 표 대신 작은 아이콘과 숫자, 재사용 대기 표시를 사용한다.

모듈을 발동하면 짧은 상태 피드백을 제공한다.

- `과부하 작동 · 8초`
- `열 배출 완료`
- `도약 준비 · 3초`
- `도약 불가 · 도착 공간 부족`
- `모듈 파괴 · 사용 불가`

기존 전투 리본, 격침 배너, 무장 선택, 반물질 어뢰 상태, 전력·피해 HUD와 겹치지 않게 한다.

현재 리본은 조준점 아래 무장 선택 줄 부근에서 등장하므로 **전술 스킬 UI와 리본 팝업의 공간을 따로 검토**한다.

단순히 기존 무장 선택 줄 위에 스킬 아이콘을 추가해 겹치게 하지 않는다.

1280×720, 1600×900, 텍스트 100% 및 130%에서 검증한다.

K/L로 바뀐 드론·수리 단축키는 해당 HUD에 반영한다.

F1 도움말과 조작 안내에서도 기존 4/5 표기를 전부 교체한다.

## 9. AI의 전술 모듈 운용

AI 함선도 장착한 전술 모듈의 패시브 효과를 정상적으로 사용한다.

액티브 스킬은 상황에 따라 사용한다.

예:

**발전기 과부하**

주포 재장전, 실드 충전, 강한 전력 수요가 겹치고 과열 위험을 감당할 수 있을 때 사용.

**긴급 열 배출**

과열 또는 냉각 문제로 주요 전투 기능이 제한될 때 사용.

**집중 탐색**

관측 정보가 부족하거나 정찰 임무 중 탐색할 방향이 뚜렷할 때 사용.

**초공간도약**

충돌 위험·전술적 이탈·사격선 확보·강습 접근 등 명확한 필요가 있을 때 사용.

도약은 무조건 적에게 가까워지는 단순 돌격 수단으로 사용하지 않는다.

AI 판단은 실제 관측 정보만 사용하며 미탐지 표적 좌표를 참조해서는 안 된다.

모듈 미장착, 파괴, 전력 부족, 재사용 대기시간을 정상 처리한다.

액티브 AI 판단은 기존 AI 주기와 성능 예산에 연결하고 매 틱 과도한 경로 탐색이나 목록 생성을 추가하지 않는다.

## 10. 저장 데이터 및 연구 이관

현재 `hangar.json`은 v5 형식을 사용하고 있다.

새 전술 모듈 구조를 추가할 때 버전을 올리고 기존 저장 파일을 호환 이관한다.

### 반드시 보존할 내용

- 보유 함선
- 연구 점수(RP)
- 기존 함급·부품 연구 상태
- 프리셋 3개
- 개별 편대원 세팅
- 무장 교체 정보
- 기존 베이 장비 선택
- 편대 구성
- 저장 백업 및 손상 파일 보호

기존 고용량 실드·센서·ECM·드론 확장은 대응하는 새 부품으로 이관한다.

이관된 장비에 기존 능력치 효과를 남겨 같은 강화가 두 번 적용되지 않도록 한다.

이미 연구하거나 장착한 장비를 다시 구매하도록 만들지 않는다.

구형 저장의 모듈 위치와 새 장착 규칙이 충돌하는 경우 임의로 장비를 삭제하거나 RP를 차감하지 않는다. 호환 가능한 이관 또는 명시적 처리 경로를 만든다.

이관은 검증을 완료한 뒤 원자적으로 저장하고, 실패하면 원본을 보존한다.

기존 베이 장비 데이터를 단순 삭제하는 방식은 금지한다.

AI의 액티브 스킬 사용 조건을 구현·조정한다.

전술 모듈 조합별 공격·방어·생존·승률을 측정한다.

기존 전투 결과의 변경이 의도한 모듈 효과 때문인지 별도 확인한다.

## 13. 필수 검증

### 단축키

- 1·2·3 무장 선택 유지
- 4·5·6·7 각각 할당된 능력만 발동
- K 드론 라디얼 정상 동작
- L 응급복구 라디얼 정상 동작
- F/B/N 메뉴와 충돌 없음
- F6 개발용 복구 유지
- 드론이 없는 함선에서 K를 눌러도 입력 정상 복귀
- 모듈이 없는 슬롯 입력은 안전하게 무시
- 키 유지·반복 입력으로 스킬 중복 발동 없음
- 라디얼·지도·일시정지·관전·도움말에서 스킬 오발 없음

### 모듈 효과

- 능력 발동과 종료 시간이 정확함
- 전력·폐열·질량이 실제 계산에 반영됨
- 모듈 파괴 시 효과 중지
- 응급복구로 재사용 대기나 소모 횟수가 초기화되지 않음
- 과부하 중 과열과 전력 부족 계산 유지
- 긴급 열 배출 후 탐지 신호 증가 반영
- 방공 지원이 미탐지 적의 정보를 사용하지 않음
- 미사일 급속 장전이 탄약을 늘리지 않음
- 초공간도약 중 충돌·위치·속도·자세 정상

### 저장·연구

- 기존 v1~v5 저장 이관
- 보유·RP·연구·편대 유지
- 기존 강화 모듈의 부품 전환
- 중복 강화 효과 제거
- 프리셋/개별 장착 저장
- 장착 실패 시 RP와 세팅 불변
- 출격 스냅샷과 실제 전투 장비 일치
- 조종권 인계 후 해당 함선의 모듈 상태 유지

### 전투 및 성능

- 섬멸전·기함전·점령전
- 심우주·소행성 군집
- 지구·화성 혼성 함대
- 24척 및 약 80척 전투
- 같은 시드의 결정성 검사
- 도약·과부하 등 스킬 발동 시 로그 기록
- 추가 틱 비용과 FPS 확인

전술 모듈이 없는 기존 기본 세팅에서는 이전 전투 결과가 유지되어야 한다.

변경된 전투 규칙은 전술 모듈을 실제로 장착·사용한 경우에 한정한다.

## 14. 완료 기준

1. 기존 강화형 모듈 네 종류가 부품으로 이관된다.
2. 전술 모듈은 기존 장비의 운용 강화 또는 신규 특수 능력으로 작동한다.
3. 무장은 1~3, 액티브 전술 스킬은 4~7을 사용한다.
4. 드론 K, 응급복구 L이 정상 작동한다.
5. 패시브 모듈은 단축키 없이 정상 적용된다.
6. 스킬의 준비·지속·재사용 대기·파괴 상태가 HUD에 표시된다.
7. 기존 모듈 피해와 응급복구 체계를 유지한다.
8. 기존 저장·연구·편대 세팅을 잃지 않는다.
9. AI도 유효한 전술 모듈을 상황에 맞게 사용한다.
10. 모든 전투 모드와 주요 함급에서 자동검사 및 실제 게임 검증을 통과한다.

**최종 목표: 부품은 함선의 물리적 성능을 결정하고, 전술 모듈은 그 함선이 전장에서 무엇을 할 수 있는지를 결정한다.**
