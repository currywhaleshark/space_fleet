# 함대 규모 부하 시험

```powershell
dotnet run --project tools/ScaleBench -c Release -- --groups 1,2,4,10 --warmup 15 --seconds 60 --repeats 3 --output shots/scale/scale.json
```

`groups`는 **각 진영의 기존 12척 편성 수**다. 1·2·4·10은 양측 합계 24·48·96·240척이며, 각 편성의 전투단·호위 전대·요격 편대와 센서/무장/지휘 AI를 모두 실행한다. 10:10에서 플레이어마다 현재 편성 전체가 따라온다는 가정의 상한 부하를 시험할 수 있다. 실제 플레이어 수, 최종 편대 구성, 네트워크 동기화를 구현하거나 게임의 기본 출격 수를 바꾸지는 않는다.

기본값은 심우주, 초기 진영 간 거리 40km, 인접 편성은 14km/10km 간격이다. 개별 독립 전투를 병렬 실행하는 방식이 아니라 **하나의 SimWorld에 모든 함선을 넣어** 서로 탐지하고 교전시킨다. 15초 준비 후 60초를 측정하며, 초기 근거리 교전 부하를 재현하는 합성 시나리오다. `--battlefield AsteroidCluster --field-seed 2`로 동일 함대에 소행성을 추가하고, `--warmup 180 --seconds 60`으로 후반 구간을 측정할 수 있다. 실제 GPU·음향·네트워크 비용은 별도로 측정해야 한다.

출력은 평균·p95·p99·최대 틱 시간, 틱당 할당 바이트, 동시 탄체/미사일/프로브 최고 수, 생존 전력, 구간별 µs/틱과 전투 요약 SHA-256이다. 틱은 기존 60Hz, 충돌과 탄도는 기존 240Hz다. 시뮬레이션 프로파일러를 켜므로 소량의 계측 비용을 포함한다. 시간 측정용 배열과 결과 직렬화는 측정 밖에 둔다.

한 번에 하나의 실행기만 실행하고 게임·빌드·다른 검사와 겹치지 않게 한다. 전후 버전의 실행 순서를 번갈아 바꾸며 반복하고, 같은 시드의 결과 해시도 비교한다. 단계별 JSON을 저장하므로 긴 240척 시험이 끝난 범위까지 복구할 수 있다. 이전 소스를 별도 폴더에 보존했다면 MSBuild의 `SimSource` 속성으로 같은 시험 코드를 이전 시뮬레이션에 연결할 수 있다.

60Hz의 전체 틱 예산은 약 16.67ms다. 이 도구의 수치가 예산 아래라는 것만으로 게임이 60 FPS라는 뜻은 아니다. 4배속이면 초당 처리할 틱도 네 배가 된다.
