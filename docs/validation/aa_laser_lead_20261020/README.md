# 방공 레이저가 미사일을 쏘지 못하던 문제 (2026-10-20)

사용자 보고: 방공순양함 레이저가 미사일을 격추하지 못한다. 미사일을 잠그면 수동(좌클릭 유지)도 자동(자율 교리)도 쏘지 않는다.

## 원인

- 포탑은 움직이는 표적을 따라갈 때 조준 각속도만큼 미리 돌아간다(`RailgunState.Step` → `Lead`).
  - 다음 틱에 정렬했을 때 포탑이 이미 그 방향에 있게 하려는 것이다.
- 레일건은 사격 요청 순간에 정렬을 보고 바로 쏜다.
- 레이저는 다르다.
  - 요청은 1.5틱 동안만 유효하다.
  - 실제 조사(`SimWorld.StepLasers`)는 다음 틱에 다시 정렬을 판정한다.
  - 이때 앞당겨 돌아간 포신과, 앞당기기 전인 **한 틱 전 요청 방향**을 비교했다.
- 정렬 허용 오차는 0.03°다. 한 틱(1/60초)에 표적 방향이 그보다 많이 바뀌면, 즉 초당 약 1.8° 이상이면 조사가 한 번도 켜지지 않았다.
  - 예: 4 km 거리를 2 km/s로 가로지르는 미사일은 초당 약 29°다.
- 자기 쪽으로 곧장 오는 미사일은 방향이 거의 바뀌지 않아 정상이었다.
  - 그래서 기존 검사(정지한 미사일, 정면으로 오는 파도)는 통과했다.
  - 실제 전투에서 다른 함선을 노리고 옆을 지나는 미사일은 거의 맞히지 못했다.
- 플레이어 잠금 경로(`StepSmallTargetBattery`)와 AI 방어 포대가 같은 레이저 단계를 거치므로 둘 다 막혔다.

## 수정

- `RailgunState.Led(requested)`: 이 포탑이 따라가고 있는 요청이면, 포탑과 같은 앞당김을 지금 시각까지 적용한 방향을 돌려준다. 아니면 그대로 돌려준다.
- `StepLasers`가 정렬과 사선 판정에 이 방향을 쓴다.
- 조사 방향은 원래부터 실제 포신 방향이다. 그래서 명중 판정(반경 3 m)과 물리 구동 한계(선회 속도)는 바뀌지 않는다.
  - 포탑이 따라가지 못할 만큼 빠른 근접 횡단은 여전히 쏘지 못한다(기존 검사 "Unaligned close crossing" 유지).

## 재현과 확인 (`aa_player_before.json` → `aa_player_after.json`)

방공순양함 T3·T5, 연구 없음 / 포좌 확장·주포 전원, 시드 3개. 미사일 6발을 4초 간격으로 쏜다. 결과는 합계다.

| 비행 | 방식 | 수정 전 격추 | 수정 전 펄스 | 수정 후 격추 | 수정 후 펄스 |
|---|---|---|---|---|---|
| 자기에게 오는 관성 비행 | AI | 72 / 72 | 912 | 72 / 72 | 912 |
| 자기에게 오는 관성 비행 | 플레이어 잠금 | 72 / 72 | 144 | 72 / 72 | 144 |
| 자기에게 실제 발사(가속·유도) | AI | 72 / 72 | 934 | 72 / 72 | 934 |
| 자기에게 실제 발사 | 플레이어 잠금 | 72 / 72 | 163 | 72 / 72 | 163 |
| **5 km 옆 아군에게 실제 발사** | AI | **0 / 72** | **0** | 72 / 72 | 989 |
| **5 km 옆 아군에게 실제 발사** | 플레이어 잠금 | **0 / 72** | **0** | 72 / 72 | 162 |

- 수정 전 "옆 아군" 플레이어 잠금에서 사격 요청은 받아들여졌다. 그러나 다음 틱 판정이 매번 "정렬 안 됨"이었다.
  - 진단 계수로 확인했다: 2,309번 중 2,309번.
- 플레이어 잠금 흉내는 `ScaleTest.StepSmallTargetBattery`와 같은 순서다(잠금 유지 → 포탑별 `SmallTargetAim` → `Aim` → `FireRailgun`).
  - 실험 단계는 `BattleBatch --component-trials --phase aa-player`다.

## 영향

- **방공 시험**(4파 48발, 2.5 km/s, `laser_duels_after.json`의 방공 행):

  | | 수정 전 요격 | 수정 후 요격 |
  |---|---|---|
  | 기본 레이저 | 23.8 | **46.0** |
  | 대형 레이저 | 23.4 | **45.6** |
  | 레일 2연장 | 22.2 | 22.2 |

- **포화 파도**(48발, 3.5 km/s, 기존 `--aa-lasers` 출력): 레이저 22 → 48 / 192, 겹방어 31 → 46 / 192.
- **함선 결투**: 방공순양함·전함 레이저 결투 540전의 결과가 수정 전과 **완전히 같다**. 함선 표적은 각속도가 작기 때문이다.
- **함대 기본 편성**(강제 부품 실험과 같은 32경기, 모두 기본 장착, `fleet_stock.txt`):
  - 청팀 ÷ 적팀 피해 비가 0.967 → 1.000(+3.4%)이고, 청팀 승은 13 → 14다.
  - 두 팀 모두 수정의 영향을 받으므로 잡음 범위(±8%) 안의 변화다.
- **이후 부품 실험의 기준선**은 이 결과(`fleet_stock_after.csv`)로 바꿔야 한다. 지금까지의 강제 부품 실험은 수정 전 코드끼리(기준선 포함) 비교했으므로, 비교 자체는 유효하다. 다만 레이저와 관련된 부품(대형 레이저, 전열 레이저, 냉각기)은 미사일 요격이 강해진 만큼 함대 효과를 다시 재야 한다.

## 검사

- SimChecks `--aa-lasers`에 회귀 검사를 더했다.
  - 옆 아군을 노리는 미사일 3발을 자동 방어와 플레이어 잠금이 모두 격추한다.
  - `Led`는 새 요청과 관계없는 요청을 바꾸지 않는다.
  - 수정 없이 돌리면 "0/3, 0 pulses"로 실패한다.
- 실제 렌더러 `--weapon-input-test`에 가로지르는 실제 미사일 사례를 더했다(방공순양함 T3·T4·T5, 자율 교리와 좌클릭 유지).
  - 수정 없이 돌리면 "automatic doctrine destroys a crossing missile (health 4, pulses 0)"으로 실패한다. 사용자 보고와 같은 증상이다.
  - 수정 후 366개가 통과했다.
- 전체 SimChecks 69묶음 5,795,058개 통과(`sim-all.log`).
  - 이전과 출력이 다른 줄은 방공 레이저 파도 8줄뿐이다.
  - 정면 파도는 요격이 이미 48/48이고 펄스만 늘었다. 3.5 km/s 포화 파도의 요격은 늘었다.
