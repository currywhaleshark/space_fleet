# 지구권 / 화성권 함대

`Faction.Blue/Red`는 전투 팀이고 `DesignFamily.Earth/Mars`는 함체 설계 계통이다. 서로 묶이지 않는다. 기존 `battleship`, `escort`, `interceptor` JSON·Blender 원본·GLB는 보존하고, `mars_battleship`, `mars_escort`, `mars_interceptor`를 추가했다. 기존 JSON의 누락된 `design`은 Earth로 해석한다.

## 플레이

출항 → 아군 설계 / 적군 설계를 각각 선택 → 전함·호위함·요격함 중 지휘할 함선을 선택한다. 기본 대전은 지구 Blue 대 화성 Red다. 지구 대 지구, 화성 대 화성, 화성 Blue 대 지구 Red도 가능하다. 주포 1·미사일 2·어뢰 3, 좌클릭 발사, 망원·라디얼·드론·피해·복구 체계는 공통이다. 양쪽 요격함 모두 일반 미사일 4발과 반물질 어뢰 2발을 독립적으로 탑재한다.

```powershell
.\tools\run.ps1 --battle --blue-design=Mars --red-design=Earth --control=IC-21 --seed=1
```

화성 전함의 단발 관통력은 2650mm(지구 1800), 모든 포탑이 사격할 때 기준 지속 에너지는 약 1769/s(지구 2800/s)다. 장갑·실드·모듈 체력·발전 계통 중복성을 낮춰 정면 소모전의 대가를 둔다. 반응로 예비 계통 제거와 취약한 외부 방열판은 기존 전력/열/모듈 피해 계산에 실제로 작용한다. 포보스 격리용기의 체력과 SAFE/ARMING 위험 임계값은 지구 요격함과 같으며 얇은 선체와 약한 실드의 위험을 유지한다. 수치는 초기 밸런스다.

## 데이터와 렌더링

- `ShipDefinitions.ById(id)`로 함체를 선택한다. `For(kind, design)`은 기본 함체 선택 편의 함수이며 기존 `For(kind)` 호출은 지구형이다. 신규 코드는 `new ShipBody(callsign, definition, team)`을 사용한다.
- `BattleConfig.BlueDesign/RedDesign`은 팀 기본 설계이고 `HullOverrides`는 호출부호별 ID다. 같은 팀에 지구·화성 설계를 섞을 수도 있다. 자동검사에서 24척 안에 6종을 동시에 배치한다.
- `ShipView`와 GLB 로더는 함종이 아닌 `Definition.Id`를 사용한다. 팀 식별 띠는 Blue/Red를 표시하며 화성 장갑색과 주황색 추진광은 설계 특징이다.
- `tools/build-mars-models.py`는 화성 원본만 생성한다. 노출 트러스·수직 방열판·긴 정밀포·외부 센서·가느다란 중심 선체를 별도로 구성했다. 화성 전함은 상부/하부 각 1기, 호위함도 상부/하부 각 1기다.
- 무장 피벗/고저축/포구/PD/모듈은 JSON에서 제작한다. 주엔진 발광면은 추진 모듈의 후면, RCS 배치는 신규 선체 구획에서 도출하여 FX manifest에 저장한다. 내부 모듈 안내 상자는 Blender에서만 표시하고 게임 메시에서는 제외한다.
- 수작업 편집 후에는 `tools/export-ship-models.py --ship mars_battleship`처럼 내보낸다. 마커가 JSON과 다르면 내보내기를 중단한다. 기본 제작 스크립트는 해당 계통의 원본을 재생성하므로 수작업 수정 뒤에는 export를 사용한다.
- 삼각형 / 움직임별 메시 그룹: 아레스 33,334 / 13, 데이모스 28,256 / 9, 포보스 11,844 / 3. 재질은 12 / 12 / 10종이다. 이 작업에서 FPS를 별도로 재계측하지 않았다.

## AI와 센서 정보

지구 AI의 기존 전열·상호지원 교리는 유지했다. 화성 전함은 약 90km, 호위함은 약 52km를 선호하고 접촉 품질이 떨어지면 거리를 줄인다. 호위함은 개전 시 전함 주변에 분산 배치하여 정밀포격을 지원한다. 요격함은 초기 120초 동안 호위함 근처에서 엄호받고, 반물질이 있으면 대형함 침투를 우선한다. 가까운 단독 강습 상황은 이 대기 규칙의 대상이 아니다.

화성의 정밀 모듈 선택은 **잠금된 표적의 함체 설계도**에서 센서·냉각·주포를 순환하며 고른다. 적 모듈의 실제 체력을 읽고 살아 있는 모듈만 선택하지 않는다. 이동과 표적 선택은 기존 팀 센서망의 접촉/식별/추정 위치를 사용하고 공통 사격통제 오차와 잠금 조건을 따른다. 미탐지 표적에 대한 조준·사격 금지 및 내부 모듈 파괴 상태에 무관한 표적 선택을 검사한다.

데이모스의 ECM은 기존 `SensorNet`에서 12km 안의 아군을 지원한다. 거리에 따라 감소하고 가장 강한 지원 하나만 적용하며 자신의 ECM과도 큰 값 하나만 적용한다. 함체 설계가 아니라 팀으로 아군을 구분한다. 공유 추적과 사격통제 품질을 교란하며, 미사일의 기존 자체 탐색기/디코이 규칙을 새 시스템으로 교체하지 않는다.

## 검증 재현

```powershell
.\tools\check-sim.ps1
.\tools\run.ps1 --model-test
.\tools\run.ps1 --flow-test --seed=1
.\tools\check-design-balance.ps1 -Seeds 1,2,3,4,5,6 -DuelSeeds 1,2 -Duels -Output shots/mars-balance
python tools/analyze-design-balance.py shots/mars-balance
```

모델 검사는 실제 렌더러가 필요하다. `--headless`의 더미 렌더러는 MultiMesh 값을 검증할 수 없다. Blender 연결 후보 검사는 `tools/audit-ship-models.py --root <repo> --ship mars_interceptor --output <folder> --check --render`로 실행한다. AABB 접촉은 거친 후보 검사이며 실제 연결·고각 간섭은 후방/하부/55도 고각 렌더로 함께 확인한다.

배치 검사는 Earth/Earth, Mars/Mars, Earth/Mars, Mars/Earth를 모두 공간 반전과 함께 실행한다. 24척 함대전 외에 전함 20/70/130km, 호위함 12/45/80km, 요격함 4/12/30km에서 각각 1대1을 비교한다. `.ships.csv`는 함체 ID·설계, 피해 기여, 최초 무력화/격침, 생존시간, 주포 발사거리·명중, 일반 미사일/어뢰의 PD·드론 요격을 보존한다. 발사거리 표본이 없는 수동 사격은 평균에서 제외한다. 요격률의 분모는 상대팀이 발사한 일반 미사일 전체이며, 해당 함선만 노린 미사일 수가 아니다. 피해량·격침/무력화는 별도 항목이므로 피해량 우세를 승리로 간주하지 않는다.

국가별 티어 트리·경제·해금·추가 함종·신규 무기 계열은 이번 범위에 포함하지 않았다.

## 2026-10-10 검증 결과

- 전체 Sim **7,198개** 통과(설계/카탈로그/ECM/혼성 편성/화성 AM 175개 포함).
- 배포한 Windows EXE에서 장면 46·모델 1,204·전투 효과 36·자함 음향 116·주변 음향 104, **총 1,506개** 통과. 빌드 경고·오류 0.
- 지구형 기존 20판의 전투 요약이 최적화 2차 기준값과 **20/20 정확히 일치**했다. 이 작업 시작 시점의 지구 JSON·Blender·GLB 9개 SHA-256도 모두 유지했다. 앞선 부품 정렬 작업은 보존했다.
- 화성 원본 3개에서 정적 연결 후보 검사와 포신 축/좌우 미익 정렬 검사 통과. 후방·하부·55° 고각을 포함한 14개 렌더를 확인했다. 원본 및 GLB는 각각 `art/blender/mars_*.blend`, `assets/ships/mars_*.glb`다.

최종 반복 전투는 **192회**다. 24척 함대전 48회(4조합 × 시드 1~6 × 공간 반전)와 동급 1:1 144회(3함종 × 3거리 × 4조합 × 시드 1~2 × 반전)를 25분 제한으로 실행했다. [집계표](balance/mars_20261010/report.md), [세부 집계](balance/mars_20261010/analysis.json), CSV와 검증 로그를 같은 폴더에 저장했다. 같은 시드의 반전은 독립 표본으로 해석하지 않는다.

| 함대 조합 | Blue 승 | Red 승 | 무승부 |
|---|---:|---:|---:|
| 지구 / 지구 | 6 | 6 | 0 |
| 화성 / 화성 | 5 | 4 | 3 |
| 지구 / 화성 | 7 | 2 | 3 |
| 화성 / 지구 | 3 | 7 | 2 |

비대칭 24판은 지구 14승·화성 5승·무승부 5회로 아직 지구 쪽에 치우친 초기값이다. 화성 전함의 평균 주포 발사거리는 100.4km·명중률 84.3%, 화성 호위함은 40.8km·69.8%였다. 지구 호위함은 15.3km·39.0%였고, 이 비대칭 함대 표본에서 지구 전함은 주포를 발사하지 못했다. 장거리 접근/잠금 문제와 승리 판정은 분리해서 봐야 한다. 함대 승리만 보고 지구 전함이 우세하다고 해석하면 안 된다.

거리별 1:1에서 호위함은 12km 지구 6승·무승부 2, 45km 화성 7승·무승부 1, 80km 화성 8승이었다. 요격함은 4km 지구 5승·화성 3승, 12km 화성 8승이었다. 거리별 강점은 구분되며 모든 거리의 승자가 같은 설계는 아니다. 전함 20/130km 및 요격함 30km는 비대칭 8판 모두 무승부여서 화력 수치만으로 최종 밸런스를 단정할 수 없다.

화성 요격함은 최초 실험의 조기 단독 돌진을 줄이도록 120초 엄호 대기를 넣었다. 최종 비대칭 함대전에서 AM 43발을 발사해 17발 명중했지만, 120척 표본 중 82척 격침·평균 전투 가능 시간 311초로 손실이 여전히 높다(지구 12척 격침·1,295초). 격리 실패 77회, 투기 39회이며, 격리용기 체력과 위험 임계값은 양쪽 동일하다. 다음 조정은 접근 경로·호위 이탈 시점·장거리 교착을 우선한다. AI 통계이며 사람의 조작감 평가는 별도로 필요하다.
