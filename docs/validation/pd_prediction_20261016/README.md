# 근접방어포 선행조준과 통계형 명중 — 2026-10-16

## 적용 범위

전함·호위함·요격함 및 파생 함급의 선체 PD에 적용한다. 기존 주포 `FireControl`의 장거리 오차, 미사일 유도, 방어드론의 사격 모델은 바꾸지 않았다. 새 탄환 객체·지연 판정 큐·충돌체를 만들지 않는다. 명중 피해는 기존처럼 즉시 확률 판정하며, **실제 탄환의 비행/충돌을 완전히 재현한 모델은 아니다.**

- 포대마다 현재 표적에 대한 관측 표본과 등속 교차 해 하나만 보관한다. 같은 표적은 15Hz로 갱신하고, 함선 호출부호와 포대 번호로 240Hz 하위 틱 16칸에 갱신 시점을 분산한다. 신규 표적 획득/전환 때에는 즉시 다시 계산한다.
- 포탑 회전·고각·정렬, 현재 표적의 사거리·선체/지형 가림·생존 확인은 240Hz를 유지한다. 갱신 사이에는 관측 위치/속도와 교차시간의 1차 변화로 조준점을 보간한다. 포탑을 다음 관측까지 정지시키지 않는다.
- 관측은 기존 PD의 근접 국소 탐지 조건(센서 전력, 추적 범위, 포각, 가시선)을 통과한 표적에 한정한다. 프로브의 센서망 접촉 요구도 유지한다. 새 조준 해는 이전 표본 이후의 실제 표적 기동을 미리 알지 못한다.
- 발사 방향 자체도 포각과 자기 선체·지형을 통과해야 한다. 현재 표적 거리와 탄의 교차점까지 이동거리 모두 기존 사거리 이내여야 한다. 기존 1.5배 범위의 조기 추적은 사거리를 늘리지 않는다.
- 기존의 단순 횡방향 속도 벌점을 제거한다. 등속 횡단은 선행조준으로 보정하고, 관측 속도의 변화로 얻은 횡방향 가속에 대해서만 `오차 ≈ 0.5 × 가속 × (비행시간 + 표본 나이)²`를 사용한다. 이 오차의 확률 계수는 `1 / (1 + (오차 / 허용척도)²)`다.
- 기본 명중률·크기 계수·센서/무장 출력과 기존 거리 감쇠는 유지하되, 감쇠 거리는 **현재 표적 위치까지가 아니라 탄이 예상 교차점까지 이동하는 거리**로 바꿨다. 접근 미사일은 더 가까이서, 횡단/이탈 표적은 더 멀리서 탄과 만난다.
- 기본 `MuzzleSpeed=6000m/s`, `TrackingErrorMeters=6m`. 후자는 확률 보정의 조정 척도이며 실제 피탄 반경·근접신관 반경이 아니다. 기존 JSON에 없는 필드는 기본값을 쓰므로 함체/모듈/모델 데이터 재생성은 하지 않았다.
- 정렬을 잃거나 사거리/가시선이 끊기면 발사 누적을 비운다. 이미 정렬된 표적 사이에서 바꿔 겨눌 때는 기관포의 미완료 발사 주기를 유지한다. 예광은 기존 시각효과 이벤트를 사용하고, 함선 명중 효과는 실제 현재 실드/장갑 경계에 표시한다.

## 검사와 비교 기준

`PointDefenseChecks`는 실제 교차점(사수 속도 상속, 1e12 좌표 포함), 표본 사이의 숨은 기동 비참조, 정지/등속 표적의 탄속 불이익 없음, 횡가속과 비행시간의 관계, 불가능한 교차, 15Hz 갱신 및 16개 위상 분산, 재획득/리셋, 물리 탄환 미생성, 직렬화·유효성 검사를 포함한다. 기존 근접 고속 통과, 자기 선체/지형 가림, 포각·선회속도 검사를 유지한다.

`DefenseReference`는 최적화 이전의 전체 후보 순회를 유지하고, 새 조준/발사 규칙만 공통 함수를 사용한다. 이 대조 검사는 후보 누락·선택 순서·동일 하위 틱의 격추/피해 일치를 검증하며, 새 조준 수학의 독립적인 증명으로 사용하지 않는다.

기존 단독 호위함 미사일 검사는 4방향 24발에서 이전에도 1발만 격추했다. 새 발사 시점/기동 오차가 이 결과를 0발로 바꾸어, 원래 조건을 포함한 **4방향 × 명중 난수열 위상 4개 = 96발**로 확장했다. 실제 함체·미사일 수치는 바꾸지 않았고, 무방어 전탄 명중 및 방어 시 일부 요격/일부 돌파 조건을 유지한다. 최종 96발 대조에서 이전 5발/변경 후 3발 격추, PD 사격 1,819→1,665발, PD 명중 111→108발이었다. 희귀한 격추의 소표본이므로 이 수치로 전체 방공 밸런스의 개선이나 악화를 단정하지 않는다. 초기 후보의 거리 보정 오류는 수정했고, 6m→12m 보정 척도 시험은 문제를 해결하지 못해 채택하지 않았다.

방공순양함 역할 검사는 같은 12발 공격에서 일반 호위함 3발, 시러스 6발 요격(요격탄 2발 포함)을 확인했다. 방어 계층별 마무리 격추가 달라져 시러스 드론의 격추는 0발이었다. 한 공격에서 모든 계층의 마무리 격추를 동시에 요구하던 조건을 총 방어 효과 비교와 개별 수단 검사로 나눴다. 드론 단독 조건에서는 다른 방어 무장을 끄고 이미 손상된 미사일(남은 HP=드론 1회 피해)을 사용해 실제 마무리 요격을 확인했다. 이 조건을 온전한 미사일의 단독 방어 성능으로 해석하지 않는다. 기존 별도 드론 전투 검사도 유지했다.

## 성능 측정

`measure.ps1`은 같은 실행기·함체 데이터로 보존한 변경 전 어셈블리와 변경 후 어셈블리를 사용한다. 240척 합성 전장, 시작 40km, 준비 15초 후 30초 측정, 심우주/소행성(필드 시드 2), 각 3반복, 실행 순서 AB/BA/AB. 빌드·다른 검사와 겹치지 않게 순차 실행한다. 결과 JSON에 평균/p95/p99/최악 틱, 구간별 시간, 할당량, 최대 탄체 수, 실제 PD 발사량을 남긴다. 새 버전은 조준 해 계산 수도 기록한다.

두 어셈블리는 같은 `ScaleBench` 이름을 가지므로 별도 실행 폴더에서 각각 원래 파일명으로 실행한다. 이름만 바꾼 baseline에 최신 빌드의 `deps.json`을 지정하면 최신 DLL이 로드되는 문제가 실제 첫 측정에서 발생했다. 잘못된 결과는 `invalid-shared-deps/`에 격리했으며 비교에서 제외한다. 수정한 측정기는 변경 전 출력에 `pdSolutions`가 없고 변경 후에만 있는지도 확인하여 잘못된 로드를 즉시 중단한다.

전투 판정이 달라져 전후 발사량·생존 함선·탄체 부하가 달라질 수 있다. 따라서 전체 틱 시간 차이를 선행조준 수학만의 비용으로 단정하지 않는다. 이 측정은 렌더링/음향/네트워크가 없는 시뮬레이션 비용이며 실제 화면 FPS가 아니다. 기존에도 240척 모든 틱의 16.67ms 이하는 보장하지 않았다.

원자료 `before-deep-1.json`과 `after-deep-1.json`은 초기 후보의 60초 측정이다. 최종 반복 비교에는 `DeepSpace-*`, `AsteroidCluster-*`만 사용한다. `salvo-first-candidate.json`은 교차거리 보정 전이며 최종 명중 성능으로 해석하지 않는다.

**게임플레이 변화도 있다.** 측정 구간의 PD 발사량은 심우주 8,994→4,396발, 소행성 7,461→3,783발이다. 선행조준 방향이 포각/선회/탄 이동거리 제한을 통과해야 하므로 현재 위치를 향해 쏘던 때보다 발사 기회가 줄었다. 최대 미사일 수는 각각 434→469발, 393→400발이고, 종료 시 전투 가능 함선은 216→214척, 215→214척이었다. 전투 부하 자체가 달라졌으므로 위 시간 차이를 추가 수학 연산만의 비용으로 해석하지 않는다. 이 45초 합성 전장은 승률·최종 격추율 검증도 아니므로 혼성팀 방공 강도와 직접 조종 감각은 후속 플레이/전투 통계로 확인한다. 이를 숨기기 위해 기존 PD 피해량·연사력·탄속/오차 기본값을 추가 상향하지 않았다.

## 재현

```powershell
dotnet build tests/SimChecks/SimChecks.csproj -c Release --no-restore
dotnet tests/SimChecks/bin/Release/net8.0/SimChecks.dll
dotnet build SpaceFleet.csproj --no-restore
& docs/validation/pd_prediction_20261016/measure.ps1
python docs/validation/pd_prediction_20261016/analyze.py
```

`measure.ps1`의 기본 입력은 `tools/ScaleBench/bin/Release/net8.0/ScaleBench.before.dll`(이 작업 시작 시 보존한 baseline)과 `ScaleBench.dll`이다. 원래 baseline은 단순 재빌드로 재생성되지 않는다. `runner-snapshots.zip`에 두 버전의 어셈블리와 실행 설정을 보존하고, SHA-256을 `runner-hashes.json`에 기록했다. 압축을 `shots/pd-replay/` 같은 별도 폴더에 풀고 현재 게임 빌드의 `GodotSharp.dll`을 각 `before/after` 폴더로 복사하면 다음처럼 개별 재실행할 수 있다(.NET 8 필요).

```powershell
dotnet shots/pd-replay/before/ScaleBench.dll --groups 10 --warmup 15 --seconds 30 --repeats 1 --battlefield DeepSpace --field-seed 2 --output shots/pd-replay/before.json
dotnet shots/pd-replay/after/ScaleBench.dll --groups 10 --warmup 15 --seconds 30 --repeats 1 --battlefield DeepSpace --field-seed 2 --output shots/pd-replay/after.json
```

96발 대조의 별도 계측 소스는 `salvo-probe-source.cs.txt`로 보존했다. 원자료/도구/로그/보존 바이너리의 해시는 `sha256.json`에 있다.
