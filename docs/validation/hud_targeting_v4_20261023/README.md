# HUD / 외부 부위 조준 v4 검증

기준 커밋: `63ffa6bbbbf1aef66f074225c11079f4ebeb03f4`. 작업일: 2026-10-23.

## 구현 범위

- 34개 GLB에서 외부 표면 282개를 추출한 명시적 메타데이터와 BVH. GLB SHA-256 일치 확인. 원본 함선 모델/피해 모듈/무장 수치 변경 없음.
- 주포 하우징, PD 하우징, 엔진 노즐, 실제 외장 방열판·센서 마스트만 후보. 반응로·탄약고·매립 센서·전력망을 직접 선택할 수 없다.
- 최근 잠금 + 관측자에게 보이는 표면 + 사수에게 보이는 표면 + 지형 차폐 + 무장별 오차/실효 투영 크기를 통과해야 선택 가능. 클릭/Y/AI/주포/어뢰의 부위 입력이 공통 판정을 사용한다. 실패하면 선체 사격으로 복귀한다.
- 관측 스냅샷에는 당시 외부 상태/자세만 저장. 지연 계산에도 실제 적의 현재 위치나 모듈 HP를 다시 읽지 않는다. 내부 피해 판정은 기존 DamageRay 경로 유지.
- 접촉: 동일한 비고유 신호. 식별: 실제 GLB. 잠금: 선택 가능한 외부 표면. 신호 소실: 마지막 모형·자세 동결 및 새 부위 선택 중지.
- SubViewport 304×178 하나 재사용, 10Hz 갱신. 그림자/발광/후처리 없음. 모형은 함급 식별로 알려진 표준 외형이며 숨겨진 교체 장비 정보를 공개하지 않는다.
- 개별 포탑 실제 yaw/elevation 방향과 해당 무장 탄속의 선행점. 번호별 파괴 X, 선회/포각/사선/전력/장전/소진 구분. HUD는 Aim/Fire를 호출하지 않는다.
- 무장 1–3/전술 4–7 통합 바, 최소 기동·실드·구조·전력·열·편대 상태. I로 계통·드론·전력·편대·사격 상세. 기존 I 사용자 지정이 있으면 빈 키로 안전하게 신규 키 배정.
- 요격함의 기수 조준·망원·선행점 유지. 어뢰 준비/격리 경고는 우측 표적창 아래로 이동해 중앙 조준선과 통합 바를 피한다.

## 성능 측정 조건

- `baseline.tsv`: 기준 커밋 소스에 동일한 성능 하네스만 넣은 비교. `before_optimization.tsv`: 초기 정밀 레이 전수 검사. `current.tsv`: 최종 구현.
- 동일 시드 91, 24/80척 지구·화성 혼성, 심우주/소행성, 45km, 5초 예열 + 30초 측정, 각 2회. 동일 버전의 두 반복 상태 해시 일치 검사. 전체 전투 종료 승률 시험은 아님.
- 정밀도 상한으로 먼저 제외, 관측 노출은 필요할 때 계산, 같은 사수·표적·정확히 같은 관측 상대좌표의 표면 결과 재사용. 시간 유예나 좌표 반올림 없음.
- `render-*.log`: RTX 2060, Godot 4.7.2 Vulkan Forward+, 1600×900, 최적화 빌드, 표적창 off/on 순차. 24척 기본 편성 및 80척 실제 교체 장비 혼성 편성, 30km 근접 교전 부하. 측정 시간 12초, 동시 벤치마크 실행 없음.

## 범위와 한계

- PD는 현재 독립 피해 모듈이 없다. 외장 조준점은 선택할 수 있지만 별도 PD HP를 새로 만들지 않았고, 기존 선체 관통 경로로 피해가 들어간다.
- 가림 형상은 GLB의 고정 외장/포탑 하우징 기반이다. 움직이는 포신·리코일·PD pitch는 가림 메시에서 제외한다. 미세한 포신 간 가림이나 장비 교체 후 모든 외장 형상 차이를 동적 메시로 재계산하지 않는다.
- 원본 모델을 바꾸면 메타데이터/메시를 다시 생성해야 한다. `dotnet run --project tools/DefSnap -- --external-defs shots/external-defs` 후 `tools/bake-external-targets.py` 실행. 전 모델 GLB 해시 검사를 함께 수행한다.
- 근접 80척 전투의 전체 CPU 비용은 표적창을 꺼도 높았다. 이번 HUD 작업을 80척 60FPS 달성으로 해석하면 안 된다. 실제 측정치를 아래에 기록한다.

## 렌더 측정값

첫 두 측정 구간을 제외한 나머지 구간. CPU 비용은 프레임당 평균, GPU 전용 타이밍은 아니다. 단일 순차 A/B이고 전투 진행량과 머신 부하 변동이 있으므로 FPS 차이를 전부 표적창 비용으로 해석하지 않는다.

| 함선 | 표적창 | FPS 중앙값 | FPS 구간 | 표적창 CPU ms/frame | HUD CPU ms/frame |
|---|---|---:|---:|---:|---:|
| 24 | 끔 | 27.75 | 24.0–35.4 | — | 5.700 |
| 24 | 켬 | 27.35 | 19.4–36.3 | 1.300 | 6.010 |
| 80 | 끔 | 4.40 | 3.0–4.9 | — | 11.911 |
| 80 | 켬 | 4.00 | 3.4–5.9 | 0.811 | 10.956 |

80척은 실제 시뮬레이션 시간이 측정 벽시계보다 느리게 진행됐다. 물리 틱 누적, AI 교전 및 PD 비용이 크다. 기능 검증은 통과했지만 이 부하에서 쾌적한 플레이 성능 검증은 통과하지 못했다.

## 시뮬레이션 틱 측정값

각 조건 두 반복의 범위(ms). 첫 실행 JIT/GC와 시스템 부하 변동을 포함한다. 두 반복의 전투 상태 해시는 조건별로 모두 일치했다.

| 함선 / 전장 | 기준 평균 | 현재 평균 | 기준 p99 | 현재 p99 | 현재 최대 |
|---|---:|---:|---:|---:|---:|
| 24 / 심우주 | 0.93–1.88 | 1.10–1.58 | 2.13–7.17 | 2.51–5.60 | 22.73 |
| 24 / 소행성 | 1.07–1.25 | 1.17–1.23 | 2.06–2.82 | 2.73–2.79 | 6.47 |
| 80 / 심우주 | 2.48–2.56 | 4.06–4.44 | 4.49–4.91 | 7.45–10.27 | 38.11 |
| 80 / 소행성 | 3.61–3.69 | 4.51–4.64 | 10.85–12.72 | 9.51–10.03 | 14.67 |

초기 전수 정밀 가림 검사(`before_optimization.tsv`)의 80척 p99 약 32–39ms에서 최종 약 7.4–10.3ms로 감소했다. 관측/부위 공통 검사가 추가되어 평균 비용과 할당량은 기준보다 늘었다. 첫 실행 최대 38.1ms가 관찰되어 모든 틱이 16.7ms 이하라는 보장은 없다.

전투 상태 해시는 기준과 다르다. 내부 부위/가려진 부위에 대한 AI 정밀 조준을 제한하고, 피해 모듈의 박스 크기 대신 실제 외부 표면의 공통 정밀도 검사를 쓰도록 바꾼 의도된 결과다. 같은 최종 구현·시드의 반복 결정성과 기존 피해/무장 회귀를 별도로 확인했다.
