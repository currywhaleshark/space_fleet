# 작업지시서: 전장 환경 2단계 — 소행성 군집

작성 2026-10-11 · 기준: 이 지시서가 들어간 커밋 · 대상 저장소 `space_fleet/`
선행: `docs/WORKORDER_environment_stage1.md`, 결과 `docs/ENVIRONMENT_stage1.md`

## 0. 목표 한 줄

> 전투 시작 전에 **전장**을 고를 수 있게 하고, 첫 환경 전장으로 **소행성 군집**을 만든다.
> 바위 사이를 AI가 길을 찾아 지나가고, 막힌 사선은 자리를 옮겨 뚫으며, 심우주와 다른 교전 양상이 **숫자로** 드러나야 한다.
> **심우주 섬멸전·기함전의 결과는 한 바이트도 바뀌지 않는다.**

---

## 1. 출발점

### 1.1 1단계에서 이미 된 것

- 장애물 자료: `Obstacles.cs`(구·캡슐 `ObstaclePart`, `Obstacle`, `ObstacleSet.SegmentBlocked/ClosestApproach`, OBB 접촉). double 좌표, 결정적 첫 충돌.
- 연결: 함선 충돌(`ObstacleCollision`), 회피(`ObstacleAvoidance`, 10초 앞 최근접), 센서 가림과 60초 추적 기억(`SensorMemory`), 무기·프로브 차단(`ObstacleWeapons`), 지형 가림 포탑 상태, 지도 윤곽(`MapObstacles`), 3인칭 카메라 당김, 환경 로그(`EnvironmentLog`, `.environment.csv`).
- 첫 장애물: 점령전 거점 구조물 3개(`ZoneStructureShapes`).

### 1.2 1단계가 남긴 과제 (이번에 함께 푼다)

- **갇힘 2건**(점령전 20판): 경로 탐색이 없어서 생긴다. 바위가 수백 개가 되면 훨씬 늘어난다.
- **점령전 틱 비용 +28%**: 장애물 3개인데 충돌 42→85 µs, 센서 3.5→16 µs. 장애물 질의가 경계 구 전수 검사라서, 바위 수백 개에서는 그대로 쓸 수 없다.
- **막힌 사선에서 AI가 그냥 기다린다**: 점령전에서 레일건 253발·미사일 261발이 차단됐다. 자동 사격은 막히면 보류하는데, 자리를 옮겨 사선을 확보하는 행동이 없다. 바위가 많으면 전투가 멈춘다.
- 수동 조종 시 카메라·엄폐 체감은 미확인이다(이번에도 사람 확인 항목).

## 2. 설계 결정 (값은 제안값. 측정 후 조정하고 근거를 보고)

### 2.1 전장 선택

- `enum Battlefield { DeepSpace, AsteroidCluster }`, `BattleConfig.Battlefield`(기본 `DeepSpace`), `BattleConfig.FieldSeed`(기본 1).
  - 전투 시드(`Seed`)와 배치 시드(`FieldSeed`)를 분리한다. 같은 지형에서 여러 전투, 같은 전투 시드로 여러 지형을 돌릴 수 있게.
- 출격 화면: 전투 목표 선택처럼 **전장** 선택 버튼(순환). 시작 문구에 전장 이름.
- 명령줄: `--battlefield=AsteroidCluster --field-seed=3`. `BattleBatch`/`battle-batch.ps1`에 `-Battlefield`, `-FieldSeeds`.
- 모든 전투 목표(섬멸·기함·점령)와 조합된다.

### 2.2 배치 (생성 규칙)

전장 중심 `C` = 두 함대 출발점의 중점(기본 `(0, 0, -75 km)`).

- **군집 영역:** `C` 중심 타원체, 반축 X 70 km · Y 25 km · Z 35 km. 함대 출발점은 중심에서 Z ±75 km라 영역 밖에서 약 40 km를 접근한 뒤 군집에 들어간다.
- **바위 크기 3층**(모두 충돌·가림 대상):
  - 대형 반지름 2~5 km: 6~10쌍. 전함(1.2 km)을 통째로 숨긴다.
  - 중형 0.6~2 km: 30~50쌍.
  - 소형 150~600 m: 60~100쌍. 요격함(30 m)·호위함(300 m) 엄폐용.
- **모양:** 바위 하나 = 구 1~4개 묶음(울퉁불퉁한 덩어리). 캡슐은 쓰지 않아도 된다.
- **점대칭:** 절반만 생성하고 나머지는 `p → 2C − p`로 만든다(자세도 대칭). 정·역배치 비교가 공정하려면 필수다. 중심을 가로지르는 바위는 대칭 쌍이 겹치지 않게 처리한다.
- **비워 둘 곳:**
  - 각 함대 출발점 반경 25 km(출발 대형 전체가 들어가는지 확인)
  - 점령전 거점 중심 반경 7 km(구조물 + 대기점 4 km + 여유). 거점은 군집 안에 있어도 된다. 바위가 점령 반경(12 km) 안쪽 가장자리를 둘러싸는 것은 허용.
  - 바위끼리는 표면 간격 최소 300 m(겹치거나 빈틈 없는 벽 방지).
- **통행 보장:** 각 출발점 → 군집 중심, 각 출발점 → 각 거점 경로가 전함 기준(반지름 + 여유)으로 **존재**해야 한다. 3차의 경로 탐색기로 생성 직후 검사하고, 실패하면 해당 배치 시드를 재생성(결정적으로)한다. 재생성 횟수를 기록한다.
- 결정성: 같은 `FieldSeed` → 같은 바위 목록(바이트 단위). 생성은 `src/Sim`(서버에서도 돈다).

### 2.3 그림

- 바위 외형은 같은 시드로 만든 일그러진 구(`ZoneStructures.Asteroid` 방식 재사용 가능). **보이는 바위를 함선이 뚫고 지나가면 안 된다**:
  - 보이는 면이 충돌 구 묶음 밖으로 나오는 양을 반지름의 3% 이하로 제한하고 검사로 확인한다.
  - 반대로 충돌 구가 보이는 면보다 크게 튀어나오는 곳(빈 공간에 부딪힘)도 측정해 보고한다.
- 메시는 형태 변주 8~12종을 공유하고 크기·회전만 바꾼다(인스턴싱). 재질 하나.
- 충돌 없는 장식 자갈은 반지름 20 m 이하만 허용(먼지 취급). 넣지 않아도 된다.
- 가독성: 어두운 바위가 별 배경에서 실루엣이 보이는지 스크린샷으로 확인. 필요하면 은은한 가장자리 광. 플레이어가 엄폐를 쓰려면 바위가 보여야 한다.

## 3. 단계별 작업

각 차수는 별도 커밋. **차수마다 심우주 섬멸전·기함전 40판 요약 바이트 일치**를 확인한다.

### 1차: 전장 선택과 생성기 (심우주 결과 불변)

- 2.1, 2.2의 생성 규칙(통행 보장 검사는 3차 경로 탐색기가 생긴 뒤 연결. 1차에서는 간격 규칙만).
- 2.3의 그림과 지도 표시(`MapObstacles`가 바위 수백 개에서 화면을 덮지 않게: 지도 확대 수준에 따라 소형 생략 등).
- 확인 장면: `--battlefield=AsteroidCluster --show-obstacles`, 갤러리 또는 전용 미리보기로 바위 형태 변주.
- 검사: 같은 시드 바이트 일치, 점대칭, 출발점·거점 비움, 최소 간격, 외형-충돌 오차 3%, 영역 안 개수 범위.
- 이 차수에서 바위 전장 전투는 돌기만 하면 된다(AI는 1단계 그대로).

### 2차: 공간 분할 (결과 불변)

- `ObstacleSet` 질의(`SegmentBlocked`, `ClosestApproach`, 충돌 후보)를 **정적 BVH**(또는 격자)로 바꾼다. 장애물이 고정이므로 전투 시작 때 한 번 만든다.
- **첫 충돌 결정성 유지:** 전수 검사와 같은 결과(같은 장애물·부품·위치)를 내야 한다. 성능 2.5차처럼 기존 알고리즘과 직접 비교하는 검사를 둔다(무작위 선분 수천 개, 원거리 좌표 포함).
- 결과: 1단계 점령전(심우주 전장 + 구조물) 20판 요약이 **바이트 일치**해야 한다.
- 측정: 점령전과 바위 전장의 센서·충돌·회피 구간 µs/틱 전후.

### 3차: 경로 탐색

- **정적 길찾기 격자:** 전투 시작 때 군집 영역을 거친 3차원 격자(제안 1.5~2 km 칸)로 나누고, 함급별 반지름 + 여유로 부풀린 점유를 계산한다(전함·호위함·요격함 3종).
- **A\*** (결정적 동점 처리), 결과 경로는 `SegmentBlocked`(부풀림 포함)로 줄여 웨이포인트 몇 개로 만든다.
- 사용하는 곳: 함대 명령의 이동 목표(공격 접근, 점령 대기점, 호위 위치, 요격함 임무 목적지, 귀환). 목표까지 직선이 열려 있으면 경로 탐색을 하지 않는다(심우주·빈 공간 비용 0).
- 국소 회피(`ObstacleAvoidance`, 함선끼리 회피)는 그대로 그 위에 얹는다.
- 편대: 대장이 경로를 따르고, 대원은 대형 간격을 좁은 통로에서 줄인다(필요하면 일렬). 대형 오프셋 지점이 바위 안이면 가장 가까운 빈 곳으로.
- 재계획: 목표가 일정 거리(제안 5 km) 이상 바뀌거나 갇힘 감지 시. 계획 빈도와 비용을 기록한다.
- **관측 규칙:** 목표가 적이면 경로 목적지는 센서 추정 위치나 추적 기억 예측 위치뿐이다. 실제 위치를 읽지 않는다.
- 2.2의 **통행 보장 검사**를 이 탐색기로 연결한다.
- 점령전(심우주 전장)도 구조물 때문에 결과가 바뀔 수 있다. 섬멸전·기함전 심우주는 직선이 항상 열려 있으므로 바이트 일치를 유지해야 한다.
- 검사: 오목한 바위 무리 우회, 막다른 곳 탈출, 대형 축소·복원, 경로 결정성, 숨은 적 위치 미사용, 갇힘 0을 목표로 바위 전장 기록.

### 4차: 사선 확보 기동

- AI 함선이 현재 표적을 **지형 가림**으로 일정 시간(제안 5초) 이상 못 쏘면, 주변 후보 지점에서 사선이 열리는 곳을 찾아 이동한다.
  - 후보: 현재 위치 둘레의 몇 개 방향 × 몇 개 거리(제안 1~4 km). 후보마다 (후보 → 표적 추정 위치) `SegmentBlocked`와 경로 존재를 검사한다.
  - 선택 기준: 이동 거리 짧음, 함종별 교전 거리 유지, 현재 명령 범위 안(점령 대기 중이면 점령 반경 안, 호위 중이면 호위 거리 안).
  - 전함은 큰 이동보다 짧은 횡이동을 선호한다. 요격함은 표적 쪽으로 돌아 들어가도 된다.
- 미사일: 우회 유도는 이번에도 하지 않는다. 발사 보류가 길면 같은 사선 확보 기동으로 해결한다.
- 기록: 사선 확보 기동 횟수, 기동 후 사격 재개까지 시간, 실패 횟수.
- 검사: 바위 뒤 표적에 대해 측면으로 돌아 사격 재개, 명령 범위 밖으로 안 나감, 표적이 기억 상태면 기동하지 않음(쏠 수 없으므로).

### 5차: 엄폐를 이용한 접근 (요격함 강습·정찰 한정)

4차까지의 측정을 보고에 포함한 뒤 진행한다.

- **노출도:** 지점 하나에 대해, **아군이 알고 있는** 적 함선(추적 또는 기억 예측 위치)에서 그 지점까지 시선이 열린 수(센서 강도 가중 가능). 관측하지 못한 적은 계산에 넣지 않는다.
- 요격함 강습·침투 경로의 A\* 비용에 노출도 항을 더한다(가중치는 제안하고 측정). 다른 함종은 이번에 쓰지 않는다.
- 기록: 강습 경로의 평균 노출도, 강습 도달률, 반물질 어뢰 명중, 도달 전 손실.
- 비교: 노출도 항 끈 것/켠 것 같은 시드 20판.

### 6차: 화면·HUD·성능 마무리

- 지도: 바위가 많아도 함선·거점·표적이 묻히지 않게(소형 생략, 높이 단서 유지).
- 전술 레이더: 근거리 큰 바위만 윤곽.
- 충돌 경고: 조종 중인 함선이 일정 시간 안에 바위에 닿을 예측이면 진행 방향에 경고 표시(글자 없음).
- 3인칭 카메라: 바위 사이에서의 당김이 과하게 흔들리지 않는지(빠른 연속 당김·복귀) 확인.
- 렌더 성능: 바위 수·인스턴싱·그림자. Debug ×4 자동 관전 FPS.
- 스크린샷: 군집 원경, 바위 사이 함대, 바위 뒤 기억 표적, 지도, 충돌 경고.

## 4. 측정 — "전장이 전술을 바꾸는가"

**비교 묶음:** 전투 목표 3종 × {심우주, 소행성(배치 시드 1·2·3)} × 시드 1~10 × 정/역배치.
(심우주 60판 + 소행성 180판. 시간이 많이 들면 배치 시드 1개로 먼저 보고하고 나머지는 이어서.)

지표(전장별 표):

- 승패·무승부, **정/역배치 승률 차이**(지형 공정성)
- 판정 시각 중앙값, 첫 접촉·첫 피해 시각, 교전 국면 비율
- 차단된 레일건·미사일·어뢰·프로브, 잠금 소실 횟수·시간, 기억 재획득
- 함선-바위 충돌 횟수·피해, 갇힘, 경로 재계획, 사선 확보 기동(성공/실패)
- 함종별 생존율, 요격함 강습 도달률과 반물질 어뢰 명중
- 성능: 구간별 µs/틱(Release 단독), Debug ×4 게임 FPS

판단 기준(보고에서 답한다):

- 소행성 전장에서 교전 거리가 짧아지고(저격·미사일 국면 감소, 난전 증가) 요격함 강습 성공이 늘었는가? 반대라면 왜인가?
- 정/역배치 승률 차이가 심우주보다 커졌는가? 커졌다면 배치 생성 문제인지 확인.
- 한 함종이 일방적으로 강해지거나 무력해졌는가?

## 5. 유지할 것

- **심우주 섬멸전·기함전 40판 바이트 일치**(모든 차수).
- 1단계 점령전(심우주) 20판은 2차까지 바이트 일치. 3차부터 바뀌면 전후 표.
- 결정성, 층 분리(생성기·경로 탐색 모두 `src/Sim`, Godot 노드 없음), 240 Hz 연속 판정, double 좌표.
- **관측하지 않은 정보 금지**: 경로 목적지, 사선 확보, 노출도 모두 센서·기억 값만.
- 성능:
  - 심우주 단독 µs/틱 ±1%(1단계와 같은 교차 측정법).
  - 소행성 전장 Release 평균 틱이 같은 목표 심우주의 1.5배 이하, 난전 p99 1 ms 이하.
  - Debug ×4 게임 자동 관전 10분 무렵 FPS 30 이상.
  - 못 맞추면 구간별 표와 원인을 보고하고 사용자 판단을 받는다.
