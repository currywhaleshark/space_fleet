# 부품·전술 모듈 분리와 단축키 설정 — 2026-10-22

## 구현

메인 메뉴에 **단축키 설정**을 추가했다. 입력 대기, Esc 취소, 중복/예약 키 안내, 기본값 복원, 저장/취소를 제공한다. 저장 전에는 실제 조작을 바꾸지 않는다. 저장한 키는 입력 맵과 HUD·도움말에 반영되며, `user://keybindings.json`에 별도 저장한다. 키 파일이 손상되면 기본값으로 실행하고 원본을 보존한다. 마우스 조작과 Esc·Alt·지도 Shift/Home은 고정이다.

기본 배치는 무장 1/2/3, 활성 전술 능력 4/5/6/7, 전력 F, 사격 B, 편대 N, 드론 K, 응급복구 L이다. 전술 키는 무기 선택을 바꾸지 않는다. 라디얼·지도·도움말·편성표·일시정지·관전·결과·조종 불가 상태와 키 반복을 차단한다. 조종권을 넘겨도 재사용 대기와 사용 횟수는 각 함선에 남는다.

기존 실드·센서·ECM·드론 확장은 `data/parts/`의 보조 부품으로 이동했다. 원래 베이·전력망·효과·질량·손상 구획과 드론 탄약 규칙을 유지한다. 새 장착 경로는 `Components.AuxiliaryParts`이며 구형 `Equipment`는 호환 이관한다. 외부 부품은 선체에서 직접 선택하고, 발전기·실드·보조 부품은 내부 부품 행에서 선택한다.

전술 모듈은 별도 내부 베이에 장착한다. 함체별 빈 구획을 검사해 전함 최대 6, 중형함 최대 5, 요격함 최대 4베이를 배치하며 기존 고정 모듈과 보조 부품 베이를 움직이지 않는다. 중형/소형 규격, 카테고리, 티어, 전력·폐열·질량 예산과 중복 제한을 검증한다. 베이는 실제 피해 레이에 참여하고 각 전력망에 연결된다. 패시브는 단축키를 차지하지 않는다.

| 모듈 | 종류 | 첫 구현 효과 |
|---|---|---|
| 예비 복구 자재 | 패시브 | 시작 시 키트 +2, 파괴 후 복구로 재보급되지 않음 |
| 복구 통제기 | 패시브 | 작업 시간 25% 단축, 피격 대기·복구 상한 유지 |
| 발전기 과부하 | 활성 | 8초간 가용 발전 +25%, 추가 열, 재사용 90초 |
| 긴급 열 배출 | 활성 | 열용량의 최대 30% 즉시 배출, 6초 IR 노출, 재사용 100초 |
| 확장 방공 통제기 | 패시브 | 실제 관측 궤적으로 위협 우선순위·PD/드론 배정 개선; 무장 사거리 유지 |
| 미사일 신속 장전기 | 패시브 | 재장전 시간 15% 단축, 탄수·탄두·유도 유지 |
| 집중 탐색 | 활성 | 10초간 기수 ±35° 관측 강화, 다른 방향 약화·노출 증가, 재사용 60초 |
| 단거리 초공간 도약 | 활성 | 준비 3초, 최대 10km, 속도·자세 유지, 성공 후 재사용 120초 |

도약은 함체 전체의 도착 공간을 준비 전/후 검사한다. 소행성·정거장·잔해·다른 함선과 겹치면 취소한다. 준비 중 무장을 차단하고 장치/발전/전력망 손상 때 취소한다. 실패에는 탄약/재사용 대기를 소모하지 않는다. 기수 방향 기본 도약은 준비 중 관성 이동을 반영하고, API는 명시적 목적지도 받는다. 성공 후 센서·AI 경로를 갱신한다. 열 배출은 실제 냉각 구획의 외장 표면, 도약 준비는 함체 주변의 진행하는 고리로 표현한다.

AI는 역할별 최대 두 모듈을 선택하며 열·전력 수요·관측 표적·실제로 탐지한 접근 미사일에 따라 사용한다. 도약은 위협을 받는 심한 구조 손상 함선의 이탈에 사용한다. 티어 매칭에서는 무장 편성/맞춤이 끝난 뒤 설치해 `Components` 교체로 모듈이 사라지지 않도록 했다. 새 장비 선택은 기존 함급 추첨 RNG를 소비하지 않는다. 플레이어 프리셋에는 자동으로 추가하지 않는다.

격납고의 전술 목록은 베이 선택, 장착/연구 여부, 규격·수치 툴팁, 전후 비교 확인창, 활성 키 순서를 제공한다. 확인 전에는 RP와 저장 세팅을 바꾸지 않는다. `hangar.json` v6는 v1–v5의 보유 함급·RP·연구·세 프리셋·개별 편대원·원래 베이 위치를 유지한다. 불명확한 중복 또는 손상 데이터는 자동 삭제하지 않고 저장을 막아 원본을 보존한다. 기존 임시 파일/백업 저장 경로를 재사용한다.

## 검증

- 게임 C# 빌드: 경고 0, 오류 0. SimChecks의 기존 nullable 경고 6개는 남아 있다.
- 신규 전술 검사 610개: 모든 34함급의 호환 장착/실제 피해 구획/출격 스냅샷, 활성 시간·대기·파괴·복구, 과열, 키트 비재보급, 센서 방향, 탄약 불변, 도약 장애물·관성·취소, v1–v5 이관과 손상 저장 보호.
- 관련 회귀: 편대/저장/매칭 799개, 연구/이관/보상 558개, 티어/카탈로그 682개, 엔진/센서/실드 3,379개 통과. AI 무장/매칭 143개에서 60개 편성의 결정성을 확인했고 양팀 전력 점수 차이는 평균 0.03%, 최대 0.19%였다.
- Godot 단축키/전술 입력 23개, 격납고·확인/취소·연구·스킬 순서·출격/인계 165개, 기존 무장·망원·응급복구 입력 366개 통과.
- 기존 전체 SimChecks를 실행했다. 마지막 저장 검사에서 구형 `Equipment` 필드에 쓰던 기대값이 새 부품 경로와 달라 수정했고, 해당 검사 이후의 관련 묶음을 별도로 재실행했다. 연속된 전체 검사 1회가 모두 통과했다고 해석하지 않는다. 기존 기본 전투 요약은 Blue 승리, 439.400초를 유지했다.
- 24/80척 × 심우주/소행성 × 섬멸/기함/점령 = 12조건을 각각 두 번, 60Hz로 60초 실행했다. 전투 요약·함선 상태·모듈 체력·스킬 상태 해시가 반복에서 모두 일치했다. 원자료 `battle-smoke.tsv`의 시간 측정은 다른 검사와 겹쳤으므로 성능 비교에는 사용하지 않는다.
- 격납고와 설정: 실제 Godot 렌더 1280×720 / 1600×900. 전투 HUD는 전함·요격함, 두 해상도, 글자 100%/130%에서 스킬과 무장 선택·계기판·AM·리본·중요 알림의 경계 비중첩 검사. 리본은 공간이 부족할 때 기존 상단 위치로 이동한다. 망원 130%에서는 별도로 배율·조작 안내·AM 패널과 리본의 비중첩을 검사하고 실제 화면을 확인했다. 촬영의 리본 수치는 배치 검증용 합성 사건이며 실제 전과 통계가 아니다.
- 표적 선택 입력 검사는 실제 렌더러에서 실행해야 한다. 이번 Godot headless 모드는 `--resolution`에도 64×64 뷰포트를 반환하여 화면 밖 표적 선택 검사가 실패했으며, 1600×900 Vulkan 렌더에서는 366개를 통과했다.

## 초기 조합 비교

24척 지구·화성 혼성, 45km 정면 출발, 심우주 섬멸전. 각 팀에 같은 장착 정책을 적용하고 시드 91/92를 비교했다. `baseline`은 전술 모듈 없음, `support`는 자재+복구 통제기, `role`은 AI 역할별 두 모듈이다. 여섯 판 모두 실제 판정까지 진행했다. 피해·격침/무력화·요격·복구·평균 생존시간·스킬 사용을 `balance.tsv`에 기록했다.

|---|---|---|
| 기본 | Red 승 / 105.167초 | Red 승 / 140.033초 |

역할형의 활성 사용은 판당 21회였다. 장비의 추가 질량·내부 피격 구획도 전투 경로를 바꾸므로 승패 차이를 특정 스킬 하나의 효과로 해석하지 않는다. 두 시드는 통계적인 승률·진영 우열 결론에 부족하다. 이 단계에서는 위력·쿨다운 수치를 재조정하지 않았다. 섬멸전은 기존 규칙상 기함 상실과 전력 50% 이하의 복합 패배 조건도 적용한다.

## 단독 틱 측정

80척 혼성, 소행성 점령전, 시드 91, 45km 출발. 5초 워밍업 뒤 30초(1,800틱)를 계측했다. 다른 게임/검사 없이 기본→장착→장착→기본 순서로 실행했다. Debug SimChecks 결과이며 렌더 FPS와 다르다. `tick-comparison.tsv`에 원자료가 있다.

| 세팅 | 평균 ms | p99 ms | 최대 ms | 할당 bytes/tick |
|---|---:|---:|---:|---:|
| 기본 1 | 16.368 | 85.582 | 119.808 | 58,183 |
| 역할형 1 | 16.856 | 73.998 | 116.903 | 57,994 |
| 역할형 2 | 17.019 | 89.271 | 109.449 | 58,002 |
| 기본 2 | 16.372 | 74.817 | 99.256 | 58,182 |

평균 증가는 약 3.0–4.0%. 역할형은 160개 모듈을 실제 장착하므로 스킬로 달라진 전투 계산까지 포함한다. 기본 상태부터 p99가 60Hz 예산을 넘는다. 이 측정만으로 80척의 프레임 유지나 전체 전투 최적화 완료를 주장하지 않는다. 방공 위협 순위는 PD 단계별 캐시를 사용하고 모듈 상태 배열은 함선 생성 시 한 번 구성한다.

## 실제 렌더 측정

RTX 2060 / Godot 4.7.2 Forward+ / 1600×900 Debug / 배속 ×1, 76척·전술 모듈 91개인 매칭 전초 구간을 별도로 실행했다. 3.1초부터 12초 동안 실제 벽시계 프레임을 측정했고 고정 FPS 인자는 쓰지 않았다. 1초 구간 FPS는 심우주 27.3–33.3, 소행성 27.8–33.4였다. 초기 구간 이후는 약 32–33FPS였다. HUD 그리기 평균은 프레임당 약 5.5–8.5ms, 함선 표시 약 2.7–3.5ms였다. 상세는 `render-perf-DeepSpace.log`, `render-perf-AsteroidCluster.log`.

이는 초기 매칭 화면의 실행/부하 확인이며 교전 밀집 구간, 릴리스 EXE, 전후 동일 화면의 FPS 비교는 아니다. 기존 HUD/렌더 비용도 포함하므로 이 수치를 전술 UI 단독 비용으로 해석하지 않는다.

## 재현

```powershell
dotnet build SpaceFleet.csproj --no-restore
dotnet build tests/SimChecks/SimChecks.csproj --no-restore -o shots/tactical-tests/bin -p:UseAppHost=false
dotnet shots/tactical-tests/bin/SimChecks.dll --tactical
dotnet shots/tactical-tests/bin/SimChecks.dll --tactical-regression
dotnet shots/tactical-tests/bin/SimChecks.dll --fit-scores
dotnet shots/tactical-tests/bin/SimChecks.dll --tactical-trials
dotnet shots/tactical-tests/bin/SimChecks.dll --tactical-balance
dotnet shots/tactical-tests/bin/SimChecks.dll --tactical-perf
```

Godot 사용자 인자: `--tactical-input-test`, `--hangar-test`, `--weapon-input-test`. 화면 검증은 `--shot=절대경로 --menu=keys` 또는 `--menu=hangar --hangar-hull=battleship --tactical-fit=generator-overload,heat-vent,focus-search,short-jump --tactical-picker`를 사용한다. 도약은 T3부터 사용할 수 있다. 요격함 촬영은 `--hangar-hull=interceptor_t3`를 사용하고, 중형 베이 두 곳에 과부하/도약을 먼저 배치해야 하므로 `generator-overload,short-jump,heat-vent,focus-search` 순서를 쓴다. `--tactical-preview --menu=title --advance=3.1 --hud-text=130`은 전투 배치를 검증하며 `--tactical-scope`는 망원/AM 전체 패널을 연다. `--shot`·검사 모드는 격리된 진행 데이터를 사용한다.
