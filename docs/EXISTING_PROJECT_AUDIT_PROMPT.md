# 기존 프로젝트의 UI/UX 슬롭 검토 지시문

프로젝트의 기존 기능과 콘텐츠를 보존하면서 UI/UX를 검토하고 필요하면 수정하라.

1. 저장소의 `AGENTS.md`와 `docs/ANTI_SLOP_UI_UX_STANDARD.md`를 읽는다. 존재하지 않으면 이번 요청에 첨부된 동일 문서를 준수한다.
2. 현재 서비스에서 사용자 유형, 핵심 과업, 주요 화면, 주요 조작, 프로젝트의 시각적 정체성을 파악한다.
3. 화면별로 AI 슬롭 징후를 찾아 `위치 / 구체적 증상 / 왜 문제가 되는가 / 권장 조치 / 우선순위` 순서로 기록한다. 추상적으로 'AI 같다'고 평가하지 마라.
4. 특히 무근거한 그라데이션·유리 패널·과한 라운딩, 모든 요소의 카드화, 장식용 영문 메타텍스트와 배지, 애매한 버튼 문구, 가짜 통계·상태, 의미 없는 애니메이션, 모바일 부적합, 부족한 완료·오류·복구 피드백을 점검한다.
5. 사용자의 행동을 방해하는 문제(P0/P1)를 먼저 교정하고, 의미 없는 시각 장식(P2)을 선택적으로 줄인다. 범위 밖 전면 개편은 금지한다.
6. 고유한 게임 HUD, 교육용 안내, 실제 데이터 시각화, 프로젝트 정체성에 기여하는 표현은 보존하거나 강화한다. '슬롭 방지'를 단순한 무채색 미니멀리즘으로 오해하지 마라.
7. 작업 후 대표 화면과 모바일 화면에서 기능·상태·정보 위계·접근성을 확인한다. 실행하지 못한 항목은 검증했다고 주장하지 마라.
8. 변경 전후 차이와 그 이유를 사용자의 목표에 근거하여 보고한다.

이 작업의 목표는 'AI가 만든 티를 지우기'가 아니라, **용도에 근거하지 않은 디자인을 제거하고 실제 사용성과 프로젝트 고유의 성격을 강화하는 것**이다.
