# 시안 윤곽 맞춤 (A: 윤곽 측정 + B: 데이터 제약 완화)

2026-10-18~19. 사용자 결정: 26함급 롤아웃 뒤에도 시안과 실루엣이 달라서 **A(시안 윤곽 추적·일치도 측정)와 B(데이터 제약 완화)** 를 함께 진행한다. 작업 위치는 별도 워크트리 `space_fleet-models`, 브랜치 `models/silhouette-match`(기준 `a53b1a4`).

## 측정 방법 (A)

- `tools/reference_views.json`: 시안 보드에서 **정투영(위·옆) 뷰가 있는 16함급, 28개 뷰**의 자르기 상자와 기수 방향.
- `tools/reference_views.py`: 배경 거리와 국소 질감으로 실루엣을 뽑는다. 부드러운 그림자, 자르기 경계에 걸린 이웃 그림, 글자를 제외하고 구멍을 채운다.
- `tools/silhouette-export.py`(Blender): 모델의 위(z, x)·옆(z, -y) 투영 삼각형을 `sil-*/<id>.npz`로 저장한다.
- `tools/silhouette-match.py`: 두 실루엣을 같은 길이로 맞추고, 세로 위치를 찾아 IoU를 잰다. 구간별 미터 단위 폭·높이 표(`<id>-<view>.txt`)와 겹침 그림(`<id>-<view>.png`: 빨강 시안, 파랑 모델, 흰색 공통)을 남긴다. 시안처럼 모델 윤곽의 구멍도 채운다(트러스 등).
- `tools/silhouette-table.py`: 위 표의 요약(반폭, 아래·위 끝). `tools/iterate-silhouettes.sh`: 작성 → 적용 → 빌드 → 투영 → 측정.
- `tools/section-areas.py`: 피해 구획 상자의 합집합을 정면·측면·윗면에서 본 피탄 면적을 기준 커밋과 비교한다.

- 팔케의 시안 위 뷰는 처음 기수를 아래로 잡았으나, 꼬리날개와 엔진 발광이 아래쪽에 있어 **기수 위**로 바로잡았다(3/4 뷰의 발광 방향은 허셜과 마찬가지로 위 뷰와 맞지 않는다). 그 결과 엔진 포드는 앞쪽에 있고, 배기구가 함 중앙에서 끝난다.
- **전함의 옆 뷰가 낮은 이유**: 포탑 회전축(`Tier growth preserves gun pivots`)을 옮기지 않았다. 또 후방 사격선을 막지 않도록, 포탑 뒤 함미 구조물을 포신 높이 아래로 제한했다. 특히 화성 전함은 거리를 벌리며 후방으로 쏘는 운용이므로, 시안의 깊은 하부 선체와 큰 함미 프레임 높이를 일부만 반영했다.
- **3/4 뷰만 있는 12함급**(T4 8척, T5 순양함 4척)은 수치로 비교할 수 없어 이번 범위에서 뺐다. 정확히 맞추려면 위·옆 정투영 시안이 필요하다.

## 완화한 제약 (B)

- **T3 순양함 모듈 계약**(`CruiserChecks`): 모듈 ID·크기·성능은 기본 호위함과 같아야 하지만, **위치는 함체 형상에 맞게 옮길 수 있다**. 화성 순양함은 센서탑을 시안처럼 낮췄고, 좁아진 앞쪽 선체에 맞춰 버스·기동추진기·탄약고를 안쪽으로 옮겼다. 다뉴브·시러스는 방열판과 센서탑 위치를, 다뉴브는 엔진 간격을 바꿨다.
- **엔진 표시 크기**(`blockout.engineScale`): 다뉴브 1.35, 시러스 1.2, 히말라야 2.2, 네르갈 3.4. 엔진 모듈 크기는 그대로다.
- **소형함 엔진 검사**(`TierBranchChecks`): x ±3 m 밖 조건 대신 "엔진 피해 상자가 엔진 나셀 구획 안에 있고 중심선 밖" 조건을 쓴다(스키아파렐리의 동체 밀착 엔진).
- **모델 축 검사**(`ShipModelChecks`): 폴라리스는 시안대로 가로 센서 날개가 함 길이보다 넓다(44 m 대 30 m). 바로 위의 "Z 크기 = 함 길이 ±15%" 검사가 축을 이미 고정하므로, 긴 축 조건은 Z가 높이(Y)보다 긴지만 본다. 실패 메시지에 함선 ID와 경계를 넣었다.
- 그대로 둔 것: **포탑 회전축과 포탑 하우징 크기**(위 검사와 주포 데이터), 모듈 크기, 장갑·HP·성능·연구 값.

## 형상 변경 중 함께 바로잡은 것

- PD 시험 사격선과 출발점은 함체 구획 상자 밖에 있어야 한다. 그래서 데이모스·칸도르·네르갈·폴라리스의 PD 위치나 해당 구획 경계를 조정했다. 칸도르는 높아진 함미를 별도 구획으로 나눴다. 폴라리스 하부 PD는 하부 포드에 가려 쏘지 못했는데, 이 문제는 지난 세션에서 다시 그린 형상에서 생겼다. 이 PD를 함체 꼬리 아래로 옮겼다.
- 데이모스 PD는 SimChecks의 꼬리날개 가림 시험(`PointDefenseChecks.CheckHullOcclusion`)에 쓰이므로 꼬리날개 앞(z 7)에 둔다.
- 허셜 탐사정은 엔진 나셀 바깥면에서, 팔케 탐사정은 엔진 포드 뒤 날개 위에서 옆으로 사출한다(렌즈가 나셀에 가리지 않게).
- 다뉴브 하부 용골과 함미 상부 갑판은 포탑 포신 높이를 넘지 않는다. 히말라야는 하부 포탑의 후방 사격선 때문에 추가 하부 용골을 넣지 않았다.

## 피탄 면적 변화 (`section-areas.json`)

시안이 더 넓고 두꺼운 함선은 피해 구획 상자도 커진다. 정면 면적 기준 주요 변화는 다음과 같다.

- 크게 늘어난 함급:
  - 히말라야 +64%, 네르갈 +79%
  - 다뉴브 +46%, 제피르 +52%
  - 알타이르 +126%, 데이모스 +109%, 팔케 +76%, 허셜 +62%, 해동청 +73%, 폴라리스 +92%
- 줄어든 함급: 칸도르 −20%, 크리세 −17%
- 윗면 면적: 시러스 +52%, 히말라야 +73%, 네르갈 +77%

**같은 성능이어도 명중률과 전투 결과가 달라진다.** 혼성 편대 전투의 전후 비교와 균형 조정은 하지 않았다.

## 검증

- `audit/`: 바뀐 16함급의 Blender 원본 감사 통과. 마커 좌표, 엔진 노즐·프로브 렌즈 가시성, 미사일 출구, 미익 대칭, 부품 연결을 확인했다.
- `model-test.log`: 실제 렌더러 모델 검사 **10,420개** 통과(롤아웃 때와 같은 개수). `game-build.log` 빌드 성공.
- `sim-all.log`: 전체 SimChecks **63묶음 / 5,678,997개** 통과. 롤아웃 기준(`a53b1a4`의 `reference_models_20261018/sim-all.log`)과 묶음·검사 수가 같다. 출력이 다른 줄은 시러스 통계 2줄뿐이다.
  - 방어 역할 시험: AA 10/12 → 9/12 요격, 피격 2 → 3. 드론과 대응미사일은 같다.
  - 고밀도 레이저 요격: 28/192 → 31/192.
  - 처음에는 시러스 PD를 갑판 높이(y 6)로 낮췄다. 그러자 AA 요격이 5/12로 떨어져서 롤아웃 높이(y 12)로 되돌렸다.
- 모델 검사를 SimChecks와 동시에 돌린 한 번은 PD 회전축 검사에서 실패했다. 모든 GLB의 PD 회전축 위치는 데이터와 일치했고, 단독으로 다시 돌리자 통과했다.
