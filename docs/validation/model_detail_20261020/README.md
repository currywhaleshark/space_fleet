# 시안형 함선 외장 디테일

2026-10-20. 시안에 맞춘 실루엣을 유지하면서 평평한 선체에 입체적인 정비·장갑 구조를 추가했다.

[다뉴브 변경 전후](before-after.jpg) · [대표 함급 모음](overview.jpg)

## 반영 범위

- 시안형 T1·T3·T4·T5 **28함급**의 Blender 원본과 GLB, 격납고 초상화.
- 기존에 상세 외장이 있는 기본 6함급은 그대로 유지한다.
- 단차가 있는 모따기 장갑판, 매립형 점검 덮개와 경첩, 냉각 루버, 고정 클램프, 배관, 낮은 정비함.
- 지구 설계는 폐쇄형 장갑·정비 덮개, 화성 설계는 구리색 열 전달 배관·냉각 그릴 비중을 높였다.
- 날개·미익은 얇은 패널과 드문 체결부만 사용한다. 조종석·광학창·발사구·노즐은 덮지 않는다.
- 입체 장갑에 중복되던 절차적 표면 무늬·도장 얼룩을 줄였다. 새 장갑도 기존 손상·소손 셰이더를 사용한다.

단순한 상자 충돌 구획에 맞춰 장식을 배치하지 않는다. 저장된 실제 메시를 광선으로 검사하고, 비평면 로프트도 실제 삼각형 표면에 투영한다. 발사구와 엔진/RCS 출구에는 별도 통과 공간을 둔다. 초회 검사에서 화성 T5 전함 정비함이 미사일 발사 경로를 가린 문제가 발견되어, 이 통과 공간 검사를 추가하고 재생성했다.

## 보존 계약

`data/ships`, `data/variants`, `data/model_layouts`, `src/Sim`은 변경하지 않았다. 기존 메시의 정점·면·부모·변환과 모든 EMPTY의 변환을 SHA-256으로 비교한다. 28척 모두 작업 전 저장본과 일치한다. 포탑 회전·고저·반동, 포구, PD, 모듈, 엔진/RCS 좌표를 유지했다.

추가 구조는 `REFIT | ...` 이름으로 별도 편집 가능하다. GLB 내보내기 때 정적 구조는 기존 `FleetHull`에 합쳐진다. 이동 노드에 추가된 구조는 그 노드의 로컬 좌표를 사용한다. 기존 메시 그룹 수는 동일하며, 새 장갑 재질 하나가 추가된다. 모든 대상 모델은 머티리얼 11~12개, 전체 삼각형 수 15,284~44,808개다. 이는 모델당 수치이며 FPS 측정치는 아니다.

## 재생성 및 수동 편집

저장된 `.blend`를 입력으로 사용한다. 기존 큰 형상을 새로 만드는 `build-reference-models.py`를 실행할 필요가 없다.

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.1\blender.exe' --background --factory-startup --python-exit-code 1 --python tools/detail-reference-models.py -- --root . --ship earth_gun_cruiser,mars_missile_cruiser
```

`--ship`을 생략하면 형상 계약이 있는 28함급에 적용한다. 재실행은 `REFIT | ...`만 교체한다. 생성된 디테일을 수동으로 편집한 뒤에는 재생성 대신 기존 `tools/export-ship-models.py`로 내보낸다. `assets/ships/manifest.json`의 `surfaceDetail`은 일반 내보내기에서도 유지된다.

최초 로컬 백업은 무시 경로인 `shots/detail-pass/source-backup/`에 남겼다. 저장소의 변경 전 버전도 원형을 보존한다.

## 검증

- `detail-audit.json`: 28척의 원형 보존, 얕은 외장 범위, 같은 소스로 같은 디테일 생성. 메모리에서 재생성하며 파일을 쓰지 않는 감사.
- `geometry-audit.json`: 28척의 모듈·무장·엔진 마커 일치, 엔진/프로브 가시성, 미사일 발사구 통과, 부품 AABB 연결 후보 검사 통과. AABB 연결만으로 모든 면 접촉을 증명하지 않으므로 실제 화면 검토를 병행한다.
- Godot Vulkan 실제 렌더러: 모델 **10,975**, 망원 **2,472**, 전투 시각효과 **237**, 격납고 **83**, 레이저 **17** 검사 통과.
- C# 빌드 경고·오류 0.
- 최종 모델에서 격납고 초상화 28장 갱신.
- 28함급의 최종 정면 사선 렌더, 대표 순양함/소형함 4종의 하부, 순양함·전함의 전투 조명을 촬영해 검토했다.
- 상세 모델 다뉴브·아르기레를 실제 두 동강 효과로 확인했다. 추가 외장이 선체 절단을 따라가며, 내부 절단면/탈락 부품 생성이 완료된다. 해당 컷의 생성 총시간 132.2/154.6ms, 분할 생성의 가장 긴 단계 16.0/19.9ms. 단일 검토 컷 값이며 전체 전투 프레임 시간은 아니다.
- T5 아마존 선택, 시드 1, 소행성 배치 2, 10:10 편대 자동 매칭을 별도 테스트 프로필로 25초 실행해 정상 종료했다. Debug 게임/최적화 Sim, RTX 2060, 1600×900, 배속 1, 수직동기 해제. 6~25초의 1초 보고창 20개는 평균 51.24 FPS, 최저 보고창 46.4 FPS였다. 변경 전 동조건 비교가 없고 초반 접근 구간이므로 성능 회귀 없음이나 전투 전체 성능을 뜻하지 않는다.
- 처음 시도한 `--advance=180` 실행은 첫 성능 보고창 전에 55초 제한을 넘겨 중단했다. 완료된 검증은 선행 계산 없는 초기 실행이다. 해당 로그도 별도로 보존한다.

함선 성능·피해 계산은 변경하지 않았으며, 장기 전투 밸런스 재측정은 이번 외장 작업 범위에 포함하지 않는다. 전체 함대의 최소 FPS 보장이나 240척 성능 검증을 위 검사 수치로 대신하지 않는다.

각 함급 JSON은 생성 수량·원형 해시·최종 삼각형 수를 기록한다. 화면과 게임 검사 원본 로그는 로컬 `shots/detail-pass/`에 있다.

## Windows 배포본 — 2026-10-21

- `builds/SpaceFleet-20261021-model-details-r2-Windows-x64/SpaceFleet.exe`와 동일 이름 ZIP 생성. 커밋 `45c60da`에 현재 작업 폴더의 모델·렌더 변경을 포함했다. 커밋/푸시는 수행하지 않았다.
- 최초 배포 검사에서 편대 공격 화살표의 `Invalid polygon data, triangulation failed` 오류가 발생했다. 작은 삼각형을 큰 화면 좌표에서 직접 삼각분할하던 부분을 원점 근처에서 그리고 변환하도록 수정했다. 발신 함선의 비정상 투영 좌표도 제한한다. 전투 판정이나 편대 명령은 변경하지 않는다.
- 수정 후 실제 배포 실행파일에서 자동검사 20묶음, 총 **16,217개** 통과. 최초 실패와 수정 후 매칭·관전 검사 로그를 함께 보존한다.
- 게임·시뮬레이션 DLL이 최신 `ExportRelease/win-x64` 출력과 SHA-256 일치. 런타임 포함 확인, ZIP 전체 CRC와 SHA-256 검증 통과.
- 배포 실행파일에서 다뉴브 모델을 1600×900으로 촬영해 추가 외장이 포함된 것을 확인했다. 원본 화면과 전체 검사 로그는 `shots/SpaceFleet-20261021-model-details-r2-Windows-x64/`에 있다.
