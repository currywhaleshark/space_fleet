# 작업지시서: 7단계 버티컬 슬라이스 — 한 판의 전투

작성 2026-10-06 · 기준 커밋 `365c478` · 대상 저장소 `space_fleet/`

## 0. 목표 한 줄

> 24척(진영당 전투단 BB+DD2 · 호위 전대 DD4 · 요격 편대 IC5)이 150 km에서 만나 **장거리 센서·미사일전 → 레일건 포격전 → 모듈 정밀타격 → 근접 난전**을 거쳐 **15~20분 안에 승패가 나는 한 판**을, 플레이어가 함선 하나를 골라 처음부터 끝까지 할 수 있다.

이번 단계의 핵심은 두 가지다.

1. **흐름을 숫자로 잰다.** 지금은 "20분 뒤 몇 척 남았나"만 안다. 전투의 국면이 언제 바뀌는지 기록하고, 여러 판을 돌려 분포를 본다.
2. **잰 숫자를 목표 범위에 넣는다.** 현재 전투단은 60 km 대치에서 끝까지 멈춰 있고(난전이 생기지 않는다), 아군 쪽이 일관되게 불리하다. 이 두 문제를 원인부터 고친다.

그 위에 시작 → 함선 선택 → 전투 → 결과 → 다시 하기의 최소한의 판 구조를 얹는다.

순서가 중요하다. **측정(1차) → 비대칭 원인(2차) → 흐름(3차) → 판 구조(4차) → 성능·안정성(5차)**. 측정 없이 수치를 만지지 않는다.

### 1.1 작업 환경 주의

- **셸**: Windows PowerShell. dotnet이 PATH에 없으면 `. .\tools\godot.ps1`을 먼저 실행한다.
- **명령**
  - 빌드: `.\tools\build.ps1`
  - 시뮬레이션 검사: `.\tools\check-sim.ps1` (현재 512개, 약 80초)
  - 화면 확인: `.\tools\shot.ps1 <이름> [인자]` → `shots/<이름>.png`. 전함 롤처럼 느린 동작은 `--frames`를 넉넉히(전함 180° 롤 ≈ 1,700프레임).
- **스크린샷 인자**: 쉼표가 든 인자는 `'--turn=0,-8'`처럼 따옴표로 감싼다.
- **C# 예외 로그**: `%APPDATA%\Godot\app_userdata\Space Fleet\logs\godot.log`
- **커밋 메시지**: 스크래치 파일에 써서 `git commit -F <파일>`. 마지막 줄은 `Co-Authored-By: ...`.
- **한글 파일 작성**: bash heredoc 금지(인코딩 깨짐). 파일 쓰기 도구나 UTF-8(BOM 없음).
- **사용자 선호**
  - HUD는 글자보다 도형·게이지·그래프. 글자는 호출부호·거리·피해 리포트·짧은 실패 사유만. 메뉴·결과 화면의 제목과 버튼 글자는 괜찮다.
  - 기본 비행 방식은 우주식이며 이동 방향 단서를 유지한다.
  - 손으로 해 봐야 아는 것(조작감, 재미)은 "미확인"으로 정직하게 보고한다.

### 2.1 함대 배치가 두 군데에 따로 있다

| 위치 | 용도 | 호출부호 | 차이 |

- 공통 배치: 적 원점은 `(3000, 22000, -150000)`이고, 좌표를 뒤집어 마주 본다.
- **적이 22 km 위, 3 km 옆에서 출발한다.** 비대칭 후보 1순위다.

### 2.2 AI 지휘 (`src/Sim/SimAI.cs`)

- **함선 두뇌** (`ShipBrain`): 0.25초마다 판단하고, 매 틱 조종한다.
- **함종별 기준값** (`ShipAI.cs`의 `AiProfile`):

  | 함종 | 대치 거리 | 레일건 비행 시간 상한 | 미사일 사거리 | 공격 기동 |
  |---|---|---|---|---|
  | 전함 | 60 km | 8 s | 140 km | 없음 |
  | 호위함 | 30 km | 5 s | 110 km | 없음 |
  | 요격함 | 6 km | 2.5 s | 15 km | 침투 공격 |

- **진영 지휘관** (`Command(faction)`, 2초마다): 전투단 → 호위 전대 → 요격 편대 순서로 표적과 행동을 정한다.
  - 전투단: 주 표적을 정해 대치 포격한다.
  - 호위 전대: 기함 호위 → 측면 기동 → 측면 공격 → 방공.
  - 요격 편대: 전방 경계 → 요격 → 집결 → 돌격.
- **국면 개념이 없다.**
  - 전투단은 대치 거리에 닿으면 그 자리에서 끝까지 쏜다. 난전으로 넘어갈 계기가 없다.
  - 미사일을 다 쓴 뒤에도, 상대가 무너진 뒤에도 행동이 같다.

### 2.3 현재 전면전 결과 (`check-sim`의 `Full battle 20 min`, 결정적이라 매번 같음)

- **진행**: 첫 피해 4.8분. 20분 동안 24척 중 15척이 격침되거나 무력화된다.

  - 적이 미사일은 2.7배, 레일건은 4배 많이 쏜다.
  - 아군이 일관되게 진다.
- **한계**: 한 가지 배치로 한 판만 본 결과다. 우연인지 구조 문제인지 모른다.

### 2.4 판 구조가 없다

## 3. 단계별 작업

각 차수가 끝날 때마다 빌드, `check-sim` 전부 통과, 커밋, 7장 형식의 보고를 한다.

### 1차: 전투 시나리오 통합과 측정

#### 3.1.1 Sim: 배치 하나로 (`src/Sim/BattleSetup.cs`)

```csharp
public sealed record BattleConfig
{
    public int Seed { get; init; }                  // 0 = 지금 배치 그대로(지터 없음)
    public double StartDistance { get; init; } = 150_000;
    public Vector3 RedOffset { get; init; } = new(3000, 22000, 0);   // 지금 값. 2차에서 조사
    public bool Mirror { get; init; }               // 진영과 출발 위치를 맞바꾼다(2차 진단용)
    public double PositionJitter { get; init; } = 2_000;   // Seed≠0일 때 편대 단위 위치 흔들기(m)
    public float HeadingJitterDegrees { get; init; } = 5;
}
public static class BattleSetup
{
    public static BattleRoster Spawn(SimWorld world, BattleConfig config); // 함선·편대·지휘관까지
}
```

- **배치 하나로 통합**: 게임 쪽 `ScaleTest.SpawnFleets()`의 배치와 호출부호를 기준으로 삼는다. 게임과 검사가 같은 함수를 쓴다.
  - 게임 쪽은 반환된 함선에 `ShipView`와 드론 연출만 붙인다.
  - 검사 쪽 `AIChecks.SpawnFleets`는 지운다.
- **시드 흔들기**: 결정적이어야 한다. `System.Random`을 시드로 만들어 이 함수 안에서만 쓴다.
  - 같은 시드면 같은 배치, 같은 결과다.
  - 흔드는 단위는 편대다. 편대 안의 대형은 유지한다.
- **`Mirror`**: 진영 표식(Faction)과 지휘관은 그대로 둔다. 출발 위치·자세만 맞바꾼다.
- **기준값 변경**: 배치가 바뀌므로 `Full battle` 숫자가 달라진다.
  - 이 커밋에서는 **동작 변경 없이 배치 통합만** 한다.
  - 바뀐 숫자를 **새 기준값**으로 보고서에 남긴다. 이후 차수는 이 기준과 비교한다.

#### 3.1.2 Sim: 전투 기록 (`src/Sim/BattleLog.cs`)

`SimWorld`에 붙여 매 틱(또는 무거우면 1초마다) 갱신하는 기록기. Godot 의존 없음.

- **처음 일어난 시각** (진영별, 초)
  - 탐지 단계: 접촉 · 식별 · 잠금.
  - 미사일: 첫 발사 · 첫 명중.
  - 레일건: 첫 발사 · 첫 명중.
  - 피해: 첫 모듈 파괴 · 첫 함선 무력화 · 첫 격침.
  - 근접: 적 주력함(BB·DD)과 내 주력함 사이가 처음 15 km 안으로 들어온 시각.
- **30초 구간별 국면**: 구간마다 하나로 분류한다. 위에서부터 먼저 맞는 것을 쓴다.

  | 국면 | 조건 |
  |---|---|
  | `Brawl` 난전 | 서로 15 km 안의 주력함이 이 구간에 레일건을 쏨, 또는 요격함이 주력함에 명중시킴 |
  | `Sniping` 정밀타격 | 이 구간에 모듈 파괴가 2개 이상이고, 그 대부분(≥ 50%)이 실드가 꺼진 함선에 들어감 |
  | `Gunnery` 포격전 | 이 구간에 주력함 레일건 발사가 있음 |
  | `Missile` 미사일전 | 이 구간에 미사일 발사가 있음 |
  | `Approach` 접근 | 그 밖(탐지·기동만) |

- **분 단위 전력**: 진영별로 1분마다 남은 전력을 기록한다(3.1.3의 점수).
- **이벤트 목록**: 격침·무력화·모듈 파괴를 시각, 함선, 가해 진영과 함께 적는다. 결과 화면과 보고서에 쓴다.
- **요약 문자열** `BattleLog.Summary()`: 검사와 배치 실행기가 한 줄로 찍는다.

#### 3.1.3 Sim: 승패 규칙 (`src/Sim/BattleRules.cs`)

- **전력 점수**: 격침되지도 무력화되지도 않은 함선의 가중치 합이다.
  - 가중치는 전함 6, 호위함 2, 요격함 0.5다.
  - 출발 전력은 진영당 6 + 2×6 + 0.5×5 = 20.5다.
- **패배**: 다음 중 하나가 먼저 되면 그 진영이 진다. 양쪽이 같은 틱에 패배하면 무승부다.
  - 전력이 출발의 25% 이하로 떨어진다.
  - 기함(전투단 선두 전함)이 격침되거나 무력화되고, 전력이 50% 이하다.
- **시간 제한 25분**: 남은 전력 비율이 높은 쪽이 이긴다. 비율 차이가 10%p 안이면 무승부다.
- **결과**: `BattleOutcome { Winner?, Reason, Time }`. 판정이 난 뒤에도 시뮬레이션은 계속 돌 수 있다. 결과 화면 뒤 관전용이다.
- 수치는 `BattleRules` 상단의 상수 한곳에 모은다. 조정용 값임을 주석으로 단다.

#### 3.1.4 배치 실행기 (`tools/BattleBatch/`, `tools/battle-batch.ps1`)

- **프로젝트**: 콘솔 프로젝트. `SimChecks.csproj`처럼 `src/Sim/*.cs`와 함선 JSON을 링크해서 쓴다.
- **인자**: `-Seeds 1..20`, `-Mirror`(각 시드를 원본·뒤집기 두 판), `-Minutes 25`, `-Parallel`.
  - `-Parallel`은 판마다 별도 `SimWorld`를 쓰므로 가능해야 한다.
  - `src/Sim`에 가변 정적 상태가 없는지 먼저 확인한다. 있으면 보고하고 고친다.
- **출력**
  - `shots/batch/<날짜>_<라벨>.csv`: 한 판에 한 줄. 시드, 뒤집기, 승자, 판정 이유, 판정 시각, 3.1.2의 처음 시각들, 국면별 누적 시간, 진영별 발사·명중 수.
  - 콘솔 요약: 각 지표의 중앙값·최소·최대, 승패 분포(진영별, 출발 위치별), 국면별로 그 국면이 1분 이상 있었던 판의 비율.
- **시간 측정**: 한 판에 걸리는 실제 시간을 재서 보고한다(5차 성능의 기준).

#### 3.1.5 검사

- **`BattleChecks.cs` 신설**: 기존 `AIChecks`의 전면전 검사를 여기로 옮긴다.
  - 같은 시드로 두 번 돌리면 `BattleLog.Summary()`가 글자 하나까지 같아야 한다(결정성).
  - 시드 0과 시드 1의 출발 배치가 실제로 다르다.
  - `Mirror`는 출발 위치만 바꾸고 진영 표식은 그대로다.
- **`BattleRules` 단위 검사**: 전력 점수, 25% 패배, 기함+50% 패배, 동시 패배 무승부, 시간 제한 판정.
- **`BattleLog` 단위 검사**: 작은 장면을 만들어 국면 분류를 확인한다.
  - 20 km 미사일 발사만 → `Missile`.
  - 50 km 레일건만 → `Gunnery`.
  - 10 km 주력함 레일건 → `Brawl`.
- **`check-sim` 시간**: 지금 약 80초다. 전면전은 한 판만 남기고 2분 안쪽을 유지한다. 여러 판은 배치 실행기의 일이다.

#### 3.1.6 1차 보고에 꼭 넣을 것

- 시드 1~20 × 뒤집기의 **현재 상태 기준값**을 표로 정리한다.
  - 전투 흐름: 처음 시각들의 중앙값, 국면 비율.
  - 결과: 승패 분포, 판정 시각.
- 이 표를 `docs/BALANCE_stage7.md`에 "기준(작업 전)"으로 남긴다.

### 2차: 아군 열세 원인 찾기

**진영별로 수치를 다르게 주어 맞추는 것은 금지다.** 원인을 찾아 구조를 고친다.

#### 3.2.1 진단 순서

1. **뒤집기 결과로 원인을 가른다.**
   - 지는 쪽이 진영을 따라가면(파랑이 어느 위치에서 출발하든 진다) 코드의 비대칭이다.
   - 지는 쪽이 출발 위치를 따라가면(위쪽에서 출발한 쪽이 이긴다) 배치의 비대칭이다.
2. **코드 비대칭 후보.** 각각을 확인하고 결과를 보고한다.
   - `_ships` 순회 순서: 파랑이 먼저 추가되어 매 틱 먼저 움직이고 먼저 쏜다. 같은 틱 안에서 먼저 쏜 쪽이 이득을 보는지 확인한다.
     - 해결 예: 판단은 모두 끝낸 뒤 발사를 일괄 적용한다.
     - 해결 예: 틱마다 진영 순서를 번갈아 바꾼다.
   - `Command(faction)` 호출 순서. 지휘관 2초 주기가 두 진영에서 같은 틱에 도는지.
   - 일제사격 키, 표적 배정의 `OrderBy(Callsign)` 동률 처리. 호출부호 문자열("BB-01" 대 "BB-X1")의 정렬 차이가 행동을 바꾸는지.
   - `Faction.Blue`·`Faction.Red`를 직접 비교하는 분기(`grep -rn "Faction\.\(Blue\|Red\)" src/Sim`).
   - 게임 쪽에만 있는 진영별 기본값. 예: 적만 켜진 ECM, 핍, AI 비활성.
3. **배치 비대칭 후보**
   - 22 km 고도 차이와 3 km 옆 차이.
   - 출발 자세.
   - 요격 편대·호위 전대가 기함과 어느 쪽에 붙는지(`dir` 뒤집기로 좌우가 바뀌는지).
4. **센서 비대칭**: 처음 접촉·식별·잠금 시각이 진영 사이에 다르면, 그 원인을 2·3에서 찾는다.

#### 3.2.2 고치기

- **코드 비대칭**: 진영과 무관하게 같은 결과가 나오도록 구조를 바꾼다.
  - 이 수정은 AI 결정성 결과를 바꿀 수밖에 없다. 그래서 배치 실행기 결과로 정당화한다.
- **배치 비대칭**: 기본 `RedOffset`을 대칭에 가깝게 조정한다. 예: 고도 차이를 0으로 하거나 양쪽에 같은 크기로 나눈다.
  - 고도·옆 차이는 시드 흔들기로 남긴다.

#### 3.2.3 완료 조건

- 시드 1~20 × 뒤집기, 총 40판을 돌린다. 다음을 모두 만족해야 한다.
  - 진영별 승률이 각각 35~65%다.
  - 원본과 뒤집기의 승률 차이가 20%p 이하다.
- 처음 접촉·식별·잠금 시각의 진영별 중앙값 차이가 15초 이하다.
- 결과를 `docs/BALANCE_stage7.md`에 "비대칭 수정 후"로 추가하고, 찾은 원인을 한 단락으로 쓴다.

### 3차: 전투 흐름(국면 진행)

#### 3.3.1 Sim: 함대 태세 (`FleetPosture`)

진영 지휘관이 2초마다 태세를 정한다. **양쪽 진영이 같은 규칙을 쓴다.**

```csharp
public enum FleetPosture { Approach, Missile, Gunline, Close, Withdraw }
public sealed record FleetDoctrine   // 조정용 값 한곳. 기본값은 아래 표
{
    public double MissileBandMeters { get; init; } = 120_000;
    public double GunlineMeters { get; init; } = 60_000;
    public double CloseMeters { get; init; } = 12_000;
    public float MissileStockToGunline { get; init; } = 0.35f;
    public double MissilePhaseMaxSeconds { get; init; } = 240;
    public double GunlineMaxSeconds { get; init; } = 360;
    public float CloseStrengthRatio { get; init; } = 1.25f;
    public float WithdrawStrengthRatio { get; init; } = 0.4f;
}
```

| 태세 | 들어가는 조건 | 전투단 | 호위 전대 | 요격 편대 |
|---|---|---|---|---|
| `Approach` | 시작, 적이 식별 전 | 적 함대 쪽으로 순항 | 기함 호위 | 전방 경계 |
| `Missile` | 적 주력함이 식별되고 `MissileBand` 안 | 미사일 사거리 끝 유지, 일제사격 | 기함 호위·방공 | 방공(적 요격함 요격) |
| `Gunline` | 아군 주력함 평균 미사일 잔량 ≤ `MissileStockToGunline`, 또는 `Missile` 태세가 `MissilePhaseMax`를 넘김 | `GunlineMeters`까지 전진, 레일건 대치(지금 행동) | 측면 기동 → 측면 공격 | 집결 → 침투 공격 |
| `Close` | 전력 비 ≥ `CloseStrengthRatio`, 또는 `Gunline` 태세가 `GunlineMax`를 넘김, 또는 적 기함 추진 50% 이하 | `CloseMeters`까지 접근. 전투단 호위함은 전함 사각 엄호 | 적 주력함 근접 공격 | 적 주력함 후미 침투 |
| `Withdraw` | 전력 비 ≤ `WithdrawStrengthRatio` | 적 반대쪽으로 이탈하며 후미 레일건 | 기함 엄호 | 기함 엄호 |

- **전력 비**: 내 전력 점수 ÷ 적 전력 점수(3.1.3)다.
  - 적 전력은 **센서가 아는 것만** 센다. 식별 이상인 적 중 겉보기로 무력화되지 않은 것이다.
- **한 방향 진행**: 태세는 `Approach → Missile → Gunline → Close` 순서로만 간다.
  - 예외는 `Withdraw`다. 어느 태세에서든 들어갈 수 있다.
  - 경계에서 깜박이지 않도록 한 번 바뀐 태세는 최소 30초 유지한다.
- **정밀타격 국면**: 새 태세가 아니라 `Gunline`과 `Close` 안의 사격 규칙으로 만든다.
  - 표적의 실드가 0이 되면, AI 주력함은 무력화 교리처럼 그 표적의 추진·무장 모듈을 노린다.
  - 직전 작업의 `GunneryOrder`·`Subsystems.Pick`·`PreviewArmor`를 그대로 쓴다.
- **플레이어 편대**(`PlayerLed`)에는 태세 행동을 강제하지 않는다. HUD에 진영 태세를 보여 주기만 한다.
- `Squadron.Activity`는 지금처럼 짧은 한국어 문구를 쓰고, 태세가 드러나게 한다. 예: "미사일전", "포격선", "근접".

#### 3.3.2 흐름 목표 (배치 실행기 40판 기준)

| 지표 | 목표 |
|---|---|
| 첫 접촉 | 중앙값 1분 이내 |
| 첫 미사일 발사 | 중앙값 1~4분 |
| 첫 레일건 명중 | 중앙값 4~9분 |
| 첫 모듈 파괴 | 중앙값 5~10분 |
| 주력함 15 km 근접 | 중앙값 10~16분, 70% 이상의 판에서 발생 |
| 승패 판정 | 70% 이상의 판이 15~20분 사이에 판정. 10분 전 판정 5% 이하. 무승부(시간 제한) 15% 이하 |
| 국면 | `Missile`·`Gunnery`·`Sniping`·`Brawl` 각각이 1분 이상 나타난 판이 70% 이상 |
| 승률 | 2차 조건 유지(진영별 35~65%) |
| 아군끼리 충돌 | 판당 평균 1회 이하(근접 태세에서 대형이 무너지지 않는지) |

- 목표를 못 맞춘 지표는 억지로 맞추지 않는다. 가장 가까운 상태와 원인 추정을 보고한다.
- 조정하는 값은 `FleetDoctrine`, `AiProfile`, `BattleRules`를 우선한다. 함선 JSON(무장·장갑·센서)은 마지막 수단으로만 손대고, 바꾸면 이유를 남긴다.
- 조정 과정의 주요 시도와 결과(시도, 바꾼 값, 40판 요약 한 줄)를 `docs/BALANCE_stage7.md`에 남긴다.

#### 3.3.3 검사

- **태세 전환 단위 검사**: 작은 장면을 만들어 각 전환 조건을 확인한다.
  - 미사일 잔량을 줄이면 `Gunline`이 된다.
  - 적 기함 추진을 50%로 만들면 `Close`가 된다.
  - 전력 비 0.4면 `Withdraw`가 된다.
  - 30초 유지 규칙이 지켜진다.
- **전면전 1판**: `check-sim`에서 시드 고정으로 돈다. 국면 4개가 모두 나타나고 승패가 판정되는지 확인한다.

### 4차: 판 구조(플레이어가 하는 한 판)

#### 3.4.1 흐름

```
시작 화면 → 함선 선택 → 전투(브리핑 3초 겹침) → 결과 화면 → [다시 · 함선 바꾸기 · 종료]
                                ↑ 일시정지 메뉴(계속 · 다시 · 종료)
```

- **씬 구성**: 새 메인 씬 `scenes/Main.tscn`이 메뉴를 띄우고, 전투 씬을 `BattleConfig`와 함께 연다.
  - 전투 씬은 기존 `ScaleTest`를 재사용해도 되고, 개발 기능을 뺀 얇은 전투 씬을 새로 만들어도 된다. 어느 쪽이든 **`ScaleTest`의 개발 기능과 스크린샷 인자는 그대로 동작**해야 한다.
- **`--shot` 인자**: 명령줄에 있으면 메뉴를 건너뛰고 지금처럼 바로 장면을 연다. `tools/shot.ps1`이 깨지면 안 된다.
- **새 스크린샷 인자**: `--menu=title|select|result`. 메뉴 화면 확인용이다.
  - `--result-test`: 판정이 난 상태를 강제로 만든다. 결과 화면 확인용이다.

#### 3.4.2 함선 선택

세 칸으로 고른다. 각 칸에는 함선 실루엣(기존 절차적 모델의 정지 렌더, 또는 도형), 역할 한 줄, 조작 방식 아이콘을 둔다.

| 선택 | 탈 함선 | 역할 한 줄 | 조작 |
|---|---|---|---|
| 함장 | BB-01 | 전투단을 이끌고 포격선을 만든다 | 키보드 조함 + 자동 사격 |
| 전투지휘관 | DD-31 (호위 전대 선두) | 측면을 돌아 적 주력함을 친다 | 키보드 조함 + 자동 사격 |
| 조종사 | IC-21 (요격 편대 선두) | 적 요격함을 막고 주력함 후미를 판다 | 마우스 비행·사격 |

- 고른 함선의 편대가 플레이어 편대(`PlayerLed`)가 된다. 나머지는 진영 지휘관이 움직인다.
- 아군 진영은 파랑으로 고정한다. 진영 고르기는 이번 범위 밖이다.

#### 3.4.3 전투 중

- **진영 전력 막대**: 상단 중앙의 작은 막대에 양 진영의 남은 전력을 보인다.
  - 표시는 파랑·빨강 두 막대와 출발 대비 비율이다. 글자 없이 막대만 쓴다.
  - 적 전력은 센서가 아는 만큼만 보인다. 모르는 부분은 옅은 빗금으로 칠한다.
- **진영 태세**: 작은 도형 4칸(미사일·포격·근접·이탈)으로 보이고, 현재 칸에 불이 들어온다. 편대 현황 패널 위에 둔다.
- **내 함선 격침·무력화**
  1. 3초 동안 화면을 어둡게 하고, 중앙에 "격침" 또는 "무력화"를 띄운다.
  2. 이어서 같은 진영의 살아 있는 함선 중 하나로 옮겨 탄다. 같은 함종을 우선하고, 없으면 큰 함종부터 고른다. 기존 `SelectControl`·`HandOverControl`을 쓴다.
  3. 옮겨 탈 함선이 없으면 관전 카메라(기함 또는 남은 아무 함선 추적)로 바꾼다.
- **일시정지**: Esc를 누르면 일시정지 메뉴가 열린다.
  - 커서가 자유로울 때(Helm, 또는 마우스를 놓은 Pilot)만 연다.
  - Pilot이 마우스를 잡은 상태에서는 지금처럼 첫 Esc가 마우스를 놓는다.
  - 열린 라디얼에서는 지금처럼 Esc가 취소다. **우선순위는 라디얼 취소 → 마우스 해제 → 일시정지다.**
- **배속**: 판 모드에서는 ×1·×2·×4만 쓴다. ×16은 `--dev`에서만이다.
- **개발 키 잠금**: 판 모드에서는 F2~F8, 1~5·0 직접 핍, Tab 임의 전환, G/H/J를 막는다.
  - `--dev`로 열면 지금처럼 모두 쓸 수 있다.
  - F1 도움말은 판 모드에서 "플레이 조작"만 보인다.

#### 3.4.4 결과 화면

판정이 나면 배속을 ×1로 되돌리고 2초 뒤 결과 화면을 띄운다. 그 뒤로도 시뮬레이션은 뒤에서 계속 돈다.

- **결과**: 승리·패배·무승부와 판정 이유 한 줄, 경과 시간.
- **국면 띠**: 가로 막대 하나에 전투 전체를 시간순으로 그린다.
  - 30초 구간마다 국면별 색을 칠한다(`BattleLog` 30초 구간).
  - 위쪽에는 격침 표시(진영 색 X), 아래쪽에는 내가 탄 구간을 선으로 표시한다.
  - 국면 이름은 띠 아래 범례로 한 번만 쓴다.
- **양 진영 함대**: 함종 아이콘 줄. 상태는 편대 현황 HUD와 같은 규칙으로 칠한다.
  - 정상은 진영색, 손상은 주황, 무력화는 빨강, 격침은 X다.
- **내 기록**: 숫자 6개를 막대나 큰 숫자로 보인다. 글자 라벨은 짧게 단다.
  - 레일건 발사/명중, 미사일 발사/명중, 파괴한 모듈 수, 받은 피해(실드·장갑 관통·모듈 손실).
- **버튼**: 다시(같은 함선, 새 시드), 함선 바꾸기, 종료.
- **시드**: 판마다 새 시드를 쓴다. 결과 화면 구석에 작게 표시해 재현할 수 있게 한다. `--seed=N`으로 같은 판을 다시 돌릴 수 있다.

### 5차: 성능·안정성

- **시뮬레이션**: 배치 실행기에 틱 시간을 재는 옵션을 넣는다. 전면전 한 판의 `SimWorld.Step()` 평균, 99번째 백분위, 최대(ms)를 보고한다.
  - 국면별로도 따로 잰다. 난전 구간에 탄·미사일이 몰린다.
  - 목표는 평균 2 ms 이하, p99 6 ms 이하다. 넘으면 가장 비싼 곳을 찾아 보고한다(프로파일 결과 또는 구간 측정).
- **게임**: 관전 자동 진행 인자 `--autoplay`를 만든다. 플레이어 함선도 AI가 몰고, 배속 ×4로 판정까지 진행한다.
  - FPS 최소·평균을 로그에 찍는다.
  - `godot.log`에 예외가 0개인지 확인한다.
  - 시작, 10분, 판정 시점의 FPS를 보고한다.
- **오래 돌리기**: 판정 뒤 5분 더 돌려도 탄·미사일·이벤트 목록이 무한히 쌓이지 않는지 확인한다.
  - `Impacts`, `OrdnanceEvents`, `BattleLog` 이벤트 목록의 크기를 본다.

## 4. 유지할 것 (지우지 말 것)

- **개발·검증 기능 전부**: Tab 전환, F1~F8, 직접 핍, T, G/H/J, 배속, 스크린샷 인자 전부, `tools/*`, `tests/SimChecks` 전부.
  - 판 모드에서는 잠그고, `--dev`나 `ScaleTest` 직접 실행에서는 그대로 쓴다.
- **직전 작업의 조작 체계**: Pilot/Helm, 라디얼, 사격 교리, 화면 밖 표시, 사격 방위구. 이번 단계에서 바꾸지 않는다.
- **결정성**: 같은 시드, 같은 입력이면 같은 결과다. 매 차수 `check-sim`의 결정성 검사가 통과해야 한다.
- **층 분리**: `BattleSetup`·`BattleLog`·`BattleRules`·`FleetPosture`는 전부 `src/Sim`에 두고 Godot 노드에 의존하지 않는다. 나중에 서버에서 이 층만 돈다.

- 최종 UI 아트. 메뉴와 결과 화면은 기존 HUD 색과 도형 문법으로 단정하게만 만든다.
- 진영별로 다른 수치로 승률을 맞추는 것
- 비행 모델·피해 모델의 근본 변경. 흐름을 맞추려고 물리를 바꾸지 않는다. 바꿔야 한다고 판단되면 먼저 보고한다.

## 6. 완료 기준

**측정**

- 배치 실행기가 시드 1~20 × 뒤집기 40판을 돌려 CSV와 요약을 낸다.
- 같은 시드로 두 번 돌리면 결과가 같다.

**균형**

- 2차 완료 조건(진영별 승률 35~65%, 뒤집기 차이 20%p 이하)을 만족한다.
- 찾은 원인이 문서에 있다.

**흐름**

- 3.3.2 표의 목표를 만족한다. 못 맞춘 지표는 현재 값, 가장 가까웠던 시도, 원인 추정을 보고한다.

**플레이**

- 메인 실행 → 함선 선택 → 전투 → 결과 → 다시 하기가 끊김 없이 이어진다.
- 세 역할 모두로 시작할 수 있다.
- 내 함선을 잃으면 자동으로 옮겨 탄다.

**공통**

- `check-sim` 전부 통과(새 검사 포함), 2분 안쪽.
- `godot.log`에 예외 0개.
- 4차 스크린샷이 있다.
- README(실행·조작·판 규칙), PLAN(7단계 항목과 알아낸 것), `docs/BALANCE_stage7.md`가 갱신되어 있다.
