# Space Fleet (가칭 Project Fleet)

3D 우주 함대전 프로토타입. Godot 4.7 .NET + C#.

계획과 진행 상황은 [docs/PLAN.md](docs/PLAN.md)에 있다.

![0단계 스케일 테스트](docs/stage0_flyby.png)

## 필요한 것

- Godot 4.7.2 .NET: `%LOCALAPPDATA%\Programs\Godot\Godot_v4.7.2-stable_mono_win64\` (경로는 `tools/godot.ps1`에서 관리)
- .NET 8 SDK(Godot 에디터 C# 도구가 요구), .NET 10 SDK

## 실행

```powershell
.\tools\run.ps1        # 빌드 후 실행
.\tools\edit.ps1       # 에디터로 열기
.\tools\build.ps1      # C# 빌드만
.\tools\check-sim.ps1  # 기동·충돌·피해·탄도·선행 조준·데이터 검증
```

기본 실행은 시작 → 함선 선택(BB-01 / DD-31 / IC-21) → 전투 → 결과로 이어진다. BB/DD는 키보드 조함과 자동 사격, IC는 마우스 비행이다. 시작 안내는 3초, 함선 상실 시 3초 뒤 같은 함종의 생존 함선으로 인계한다(없으면 큰 함종, 전멸하면 관전). 결과에서 같은 역할·새 시드로 다시 시작하거나 역할을 바꿀 수 있다.

Windows 실행본은 `builds/SpaceFleet-*-Windows-x64/SpaceFleet.exe`로 시작한다. ZIP을 받았다면 전체를 풀고 실행한다. Godot·.NET 설치는 필요 없으며, 다른 폴더로 옮길 때는 EXE와 함께 `SpaceFleet.pck`, `data_*`, 고지 파일을 포함한 폴더 전체를 복사한다.

```powershell
.\tools\export-windows.ps1  # Windows x64 릴리스 → 내보낸 EXE 검사 → ZIP·SHA-256
```

배포 스크립트는 현재 작업본을 사용하며 모델·효과음·셰이더·.NET 런타임과 라이선스 고지를 포함한다. 최초 1회 공식 .NET 템플릿 약 1.2 GB를 내려받아 SHA-256을 검증하고 Windows용 실행 템플릿만 캐시한다. 촬영 영상·Blender 원본·검사 로그는 포함하지 않는다. 결과 및 자동검사 기록은 각각 `builds/`, `shots/빌드이름/`에 남는다. `export_presets.cfg`는 `tools/windows-export.cfg`에서 생성하며 사용자가 만든 기존 프리셋은 덮어쓰지 않는다.

판 모드 배속은 ×1·×2·×4. Esc는 라디얼 취소 → Pilot 마우스 해제 → 일시정지 순서다. F1은 플레이 조작만 표시한다. F2~F8, Tab, G/H/J는 `--dev` 또는 ScaleTest 직접 실행에서 사용할 수 있다. 전력·사격·편대·드론 방어 명령은 F/B/N/4 라디얼로 한다.

판정은 활성 전력(BB 6, DD 2, IC 0.5)이 초기의 25% 이하, 또는 기함 상실+전력 50% 이하일 때 패배다. 같은 틱의 동시 패배는 무승부. 25분 제한에서 잔존 비율 차이가 10%p 이하면 무승부다. 결과는 판정 시점의 기록을 보여 주고 전투는 뒤에서 계속 진행한다.

메뉴·전투 검증 인자(실행 인자는 Godot의 `--` 뒤):

```powershell
.\tools\shot.ps1 s7_title --menu=title
.\tools\shot.ps1 s7_select --menu=select
.\tools\shot.ps1 s7_bb_start --battle --control=BB-01 --seed=1 --frames=60
.\tools\shot.ps1 s7_result_win --result-test --result=win --seed=1
```

`--battle --seed=N`은 역할 선택을 건너뛰어 고정 시드로 시작한다. `--menu=result --result=loss`는 패배 결과 검증, `--autoplay`는 전 함선 AI·×4 관전이다. 기존 `--shot`만 쓰면 개발 ScaleTest로 바로 들어간다.

```powershell
.\tools\check-flow.ps1 # 빌드 후 메뉴·3역할·Esc·인계·결과 버튼 검사
.\tools\battle-batch.ps1 -Seeds (0) -Profile -PostSeconds 300 -Label performance
.\tools\run.ps1 --autoplay --autoplay-quit --perf --seed=1
```

프레임 구간 측정(개발용): `.\tools\run.ps1 --autoplay --seed=1 --advance=540 --perf-trace --perf-seconds=40`. 1초마다 FPS, 구간별 프레임당 평균/최대 ms(physics·sim·hudDraw·ballistics 등), 그리기 호출·객체·노드 수를 찍는다. `--autoplay-speed=1`로 배속을 바꾼다. 개발 실행은 Debug 빌드라 최적화된 내보내기 실행본보다 느리다. 실제 성능 수치와 실행 조건은 [BALANCE_perf](docs/BALANCE_perf.md)에 기록한다.

`-Profile`은 전체 및 30초 기록으로 분류한 국면별 Step 평균/p99/최대(ms)를 CSV에 추가한다. `-PostSeconds 300`은 판정 뒤 5분 동안 탄·미사일·이벤트 크기의 시작/최대/끝을 출력하고 수명·기록 상한을 검사한다. `--perf`는 자동 관전의 시작·10분·판정·결과 화면을 저장한다. `--autoplay-quit`는 결과 확인과 추가 5분 시뮬레이션 뒤 종료한다. FPS 최소·평균은 시작부터 각 시점까지 실제 벽시계로 측정한다. 전투 이벤트는 최대4,096개, 국면·분 단위 전력은 판정 시점에 고정한다.

스크린샷 모드(자동 검증용, `shots/`에 저장):

```powershell
.\tools\shot.ps1 이름 --control=BB-01 --look-at=DD-11 --turn=30,-10 --throttle=1 --frames=240 [--far] [--fixed-origin] [--zoom=1.5] [--speed=380] [--ram=BB-01] [--style=aircraft] ['--pips=3,1,4,0'] [--heat=1.1] ['--strafe=1,0'] [--roll=1] [--keep-ecm] [--launch=3] [--drill] [--drill-distance=20000] [--auto-decoys] [--no-ai] [--time-scale=16] [--order=attack] [--aim=engines] [--stern]
```

호위함·전함은 자동 사격통제를 사용한다. 자유·집중·무력화·중지·수동 교리가 있으며,
도면에서 선택한 모듈 → Y 조준 부위 → 교리 기본 조준점 순으로 결정한다.
사격 패널의 방위구에서 표적이 빨간 X로 찍히면 포각 밖이거나 선체에 가린 것이다. 표적 점이 초록 영역으로 들어오도록 Q/E로 롤하거나 기수를 돌린다.
검증 인자: `--yaw=1 --pitch=1 --doctrine=focus --below=8`(below는 연습 표적을 아래 8 km에 배치).
라디얼 검증: `--radial=power --radial-dir=90 --radial-hold-frames=60 --radial-release --frames=120`.
`--radial=gunnery`, `--radial=squad`, `--radial=drone --control=BB-01`로 같은 검증 입력을 사격·편대·드론 메뉴에 적용한다.
`--radial-dir`를 생략하면 중앙 취소를 검증하고, `--radial-release`를 생략하면 열린 메뉴를 찍는다.
전력 배분은 F 라디얼로 통일했다. 4는 드론 방어구역 라디얼이며 기존 5·0 핍 단축키와 6 AM 선택키는 해제했다. T 사격보조·교리, G/H/J 편대, F1~F8은 개발용으로 유지한다. F1 도움말에서 구분한다.
무기를 바꿀 때 누르고 있던 좌클릭은 다시 눌러야 발사한다. 망원 중에는 마우스로 중앙 조준선을 움직이고 R로 조준선 아래 탐지된 표적을 선택한다. 좌클릭은 선택 무기를 발사한다. 전함·호위함은 망원 중 주포를 임시 수동 조준하며, 해제하면 기존 사격 교리로 돌아간다. 포탑 선회율·사계·사선 제한은 그대로 적용된다.

망원 카메라는 함교 모서리 바깥의 수평 원을 따라 이동하므로 후방 관측도 함교에 가리지 않는다. 아래를 보면 갑판에 가릴 수 있으며, 이때 경고하고 수동 발사를 막는다. 요격함은 마우스 조준을 실제 기수 선회에 연결하고 전방포 사격각 안에 정렬되어야 발사한다. 기존 선회율·관성은 유지한다. 기존 HUD에 중앙 십자선·광학 눈금·배율·상대 방위/고각·기수 정렬 상태를 추가했다. 작은 화면의 AM 패널은 망원 중 왼쪽으로 옮겨 조준선을 비운다.

배율에 맞춰 감도가 낮아지고 시야각은 부드럽게 확대·복귀한다. 지도·라디얼·일시정지·커서 해제·함선 인계·창 포커스 해제 시 망원은 해제된다. 해제하면 휠로 정했던 추적 거리로 돌아오며, 대형함 관측 방향은 3초 유지 후 복귀한다. `--weapon-input-test`는 무기 선택과 망원 전환, `--telescope-test`는 실제 마우스 조준·중앙 표적 선택·발사·요격함 기수 연동을 검사한다. `--shot=... --telescope`로 확대 화면을 촬영할 수 있다.
편대 요격은 2초마다 내 20 km 안의 식별된 적 요격함을 분산 배정하고, 없으면 호위한다.
복귀는 사격 표적 없이 대형으로 재집결한다. 선택한 아군의 다른 편대를 지휘하는 기능은 아직 없다.

## 비행보조와 선회

- 기본은 플로팅 원점과 비행보조 ON(우주식)이다. V로 항공식과 바꿀 수 있다.
- 항공식: 기수 선회를 속도에 묶는다. 고속에서는 넓게 돌고, 저속에서는 빠르게 선회한다. 큰 선회 입력은 자동으로 감속한다. W/S로 정한 스로틀은 유지하며, 방향이 맞으면 재가속한다.
- 우주식: 기수는 속도와 무관하게 함종 최대 선회율로 돈다. 이동 방향은 비행보조가 횡추력을 먼저 써서 기수 쪽으로 맞추고, 남는 G로 전후 가속한다. 자동 감속은 없다. 요격함 380 m/s에서 90° 꺾으면 기수는 약 1초, 이동 방향은 약 10초 뒤 정렬되며 속도는 250 m/s 이상 유지된다.
- 이동 방향 단서(두 방식 공통): 카메라 주변 우주 먼지가 내 속도 반대로 흘러간다(줄무늬가 퍼져 나오는 점이 진행 방향). HUD에 진행 ◇·역진행 ⊗, 화면 밖이면 가장자리 주황 화살표, 1~5초 뒤 예측 위치 점, 미끄럼 각도와 정렬 예상 시간을 표시한다.
- 전진·제동·횡추력을 합산해 전함 0.5G, 호위함 2G, 요격함 5G로 제한한다. 부스트에도 같은 상한을 적용한다.
- HUD의 파란 원은 기수, 노란 마름모는 실제 이동 방향이다. 현재 G와 선회 감속 상태도 표시한다.
- Z로 보조를 끄면 자동 감속과 속도에 따른 기수 선회 제한이 해제된다. 추력 없이 기수만 돌려도 기존 이동 속도는 유지된다. G 상한은 유지된다.
- G는 무게중심의 병진 가속도 기준이다. 승무원 위치에 따른 회전 가속도는 아직 모델링하지 않는다.

## HUD

글자 대신 도형·게이지로 읽는다. 글자는 호출부호·거리·피해 리포트·발사 실패 사유에만 쓴다.

- 요격함 조준선: 왼쪽 호 = 남은 탄약, 오른쪽 호 = 재장전(초록으로 가득 차면 발사 준비, 빨강이면 주포·전력·탄약고 손상). 조준선이 초록이면 선행 보정 중, 주황이면 사격보조 OFF. 명중하면 X자 히트마커(파랑 실드 · 주황 장갑 · 빨강 모듈, 굵으면 모듈 파괴).
- 호위함·전함 사격 패널(하단 계기판 오른쪽): 왼쪽 고리 = 교리(가운데)·탄약(왼쪽)·재장전(오른쪽)·미사일(아래)·디코이(위). 가운데 = 교전 표적 호출부호·거리, 잠금 대기·사거리 밖·장갑·아군 사선일 때만 짧은 사유.
- 사격 방위구(사격 패널 오른쪽): 함선 기준 전 방향. 가운데 = 기수, 가장자리 = 함미, 위쪽 = 함선 위쪽(▼ 눈금). 초록 원 = 주포 포각, 그 안의 빨간 부분 = 자함 선체가 가리는 방향. 교전 표적은 쏠 수 있으면 초록 점, 못 쏘면 빨간 X. 글자 경고는 없다.
- 교전 표적이 포각 밖·선체 가림이면 화면 속 표적에 빨간 ⊘가 겹치고, 선행점도 빨갛게 바뀐다.
- 화면 밖 방향(가장자리 띠, 바깥부터): 나를 노리는 미사일 = 깜박이는 빨간 채운 삼각형, 적 함선(식별·80 km 이내) = 빈 빨간 화살촉 + 함종 점, 사격 표적 = 굵은 화살촉 + 고리(쏠 수 있으면 초록 고리에 함종 점, 못 쏘면 빨간 ⊘), 진행 방향 = 주황 화살표 + ◇. 아래쪽은 하단 패널 위에서 멈춘다.
- 선행 표시: 초록 사각형 = 발사 방향, 옅은 원 = 관측 오차, 둘레 호 = 비행 시간(15초에 한 바퀴).
- 하단 중앙 계기판: 속도 막대(▶ 스로틀 목표, 가로선 순항 한계, 위쪽 옅은 구간 부스트), 미끄럼 다이얼(가운데 기수, ◇ 실제 이동 방향, 안쪽 원 90°·바깥 원 180°, 둘레 호 = 정렬까지 남은 시간), G 게이지, 상태 칩(보조·방식·부스트·사격보조 또는 선회 감속).
- 하단 왼쪽: 자함 실드 막대(오른쪽 빨간 구간 = 손상으로 줄어든 최대치)와 계통 막대 7개(좌전·우전·추진·자세·무장·센서·냉각, 파랑 정상·주황 저하·빨강 위험, X 정지). 충돌하면 테두리가 빨갛게 된다.
- 오른쪽 위 표적 패널: 호출부호·함종 점(●●● 전함, ●● 호위함, ● 요격함)·거리(주황 = 내 주포 사거리 밖), 실드 막대, 상면·측면 도면(모듈을 체력 색으로 칠하고 파괴는 X, 방금 맞은 모듈은 흰 테두리), 계통 막대, 최근 피해 리포트 4줄.
- 표적 브래킷: 함종 점, 선택한 표적은 굵게, 격침은 X.
## 전력과 폐열

- 핍 8개를 추진·실드·무장·센서에 0~4개씩 나눈다. 2핍이 기준(성능 1.0)이고 0~4핍은 성능 0.3·0.65·1.0·1.25·1.5배, 소비 전력 0.15·0.5·1·1.5·2배다.
  - 추진: 모든 병진 가속(전진·제동·횡추력). G 상한은 그대로다.
  - 실드: 재충전 속도. 무장: 재장전 속도. 센서: 사격통제 관측 오차(4핍이면 오차 ÷1.5).
- 채널은 일할 때만 전력을 끈다(추진 = 가속 중, 실드 = 재충전 중, 무장 = 재장전 중, 센서 = 항상). 쉬는 채널은 10%만 쓴다.
- 추진 채널은 전방 가속을 메인 추진 단가로, 횡·상하·제동·후진 가속을 그 30%(보조 추진기) 단가로 센다. 회전 자체는 전력을 쓰지 않는다. 요격함이 380 m/s에서 기수를 3° 틀 때 비행보조의 미끄럼 보정은 메인 추진 최대의 약 38%를 쓴다(같은 단가일 때는 114%).
- 보조 추진기는 모든 함종에 같은 규칙으로 보인다: 함수·함미마다 좌·우 노즐 1개씩과 좌우로 갈라 단 상·하 노즐 2개씩, 함수 좌우 바깥에 앞으로 분사하는 역추진 노즐 2개. 평행이동·제동, 피치·요(함수와 함미가 반대로 분사), 롤(좌상·우하처럼 대각으로 분사)에 맞춰 분사한다. 분사 축을 정면으로 보면 어둡게 해서 하얗게 번지지 않는다.
- 반응로·발전기는 발전량을, 전력망(버스)은 연결만 정한다. 수요가 가용 발전량을 넘으면 모든 채널이 같은 비율로 깎인다(전압 강하). 건강한 함선은 기준 배분으로 모든 채널을 최대로 써도 정격의 80%만 쓴다. 전함이 주반응로를 잃은 채 전부 쓰면 공급 약 73%.
- 소비 전력은 모두 열이 되고, 레일건 발사는 한 발마다 열을 더한다. 냉각 모듈이 열을 빼낸다. 열 용량을 넘으면 과열: 모든 채널 절반, 레일건 발사 불가. 70% 아래로 식으면 회복한다.
  - 부스트만 계속 쓰는 것은 냉각이 감당한다. 요격함이 부스트·연사·실드 재충전을 겹치면 약 20초에 과열되고 손을 떼면 약 6초 뒤 회복한다. 냉각 모듈을 모두 잃으면 대기 상태로도 약 90초에 과열된다.
- 수치는 `data/ships/*.json`의 `power`(정격 발전, 채널별 기준 소비, 열 용량, 냉각)와 `railgun.shotHeatMj`에 있다.
- HUD 하단 오른쪽: 발전 막대(채움 = 가용 발전, 흰 선 = 수요, 빨강 = 부족분), 채널별 핍(기준과 다르면 이름에 색)과 실제 소비 막대(약 0.3초로 부드럽게 표시), 열 막대(회색선 70% 회복, 빨간선 100% 과열, ▲ = 열이 오르는 중). 과열이면 테두리가 깜박이고 계기판에 "과열" 칩, 전압 강하면 "전력 부족" 칩이 뜬다.
## 센서와 전자전

- 진영별 센서망이 0.25초마다 적 함선마다 탐지 단계를 정한다. 같은 진영은 데이터 링크로 공유하며, 표적마다 가장 잘 보는 아군의 값을 쓴다.
  - 미탐지: 화면에 없다. 검사 표적(R)으로도 고를 수 없다.
  - 접촉: 추정 위치에 "?" 마름모와 위치 오차 원. 함종·호출부호를 모른다. 표적 패널은 "미식별 접촉".
  - 식별: 브래킷·함종 점·호출부호. 아직 사격통제 해가 없다.
  - 잠금: 브래킷 안 마름모. 사격보조(선행 조준)는 잠금일 때만 동작한다. 수동 사격은 언제나 가능하다.
- 신호 = 관측 센서 세기 × 표적 신호 ÷ 거리(km)². 기준은 접촉 1, 식별 3, 잠금 8이고, 떨어질 때는 기준의 80%까지 버틴다.
- 추정 위치 오차(거리 × 2% ÷ √신호)는 몇 초에 걸쳐 천천히 흐른다. 화면은 매 프레임 표적의 실제 이동에 이 오차를 더해 그리므로 4Hz 갱신마다 튀지 않는다. 화면에서 가깝거나(약 36픽셀) 오차 원이 크게 겹치는 접촉은 묶음 하나로 그린다: 겹친 마름모, 구성원 오차 원을 모두 감싸는 원, "? ×3 147 km"(가장 가까운 구성원 거리). 한 번 묶인 접촉은 조금 멀어져도 묶음을 유지해 경계에서 깜박이지 않는다. R로는 구성원을 하나씩 고를 수 있고, 표적 패널에 "미식별 접촉 · 묶음 3"으로 나온다. 식별 이상은 묶지 않는다.
  - 관측 세기 = 데이터 `sensors.strength` × 센서 모듈 상태 × 센서 채널 배율(핍).
  - 표적 신호 = `sensors.signature` × (1 + 0.5·엔진 출력 + 0.5·열 비율). 엔진을 태우거나 뜨거우면 잘 보인다.
  - 기본 거리(전함 센서, ECM 없음): 전함 접촉 339·식별 196·잠금 120 km, 호위함 잠금 약 54 km, 요격함 잠금 약 21 km. 150 km에서 시작하면 처음엔 흐릿한 접촉만 보인다.
- ECM(다섯째 전력 채널, 키 5): 기본 핍 0(꺼짐). 켜면 상대의 식별·잠금 신호를 (1 + 방해)로 나눈다. 방해 = `sensors.jammer` × ECM 배율 ÷ 관측 센서 배율이라, 센서 핍(ECCM)을 올리면 방해가 줄어든다. 대신 방해 전파 때문에 접촉 신호는 (1 + 2·ECM 배율)배가 되어 더 멀리서 "무언가"로 잡힌다. 잠금 중에도 사격통제 오차가 √(1+방해)배 커진다.
  - 예: 전함 대 ECM 켠 전함은 잠금 거리 120 → 약 69 km. 90 km에서 식별에 머물고, 센서 4핍(무장 0)으로 올리면 잠금된다.
- 적 전함·호위함은 기본으로 ECM 2핍을 켜고 온다(무장·센서 1핍씩). 요격함은 켜지 않는다. F7 연습 표적은 ECM을 끈다(`--keep-ecm`이면 유지).
- HUD: 적 브래킷의 물결 표시 = ECM 방해 중. 표적 패널의 3칸 막대 = 접촉·식별·잠금. 계기판 "ECM" 칩 = 내 ECM 켜짐.
## 미사일·디코이·근접방어

- 미사일(2 선택 후 좌클릭)은 접촉 이상으로 탐지된 적에게 쏠 수 있다. 수직 발사관에서 위로 사출한 뒤 스스로 꺾는다.
  - 중간 유도: 발사 진영 센서망의 추정 위치(식별 이상이면 속도도). 센서망이 놓치면 마지막 목표점으로 계속 난다.
  - 종말 유도: 탐색기가 시야각·사거리 안의 적 함선과 디코이 중 신호(÷ ECM 방해)에 비례한 확률로 고른다. 0.5초마다 다시 고르며, 원래 표적에 1.5배 가중을 준다.
  - 조종: 비례항법 요구를 실제 기수 회전과 엔진 편향 한계로 실행한다. 기수 회전 상한은 전함/호위함/요격함 미사일 각각 초당 90/120/160°, 엔진 편향은 10°다. 추력 명령은 현재 진행 방향의 전방·측방 90° 이내로 제한한다. 속도가 높을수록 같은 횡가속으로 도는 반경이 커지므로 빗나간 미사일이 바로 급제동·반전하지 못한다. 큰 선회 후 재공격은 가능하지만 그동안 연료와 비행 수명을 소모한다. 연소 종료 후에는 관성 비행하며 수명이 끝나면 소멸한다. 몸체와 추진광은 속도 벡터와 구분된 실제 기수 방향을 표시한다.
  - 근접신관·실드 외피·장갑·모듈 피해와 기존 탐색기 시야·센서망 중간 유도는 유지한다. 반물질 강습어뢰는 별도의 고정 발사축·종말 유도 규칙을 사용한다.
  - 함종별: 전함 24발(25G, 탐색기 20 km), 호위함 16발(30G, 15 km), 요격함 4발(40G, 8 km). 재장전은 무장 채널을 따르고, 발사마다 열이 오른다. 탄약고가 모두 부서지면 쏠 수 없다.
- 디코이(C): 함선 기본 신호의 2.5~3배로 빛나다 4~6초에 걸쳐 꺼진다. 탐색기가 신호 비율만큼 끌려가 디코이 옆에서 헛되이 터진다.
- 근접방어: 포대마다 사거리 안의 가장 가까운 적 미사일을 자동으로 쏜다(전함 측면 포탑 8기·4.5 km·초당 8발·0.08, 호위함 4기·4.5 km·초당 12발·0.09, 요격함 상·하부 2기·1.2 km). 미사일 체력은 전함 16·호위함 12·요격함 6(한 발 4). 명중률은 가까울수록, 가로지르는 속도가 느릴수록, 센서·무장 채널이 높을수록 오른다. 미사일은 몇 발 맞아야 떨어진다. 주변 아군 함선의 근접방어도 함께 쏜다.
- 검증 수치(2026-10-10, `check-sim`): 호위함 미사일은 60 km 정지 전함에 20.3초, 30 km에서 200 m/s로 횡이동하는 호위함에 14.5초에 명중. 40 km 호위함을 전함 미사일 6발씩 네 방향에서 시험하면 방어 없음 24/24 명중, PD 있음 3발 요격·21발 명중. 단일 정면 6발에서 디코이만 사용하면 1발 명중. 전투단(전함+호위함 2)에 30/60 km·네 방향에서 8발씩 공격하면 방어 없음 64/64 명중, 방어 있음 7발 요격·57발 명중. 포대 사각과 결정적 확률 때문에 한 방향의 한 번 사격보다 여러 방향의 결과를 함께 검사한다.
- 통과 후 재공격 검사: 2,500 m/s로 요격함을 스치는 호위함 미사일은 재접근까지 약 35초가 걸리고 비행 수명 내 재명중하지 못한다. 이미 뒤쪽에 있는 저속(200 m/s) 미사일은 약 15.5 km까지 벌어지는 큰 선회 후 33.2초에 재명중한다. 특정 정지 표적 조건의 측정이며 모든 교전의 고정 시간은 아니다.
- HUD: 내 미사일 파란 갈매기(탐색기 잠금이면 채움), 적 미사일 빨간 삼각형(나를 노리면 크게·채움, 화면 밖이면 가장자리에서 깜박이는 빨간 채운 삼각형), 계기판 "미사일 N" 경보 칩. 조준선 위 호 = 미사일 잔량, 아래 호 = 디코이 잔량. 3D에서는 미사일 화염 줄, 디코이 섬광, 근접방어 예광(맞으면 주황), 폭발·요격 섬광.
## 반물질 강습어뢰

요격함은 전방포·일반 미사일 4발과 별개로 반물질 강습어뢰 2발을 탑재한다. **3**으로 선택하면 SAFE → ARMING(2.5초) → ARMED, 좌클릭으로 발사한다. **1 또는 2**로 다른 무기를 선택하면 준비를 취소하고 SAFE로 돌아간다. 준비 중 3을 다시 눌러도 진행은 유지된다. 발사 후 SAFE로 돌아오며 다음 탄은 좌클릭 또는 3으로 다시 준비한다. **Backspace를 1초 유지**하면 남은 탄두를 모두 투기한다. 일시정지·지도·메뉴는 투기 유지 입력을 취소한다. 발사·투기·유폭으로 잃은 탄두는 F6 수리나 F7 무장 초기화로도 보충되지 않고 새 전투에서만 복구된다.

- 권장 2~5 km, 전방 발사각 15°. 450 m/s 사출·22G 가속·7초 수명이며 실제 이동 경로가 8 km에 도달하면 피해 없이 소멸한다. 모함 속도를 상속하지만 부스트로 최대 비행거리를 늘릴 수 없다. 탐색기 3.5 km·시야각 35°, 종말 횡가속 6G로 제한하고 분리 뒤 센서망 중간 유도는 사용하지 않는다. ECM·디코이에 영향을 받으며 PD와 방어 드론으로 요격할 수 있다.
- 선행 조준은 발사함 속도·표적 속도·부위 회전 속도와 어뢰 가속을 함께 계산한다. 엔진 추력은 발사 자세를 기준으로 작용하며 상속한 횡속도 방향을 증폭하지 않는다. 종말 유도는 같은 가속 모델로 궤도를 보정하되 6G 제한을 유지한다. AI는 준비 중 어뢰 선행 방향으로 기수를 맞추고, 플레이어는 AM 선택 시 `AM 비행시간`이 붙은 전용 선행점을 본다. 주포의 사격보조 계산은 별도로 유지한다.
- 실드 외피 또는 선체에 직접 접촉하면 실드 → 장갑 → 내부 모듈 관통을 적용한다. 피해 에너지 1,100, 관통 2,400, 모듈 피해 1,200, 내부 진행 깊이 180 m의 임시값이다. 내부 진행 깊이는 실드가 아닌 선체 진입점부터 계산한다. 온전한 전함 실드(1,200)는 첫 발을 막는다. 실드가 소진된 엔진 구획에 정확히 맞히면 해당 추진기를 파괴하지만, 반대편 구획까지 통째로 지우는 광역 폭발은 없다. 장갑은 기존 면별 두께·관통 모델이며 별도의 누적 장갑 HP는 없다.
- 전용 `am-containment` 모듈은 우현 내부에 있으며 HP 40이다. 잔탄이 있을 때 **이 모듈에 실제 피해가 들어온 경우에만** 유폭을 판정한다. 건전성 85% 미만은 HUD 경고, SAFE에서는 15% 이하, ARMING/ARMED에서는 65% 이하가 되면 격리 실패로 격침한다. 이미 65% 이하로 손상됐으면 준비를 시작할 수 없다. 일반 선체·다른 모듈 피격이나 전력 상실은 임의 유폭을 일으키지 않는다. 준비 중 전력 상실·과열은 SAFE로 중단한다.
- 하단 패널은 AM 잔탄·준비 상태·격리 건전성·유효거리·투기 진행을 표시한다. 격리부 발광, 짧고 밝은 추진광, 0.22초 에너지 섬광과 파편을 추가했다. 명중·격리 실패와 무해한 소멸·요격을 구분한다. 준비 완료·발사·투기 소리는 기존 음원을 재사용하며 기존 효과음 음량·음소거를 따른다.
- AI 요격함은 주력함 후미 배면 진입 구역에서 6.5 km 이내 준비, 5 km 이내 발사 후 6초 이탈한다. 격리 경고가 나면 투기한다. 호위함은 식별한 근접 AM 탑재 요격함을 우선 공격하고 전함은 롤로 상부 방어를 돌린다. 실드는 현재 전 방향 단일 풀이라 방향별 실드 잔량을 골라 노출하는 동작은 아직 없다.
- 전함 방어 드론 8기는 실제 위치에서 미사일·어뢰를 요격한다. **4 유지 → 방향 → 떼기**로 전방·후방·좌현·우현 집중 방어 또는 전방위 경계를 선택한다. 방향은 카메라가 아닌 모함 기준이며 집중 구역은 수평 방위 90°로 상하 접근도 포함한다. 구역 밖 적탄은 쏘지 않으므로 한쪽 집중 시 반대쪽 방어가 빈다.
- 기본/AI는 전방위 경계. 드론은 반경 900 m의 선체 바깥 경로를 따라 최대 240 m/s로 재배치한다. 사거리 1.8 km는 드론별 실제 위치 기준이며 선체 가림을 검사한다. 초당 3발·기체당 80발·총 640발, 명중/피해 수치는 기존과 같다. 방향 변경·대기로 재보급되지 않는다. 센서/발전 상실 시 통제가 멈추며 복구되면 기존 명령을 이어간다. 개발용 무장 초기화만 잔탄과 명령을 초기화한다.
- 전력 패널 위에 방어 방향·실제 드론 위치를 나타낸 소형 도면·재배치 수·생존/무장 기체 수·잔탄·탄체 요격/요격함 명중 수를 표시한다. 월드의 작은 마름모와 발사 시 링으로 자기 드론을 식별한다. 미탑재 함선은 4 입력 시 안내만 표시한다.
- 드론은 미사일·어뢰를 우선 요격하고, 없으면 지정 방어구역 안의 적 요격함을 공격한다. 피해는 기존 실드 → 장갑 → 모듈 경로를 사용한다(임시 에너지 10·관통 30 mm·모듈 피해 6). 사거리 1.8 km·연사 3발/s·80발 탄창을 탄체 요격과 공유한다. 횡단 속도·모함 센서/무장 전력이 명중률에 영향을 주며 다른 선체를 관통해 사격하지 않는다.
- 기체마다 HP 8을 따로 갖는다. 적 PD/요격함 보조 포탑의 탄당 피해 4에는 두 번의 실제 명중으로 파괴된다. 주포도 반경 4 m 드론 판정구에 직접 맞힐 수 있으며 이동 중 연속 충돌과 더 가까운 선체의 가림을 검사한다. 격추된 기체는 사격·이동·가용 잔탄에서 제외되고 짧은 섬광/파편을 남긴다. 방향 전환·모함 수리로 복구되지 않으며 새 전투 또는 개발용 무장 초기화로만 복구한다. 모함 격침 시 드론 운용도 종료한다.
- **요격함 보조 포탑 2기는 자동으로 미사일/어뢰 → 적 드론 → 적 요격함 순서로 대응한다.** 사거리 밖 조기 추적보다 사거리 안 표적을 우선한다. 후방 상·하부를 각각 맡으며 상부 포탑은 수직 핀 뒤의 갑판에 설치한다. 포탑마다 사거리 1.2 km, 수평 90°/s·고저 60°/s, 담당 후방 중심 좌우 100°·각 갑판 기준 -5~85°로 제한된다. 포신 오차가 1.5° 이하여야 발사하며 전방 사각과 빠른 근접 횡단 표적에 대한 사격 공백이 남는다. 적 드론의 실제 위치·기동 속도를 쓰고 선체 뒤의 드론에는 쏘지 않는다. 대형함 PD도 드론을 공격할 수 있지만 미사일과 요격함 방어를 우선한다.
- 요격함 HUD에 상·하부 포탑 각각의 추적/사격 상태와 드론 격추 수가 나온다. 가까운 적 드론에는 붉은 마름모·2 km 이내 내구도 막대가 표시되며, 격추 확인음은 기존 음원과 음량 설정을 재사용한다. 드론의 함선 간 충돌·직접 선택 공격·발진/회수는 후속 범위다.
- 드론 검증: `dotnet run --project tests/SimChecks -- --drones`. 방어구역 76개와 전투 48개 검사. 전방 2.5 km 정지 적탄, 배치 완료 후 3초 발사량은 전방위 12발 / 전방 집중 64발 / 후방 집중 0발이다. 상·하부 단독 포탑 모두 기본 드론 격추 6.92초/32발, 5초 횡단 시험은 80 m/s 표적 22발 / 1,200 m/s 표적 2발이다. 상하 표적 전환과 기체 롤 후 사계도 검사한다. 모두 단독 기능 시험이며 전체 전투 요격률·승률로 해석하지 않는다.

검증은 전체 Sim 767개(AM 144개), 실제 게임 AM 입력·모델·음향 21개다. 정지 표적 128회와 수정 전후 동일 40판 비교는 [밸런스 기록](docs/BALANCE_stage7.md#반물질-비행-수정과-40판-비교-2026-10-08)에 있다. 방어가 있는 상부 접근은 모두 요격됐고 후미 배면 3.5~5 km 접근은 각각 8발 중 5발이 통과했다. 횡속도·가속 선행 수정으로 전면전 명중률은 47/228(20.6%) → 127/237(53.6%)가 됐다. 승률은 수정 전 Blue/Red 20/20, 수정 후 21/19였다. 초기 8판의 1/7만으로 고정 진영 편향을 판단하지 않으며, 40판 결과도 모든 편성의 균형을 보장하지는 않는다.

## 침투와 부위 조준

- 주력함은 면마다 장갑이 다르다. 전함은 함수 500 mm·측면 300 mm·배면 220 mm·후미 엔진 구획 80 mm, 방열판 8 mm. 요격함 레일건(관통 250 mm)은 정면·측면은 못 뚫지만 후미·방열판은 뚫는다.
- 방열판 판 안에 냉각 모듈(좌·우현 방열판)이 있다. 부수면 냉각이 줄어 과열이 빨라진다.
- 근접방어 포대마다 사계가 있다(바라보는 방향에서 100°). 전함 포대 8기는 모두 상부라 배면 아래·후미 아래가 사각이고, 전투단 호위함(하부 포대 포함)이 그 사각을 메운다. 미사일이 없으면 근접방어가 사계 안의 적 요격함도 쏜다(실드부터 깎는 약한 탄, 요격함은 미사일보다 맞히기 쉽다). 전함 위 2.5 km의 요격함은 5초에 실드를 잃고, 아래 2.5 km에는 한 발도 못 쏜다.
- Y로 사격보조 조준 부위를 바꾼다(중심·추진기·방열판·주포·센서). 표적 위에 그 부위가 마름모로 뜨고, 지금 내 포구 위치에서 그 면 장갑을 뚫을 수 있으면 초록 "관통", 아니면 빨강 "장갑 N mm"(돌아 들어가야 한다). 실드가 남았으면 파란 호. 표적 패널 도면에서도 그 모듈이 초록 테두리로 강조된다. 고른 종류 중 내게 가장 가까운 살아 있는 모듈을 노린다.
- AI 요격함은 식별된 주력함을 공격할 때 표적 후미 아래 진입 구역(35°)으로 우회한 뒤(표적 곁을 스치면 바깥 경유점) 엔진, 엔진이 없으면 방열판을 노리고 돌진·이탈을 되풀이한다. 실드가 없고 장갑을 못 뚫는 각도에서는 쏘지 않는다.
- 모듈 피해는 "탄이 모듈을 지난 길이 ÷ 그 방향으로 모듈 중심을 지나는 길이"로 계산한다(이전에는 모듈 대각선으로 나눠 얇은 판 모듈이 거의 피해를 받지 않았다).
- 검증: 정면 25 km에서 시작한 AI 요격함 1척이 근접방어를 피해 후미 아래로 들어가 약 40초에 첫 엔진 피해, 혼자 둔 전함의 추진을 4분 안에 0%로 만든다(요격함 손실 없음). 실전에서는 전투단 호위함이 이를 막아야 한다.

  | 호위 전대 | 호위함 4 (DD-31~34 / DD-X3~X6) | 쐐기 대형으로 측면 기동(표적에서 50 km 앞·40 km 옆)하며 적 호위함에 미사일, 70 km 안이면 전원 측면 공격. 적 요격함이 기함 30 km 안이면 기함 둘레 3 km로 돌아와 방공 |
  | 요격 편대 | 요격함 5 (IC-21~25 / IC-X1~X5) | 기함 앞 8 km 경계 → 60 km 안 적 요격함은 나눠 요격 → 적 함대가 기함 50 km 안이면 2.5 km 안으로 집결(최대 20초) 후 5척이 실드가 가장 약한 표적(호위함 우선)에 동시 돌격 |
- 플레이어는 지금 탄 함선의 편대를 지휘한다(G 선택한 적 공격·H 나를 호위·J 위치 유지). 나머지 아군 편대와 적 함대는 함대 지휘관이 2초마다 역할대로 움직인다. Tab으로 다른 편대 함선에 타면 그 편대가 내 지휘로 오고, 이전 편대는 지휘관에게 돌아간다. 시작은 요격 편대 선두 IC-21.
- AI는 진영 센서망이 아는 것만 쓴다. 접촉뿐인 적은 함종을 모르므로 가까운 것부터 고른다(ECM으로 식별을 막으면 엉뚱한 표적을 고르게 된다). 무력화된 적은 뒤로 미룬다.
- 함선 행동: 전함 60 km·호위함 30 km 대치(잠기지 않으면 60%로 접근), 요격함 접근 → 6 km 사격 → 1.5 km에서 4초 이탈, 10초 최근접 예측 충돌 회피. 레일건은 잠금 + 비행 시간 기준(8·5·2.5초) + 아군 사선 확인. 미사일은 같은 표적을 노리는 함선들의 일제 사격 창(8초·함선당 2발·25초 간격, 곧 사거리에 들 아군을 기다림). 미사일 사거리(전함 140 km·호위함 110 km)가 레일건보다 길어 미사일전이 먼저 온다.
- 전력: 전함·호위함 기본 ECM 2핍(2/2/1/1/2), 요격함 끔. 미사일 위협 시 근접방어 배분(1/2/2/3/0), 방해로 잠기지 않으면 ECCM(2/1/1/4/0), 열 85%면 ECM 끔. 미사일 6 km 안이면 디코이.
- 무력화: 발전이 없거나 추진·자세 제어를 모두 잃으면 스스로 움직이지 못하고 관성으로 흐른다. AI가 멈추고, 식별된 경우 브래킷에 가로줄과 "무력화"가 붙는다.
- HUD: 하단 왼쪽 편대 현황(▶ 내 편대, 구성원 점 = 파랑 정상·주황 손상·빨강 무력화·X 격침, 행동), 공격 중인 아군 → 표적까지 점선, 위치 유지 아군 → 작은 사각형, 배속 칩.
- 검증(`check-sim`): 전투단 대형·같은 표적, 요격 편대 집결 → 동시 돌격 → 요격 전환·분산, 호위 전대 측면 기동 → 방공 복귀, 대형 유지·충돌 회피·결정성·무력화, 24척 20분 전면전(편대 행동 전부 등장, 충돌 0, 약 절반 격침·무력화).
## 함선 간 충돌

- 주선체·함교·날개·방열판을 각각 근사한 충돌체를 사용한다. 큰 구 하나로 둘러싸지 않아 전함 옆을 가까이 통과할 수 있다.
- 함종별 질량을 반영해 부딪히고 미끄러진다. 고속에서 한 틱 사이에 선체를 통과하는 것도 검사한다.
- HUD에 충돌 상대, 접근 속도, 충돌로 바뀐 속도를 잠시 표시한다. 5G 같은 추력 상한은 충돌 충격을 막지 않는다.
- 충돌 피해는 비탄성 충돌로 사라지는 운동에너지(½·환산질량·접근속도²) 기준이며, 같은 에너지가 양쪽 선체에 모두 들어간다. 무거운 쪽도 접촉 구획이 파쇄된다.
- 에너지가 함선 질량 × 1만 J/kg을 넘으면 선체가 붕괴한다(고정된 벽에 약 141 m/s). 넘지 않으면 접촉점에서 선체 안쪽으로 파쇄 피해가 들어가며, 장갑·모듈 관통은 사격과 같은 계산이고 실드는 무시한다. 같은 에너지라도 작은 함선일수록 크게 부서진다.
- 예: 요격함이 전함 후미를 380 m/s로 들이받으면 요격함은 붕괴하고 전함은 접촉 구획 모듈 2개가 손상된다. 60 m/s면 요격함만 모듈 2개가 손상된다. 약 3 m/s 이하의 접촉은 피해가 없다.
- 충격에 의한 각속도 변화는 아직 없다. 방어 드론은 요격 사격에 참여하지만 함선 간 충돌 대상은 아니다.
- 검증용 `--ram=BB-01`은 조종함을 표적 뒤에 배치한다. `--speed=380 --throttle=1`과 함께 접근 충돌을 재현할 수 있다.

## 피해 모델

- [data/ships/](data/ships/)의 JSON이 함종별 기동 수치, 충돌 선체, 실드, 면별 장갑, 내부 모듈 배치를 정의한다. 빌드에 포함되므로 데이터 수정 후 다시 빌드한다.
- 사격은 실드 → 입사각·경사를 반영한 장갑 → 경로에 놓인 내부 모듈 → 출구 장갑 순으로 계산한다. 겹친 선체 부품 내부에는 외부 장갑을 중복 적용하지 않는다.
- 모듈 손상에 따라 전력·추진·자세 제어·무장·센서·냉각 성능이 내려간다. 기동, 부스트, 엔진 화염, 실드 회복, 주포 발사·재장전과 사격통제 오차에 실제로 반영된다. 탐지·식별은 센서 단계에서 구현한다.
- 좌현·우현 전력망과 반응로·보조 발전 계통을 따로 계산한다. 좌현 전력망이 끊겨도 우현 계통은 남고, 양현 공용 장비(센서 등)는 살아 있는 쪽 전력망에서 전력을 받는다.
- 발전에는 25% 여유가 있다. 발전 손실이 그 안이면 어떤 계통도 약해지지 않는다. 반응로·발전기는 체력 50% 이상이면 정격 출력, 미만이면 출력 50%("출력 저하"), 파괴되면 0이다. 반응로 체력이 곧 함선 전체 성능이 되지 않는다.
- 에너지가 충분한 탄약고·반응로 파괴는 데이터의 낮은 확률로 치명 파괴를 일으킨다. 충돌 파쇄도 마찬가지다.
- 실드는 피격 후 일정 시간이 지나야 회복한다. 전력·냉각·실드 발생기 상태에 따라 회복률과 최대 용량이 내려간다.
- R로 검사 표적을 고르고 F5로 배치를 확인한다. F4를 반복해 실드를 소진시킨 뒤 원하는 모듈을 조준하면 오른쪽에 손상과 피해 리포트가 표시된다. F6으로 복구하며 반복 검증할 수 있다.
- F4는 피해 검증용 즉시 레이다. 좌클릭의 실제 레일건은 탄속·재장전·탄약·사격통제를 반영한다. 전력 소비·폐열·도탄은 아직 없다. 격침된 선체는 관성을 유지하고 충돌·차폐에 남는다.
- 임시 모델을 교체할 때 JSON의 선체 구획·장갑·모듈 위치와 연출의 추진기 번호를 함께 맞춘다. 좌표는 로컬 기준 m, -Z 전방·+Y 위·+X 우현이다. 피해·관통·충돌 수치는 게임 조정용이다.

좌현 전력망 단절 재현(8회 시험 사격):

```powershell
.\tools\shot.ps1 damage_port --damage-test=BB-01 --module=bus-port --pulses=8 --frames=210
```

검증은 `tools/check-sim.ps1`의 실제 시뮬레이션 코드로 수행한다. 실드 지연 회복, 입사각과 면별 장갑, 순서별 관통, 전력 계통 중복성, 치명 파괴·복구, 큰 좌표의 정밀도와 충돌 피해를 포함한다.

## 레일건과 사격통제

- 함선 JSON의 `railgun`에서 연결할 주포 모듈, 로컬 포구 위치, 탄속·재장전 시간·탄약·관통력·사거리·주포 사각·관측 오차를 정의한다. 현재 함종별 주포 한 기를 연결했다.
- 탄은 발사 함선의 속도를 이어받아 직선으로 비행한다. 위치는 double이고, 240Hz 구간마다 탄과 선체의 상대 이동 경로를 검사한다. 명중 시 앞 단계의 실드·장갑·모듈 피해로 이어진다. 첫 선체에서 탄을 소모하며 함선 여러 척을 연속 관통하지 않는다.
- 사격통제 표적은 검사 표적(R) 중 살아 있는 적일 때만 잡는다. 기본 검사 표적은 가장 가까운 적이며, 아군을 고르면 "사격통제 없음"으로 표시한다. 수동 사격은 아군에게도 맞는다.
- 사격보조 ON: 선택 표적의 상대 위치·속도로 등속 선행 조준을 계산한다. 표적이 조준선에서 8° 안에 있을 때 발사 방향을 보정한다. 초록 사각형은 선행 발사 방향이며 예상 비행 시간과 관측 오차도 표시한다. 함종별 주포 사각을 넘거나 자함 선체가 포구를 가리면 발사하지 않는다.
- 사격보조 OFF(T): 조준선이 가리키는 현재 지점으로 발사한다. 표적의 이동은 직접 예측해야 한다. 센서가 파괴되어도 수동 사격은 가능하다. 현재 보조는 함선 중심을 겨냥하므로 개별 모듈 정밀 조준에는 수동 사격을 사용한다.
- 센서 손상이 클수록 관측 오차가 커진다. 오차는 재현 가능한 4Hz 관측을 보간한 임시 모델이다. 표적이 발사 뒤 가속·선회하면 기존 탄은 유도되지 않는다. 실제 탐지·식별·전자전 오차는 5단계에서 확장한다.
- 주포·전력망·탄약고 손상과 탄약 소진은 발사를 막는다. 주포 출력·냉각 저하는 재장전을 늦춘다. F6은 피해뿐 아니라 주포·탄약·비행 중인 탄도 초기화한다.
- F7로 이동 표적을 배치하고 좌클릭으로 쏜다. T를 눌러 같은 표적의 현재 위치에 수동으로 쏘면 선행 조준의 차이를 볼 수 있다. R로 다른 표적을 선택할 수 있다. 연습 표적은 관성 비행하며 아직 전투 AI는 없다.

- 포탑 추적: 사격통제가 매 틱 주는 조준 방향의 회전 속도를 재서 포탑을 한 틱 앞으로 미리 돌린다. 그래서 가로지르는 표적도 포탑 구동 속도(`yawRate`·`elevationRate`)까지는 따라가며 쏜다. 전함 주포는 초당 8°라 호위함(200 m/s)은 약 1.4 km 밖, 요격함(380 m/s)은 약 2.7 km 밖에서만 따라가고 근거리로 스쳐 가는 요격함은 놓친다. 호위함 포탑(초당 48°)은 요격함도 따라간다. 검사: `dotnet run --project tests/SimChecks -- --tracking`.

자동 비교와 장거리 사격 재현:

```powershell
.\tools\shot.ps1 rail_assist --ballistics-test=DD-X1 --target-speed=180 --pulses=6 --frames=240 --no-ai
.\tools\shot.ps1 rail_manual --ballistics-test=DD-X1 --target-speed=180 --pulses=6 --frames=240 --manual-fire --no-ai
.\tools\shot.ps1 rail_long --control=BB-01 --ballistics-test=DD-X1 --test-distance=50000 --pulses=1 --frames=600 --far
```

자동 비교에서는 카메라가 표적의 현재 위치를 따라간다. ON은 그 위에 선행 보정을 더하고 OFF는 현재 위치만 겨냥한다. 스크린샷 도구는 렌더링을 60Hz로 고정해 틱과 발사 시각을 재현한다.

## 구형 전술 레이더와 자유 관찰

좌상단에 사각 창 없이 구형 3D 상대 지도만 띄운다. 구의 전방·상부 축은 함선 기준으로 고정되며, 자유 관찰이나 피격 흔들림에 따라 회전하지 않는다. 높이선으로 함선의 위·아래 차이를 표시한다. 거리는 선형 축척이며 기본 반경은 초기 150 km 교전을 포함하는 200 km다.

아군은 파랑 점, 식별된 적은 붉은 마름모, 미식별 접촉은 주황 빈 원이다. 한 번도 탐지하지 못한 적은 숨기며 센서 추정 위치와 오차 범위를 사용한다. 가까이 모인 표적은 개수로 묶고, 범위 밖 선택 표적은 구의 경계에 별도로 표시한다. `PgUp/PgDn` 또는 커서를 놓고 지도 위에서 휠을 돌려 범위를 바꾼다. 구를 클릭하거나 `M`을 누르면 전체 지도를 연다. F1 도움말을 열 때에는 구를 잠깐 숨긴다.

접촉이 끊기면 **마지막 관측 위치와 식별 상태를 회색으로 남기고 `신호 소실`을 표시**한다. 레이더·전체 지도·화면 브래킷과 표적 패널에 같은 기록을 쓰며, 표적 선택과 기존 사격 지시의 대상은 유지한다. `R`로 소실 접촉도 다시 선택할 수 있다. 마지막 확인 시각, 호출부호·함종, 실드·계통 상태·파괴 모듈 수를 보관하고, 소실 중 실제 이동이나 피해·격침으로 기록을 갱신하지 않는다. 처음부터 미식별이었던 접촉은 회색 미식별 기록만 남긴다. 재탐지 시 같은 접촉의 위치와 색을 갱신하고, 다시 식별되면 피해 상태도 갱신한다. 기억은 이번 전투 동안 유지되며 새 전투에는 넘기지 않는다. 사격 잠금은 실시간 센서만 사용하므로 소실 기록으로 자동 사격·선행 보정·새 미사일 발사를 하지 않는다.

전체 지도도 전장 절대 좌표의 **구형 3D 지도**다. 큰 구 내부에 함선의 실제 입체 위치를 표시하고, 위도·경도선과 세계 X/Y/Z축, 앞·뒤 반구의 밝기 차이로 깊이를 보여 준다. 처음 열 때 아군과 탐지된 적 접촉을 모두 포함하고, 이후 함선이 움직이거나 지휘권이 넘어가도 지도 중심과 축척을 유지한다. 좌/우드래그로 회전, 중드래그로 이동, 휠로 커서 위치를 기준으로 확대·축소한다. 확대·이동으로 구 밖에 놓인 접촉은 개수를 표시한다. `Home` / 전체 보기 버튼으로 현재 알려진 전장을 다시 구 안에 맞추고 `M` / `Esc` / 닫기 버튼으로 돌아온다. 함선 클릭 시 호출부호·좌표·추정 오차를 확인하며, 미식별 적의 이름·함종은 공개하지 않는다. 높이선은 구 중심을 지나는 적도면에 연결한다.

지도를 보는 동안 전투와 현재 스로틀은 유지되고, 직접 사격·함선 조종·명령 메뉴 입력은 차단한다. 닫으면 요격함의 기존 마우스 캡처 상태를 복원한다. 닫기 클릭을 누른 채 돌아와도 발사하지 않는다. 개발용 `--full-map` 옵션으로 지도 화면 캡처를 할 수 있다.

호위함·전함에서 중클릭 관찰을 놓으면 그때의 상대 시점을 실제 시간으로 3초 유지한다. 이후 기존 감쇠 방식으로 함선 뒤 시점에 부드럽게 복귀한다. 다시 드래그하면 즉시 관찰을 이어가고, 다음 해제부터 새로 3초를 센다. 일시정지 중에는 유지 시간도 멈추며 함선 전환 시 초기화한다.

`.\tools\run.ps1 --navigation-test`는 유지 시간·복귀·프레임 속도·센서 필터·높이·큰 절대 좌표·전체 지도 이동/확대·구형 공간 경계 등을 45개 검사로 확인한다.

`.\tools\run.ps1 --contact-test`는 접촉 기록·소실·재탐지·미식별 보호·숨겨진 이동/피해 비노출·사격 잠금 분리 등을 22개 검사로 확인한다. `--shot=shots/contact_lost.png --control=BB-01 --no-ai --lost-contact-preview`로 소실 상태 화면을 캡처하며, `--full-map`을 더하면 전체 지도에서 해당 회색 접촉을 클릭한 화면을 확인한다.

## 전투 사운드

조종함의 엔진·부스트·주포·근접방어 발사, 실드 피격, 장갑 방어, 내부 관통, 모듈 파괴와 적 명중 피드백을 연결했다. 장갑 방어는 짧은 금속음, 관통은 낮은 충격음, 모듈 파괴는 긴 파열음으로 구분한다. 실드·장갑·관통·치명 피격에 각각 4개 샘플을 사용하고 직전 샘플은 제외한다. 함종별 기본 음높이에 최대 ±8.5% 피치·±1.2 dB 음량 변주를 더하며, 재생 중인 이전 샘플의 음높이는 유지한다. 명중 확인음은 결과에 따라 음높이가 달라지고 아군 오사는 적 명중음을 내지 않는다. 최대 16개 음성(짧은 효과 14개·연속음 2개)을 사용하며 짧은 간격의 같은 이벤트는 묶는다. 함선 전환·전투 재시작·시간 건너뛰기는 이전 이벤트를 다시 재생하지 않는다.

엔진음은 실제 추진 출력·전진 스로틀·추진계 상태를 따라 부드럽게 커지고 잦아든다. 정상 가동 중에는 정지·관성 비행에서도 낮은 기계 대기음이 남고, 스로틀을 유지한 순항은 더 강한 음을 유지한다. 부스트와 전진 스로틀을 함께 유지하면 최고 속도에 도달해 가속이 멈춰도 고출력 루프가 이어진다. 초기 음향 빌드보다 엔진 재생 게인을 약 10.5 dB, 부스트를 약 9.5 dB 높였다. 전함은 낮고 요격함은 높은 기계음을 쓴다. 엔진 파손·발전 정지·격침·관전 전환 시 연속음이 남지 않는다. 근접방어는 조종함 포대의 실제 발사 횟수로 짧은 3종 효과를 재생하며, 추적 중일 때는 울리지 않는다. 여러 포탑의 일제 사격은 90 ms 간격·최대 3음성으로 제한한다.

주변 아군·적 함선의 엔진·부스트·주포·근접방어·실드/장갑/내부 피격·격침, 미사일/드론 요격과 허공 폭발도 공간 음향으로 들린다. 카메라 방향에 따라 좌우가 바뀌고, 거리에 따라 부드럽게 줄어든다. 주변 엔진은 가청도 상위 4척(엔진·부스트 8음성), 짧은 효과는 12음성·프레임당 새 재생 4개로 제한한다. 이미 들리는 엔진에 작은 우선권을 주어 경계에서 급히 교체되지 않게 한다. 엔진 가청 반경은 전함/호위함/요격함 22/15/7 km, 주포 48/30 km, PD 10 km, 격침 60 km이며 끝부분에서 완전히 잦아든다. 자함 피격 때는 주변 음량을 잠깐 낮추고, 자함 엔진·발사·피격음은 공간 음향에서 중복하지 않는다. 전체 재생 상한은 자함 16 + 주변 20 = 36음성이다.

[Carbon Audio의 우선순위 처리](https://github.com/carbonengine/audio/blob/beff3bea148039f68c067537313b52123d8bc7c0/docs/sound-prioritization.md)를 참고해 거리·이벤트 중요도·활성 음원 우선권과 재생 수 제한을 Godot로 구현했다. Carbon의 Wwise 런타임이나 테스트 WAV, EVE 게임 음원을 가져온 것은 아니며 기존 생성 음원을 재사용한다. 공간 음향은 실제 카메라의 배정밀도 좌표와 방향을 받아 별도의 작은 좌표계에서 재생하므로 플로팅 원점 이동으로 소리 방향이 튀거나 도플러가 폭주하지 않는다. 전투 판정과 난수에는 관여하지 않는다.

`F10`으로 효과음을 끄고 켠다. `Esc` 일시정지 메뉴에서 음량과 화면 흔들림(0~100%, 기본 75%)을 조절하며 설정을 저장한다. 흔들림을 0%로 낮춰도 방향·피해 표시는 유지된다. 일시정지하면 재생 중인 소리와 피격 연출도 멈췄다가 이어진다. 공간 음향은 다음 물리 프레임에 시작할 예약음까지 중단하고 재개 위치를 보존한다. 효과음 버스에는 -1 dB 리미터를 두었다.

`.\tools\run.ps1 --fleet-audio-test`는 실제 주변 발사·피격·PD·격침, 과거 이벤트 중복 방지, 전환/복구/정리, 재생 상한과 카메라 기준 좌우·거리 감쇠·큰 좌표·음소거·일시정지·재개의 믹서 녹음을 104개 검사로 확인한다. 녹음은 `shots/fleet_audio_0.wav`~`fleet_audio_6.wav`에 남긴다(배포본은 사용자 데이터 폴더).

피격 순간 화면 가장자리의 호와 화살표가 탄이 날아온 방향을 알린다. 실드 흡수·장갑 방어·관통·모듈 파괴 순으로 충격이 커지고 전함은 느리게, 요격함은 빠르게 감쇠한다. 집중 포화에도 회전 흔들림은 1.8도를 넘지 않으며, 함선 물리·사격 원점·조준 방향을 바꾸지 않는다. 조준선은 흔들린 화면에서 실제 조준 방향에 맞춰 그린다. 레일건·미사일·근접방어의 확정 명중 기록을 공통으로 사용한다.

원거리 명중은 조준선의 원(실드)·마름모(장갑)·X(관통)·큰 X와 마름모(파괴), 결과 문구와 센서 표적 표시의 짧은 반응으로 구별한다. 실드 붕괴와 파괴한 모듈 이름을 표시한다. 표적이 나중에 파괴돼도 이전 명중 결과가 소급해 바뀌지 않으며, 늦게 도착한 미사일도 발사 순서와 관계없이 확인한다.

[Agent Audio](https://github.com/AIEGOBOT/agent-audio)의 Stable Audio 3 Medium / TFLite CPU로 세 가지 3초 원본을 생성했다. `assets/audio/source/`에 원본·프롬프트·생성 측정값을 보존하고, `assets/audio/manifest.json`에 고정 리비전·체크섬·길이·신호 검사 결과를 남겼다. 게임용 파일은 앞 공백을 줄이고 짧게 자른 뒤 -3 dB 피크와 시작·끝 페이드를 적용했다. 모델과 런타임은 저장소 밖의 사용자별 Agent Audio 폴더에 설치한다.

이 PC에서 원본 하나 생성에 약 41~52초, 생성 프로세스의 관측 메모리 최고치 약 9.6~10.7 GiB를 기록했다. 파일·재생·믹서 출력은 검사했으며 청감 품질은 직접 플레이하며 확인해야 한다.

`armor_block.wav`, `hull_penetration.wav`, `critical_impact.wav`는 기존 생성 음원을 자르고 필터·재샘플링·레이어 믹싱하여 파생했다. 새 모델 생성물은 아니며, 처리 코드는 `tools/prepare-impact-audio.py`, 원본과 결과 체크섬은 `assets/audio/impact_manifest.json`에 있다.

2026-10-10에 같은 로컬 모델로 엔진 5초·부스트 4초·근접방어 3초·금속 피탄 3초 원음을 추가 생성했다. `tools/prepare-flight-audio.py`가 기존 원음과 함께 편집하여 3.3초 엔진 루프, 2.5초 부스트 루프, PD 3종, 피격 변주 12종을 만든다. 원본·프롬프트는 `assets/audio/source/flight_requests.json`, 처리 방식·체크섬·신호 검사는 `assets/audio/flight_manifest.json`에 기록한다. 루프는 교차 페이드 후 낮은 변화량의 경계로 옮기고 PCM으로 임포트한다. 44.1 kHz 스테레오이며 루프 피크 -6 dB, 새 단발 효과 -4 dB, 파일 클리핑 0개다. 생성 원음은 배포본에서 제외한다.

```powershell
.\tools\run.ps1 --audio-test
.\tools\run.ps1 --feedback-test
.\tools\shot.ps1 feedback --control=IC-21 --no-ai --feedback-preview=Critical --frames=90
python .\tools\prepare-audio.py --output shots/audio-retune
```

`--audio-test`는 실제 무기·피격 변주·PD·엔진·부스트·대기·순항·관성 비행·파손·일시정지·음량 등 116개 검사를 수행하고 게임 오디오 버스의 출력을 `shots/audio_mix.wav`에 녹음한다(배포본은 쓰기 가능한 `user://audio_mix.wav`). `--feedback-test`는 실제 피해 분류·중복 방지·조준 보존·화면 투영·흔들림 상한 등 42개를 검사한다. 스크린샷 전용 `--feedback-preview` 값은 `Shield`, `Armor`, `Penetration`, `Critical`이다. 다듬기 도구는 원본을 보존하며 기존 출력 파일을 덮어쓰지 않는다.

## 탄도·실드·선체 파괴 연출

- 레일건은 짧은 백청색 전기 섬광과 포 주변 조명, 밝은 탄두와 뒤로 사라지는 꼬리로 발사를 표현한다. 화염·포연은 사용하지 않는다. 탄두·궤적의 최소 화면 크기를 거리와 망원 배율에 맞춰 유지하며, 청군은 청색·적군은 주황색 궤적으로 구분한다. 명중 직후에도 짧게 남는 궤적으로 입사 방향을 읽을 수 있다.
- 실드는 함체를 감싸는 보이지 않는 타원체다. 피격 위치 주변만 희미하게 드러나고, 탄도·미사일·어뢰의 실제 교차 판정과 같은 표면에서 반응한다. 근접방어포와 드론의 명중 예광선도 그 표면에서 끝난다. 붕괴 시 피격점에서 불규칙한 빛의 경계가 반대편으로 퍼지며 걷힌다. 실드 HP는 기존 전 방향 공용이며 방향별 잔량은 추가하지 않았다.
- 실드에 완전히 막힌 공격은 선체 파편을 만들지 않는다. 장갑 착탄 → 관통 → 모듈 파괴 순으로 에너지·함종 크기에 따라 금속 파편 수와 크기를 늘린다. 파편은 짧게 달아오른 뒤 어두워지며, 수명·표시 거리·최대 개수를 제한한다.
- 단순 무력화는 외형을 유지한다. 실제 치명 파괴가 발생하면 충돌·구조 붕괴·탄약고 유폭은 두 조각, 반응로·반물질 유폭은 여러 조각으로 현재 모델을 절단한다. 파편의 충돌 상자와 표시 위치가 함께 움직이며, 수리/초기화하면 원래 모델로 복구한다. 발전 정지 시 함체 발광도 꺼진다.
- 폭발 섬광은 최소 화면 크기를 유지하며 카메라 원거리 한계를 넘는 거리에서도 같은 방위에 표시한다. 실제 함체의 가림은 유지하고, 화면 밖 치명 폭발은 가장자리의 `섬광` 표시로 알린다.

- 미사일 연기 줄과 폭발(`BattleFx`, 티저에서 가져옴): 연소 중인 미사일 뒤로 끊김 없는 연기·불빛 줄, 미사일 폭발과 모듈 파괴에 여러 겹 불덩이·연기·충격파 고리·불꽃·순간광, 격침 시 선체를 따라 1.5초 연쇄 폭발 뒤 큰 섬광과 파편, 이후 40초 동안 불타는 잔해. 카메라에서 80 km 밖 사건은 만들지 않는다. 모든 판은 종류별 MultiMesh 네 개로 그리며 순간광은 8개를 돌려 쓴다. 성능 비교용으로 `--no-battle-fx`로 끈다.

현재 선체 분해는 자동 평면 절단과 간략한 절단면 표현이다. 개별 조각의 완전한 독립 강체 물리는 아직 아니며, 회전한 조각을 감싸는 충돌 상자와 모함의 공통 충돌 응답을 사용한다. 또한 활성 실드의 피격 면적이 기존 선체보다 커졌으므로 기존 승률 자료는 이 변경 이후의 밸런스를 대표하지 않는다. 무장 위력·탄속은 유지했다.

## 개발 티저 촬영

`--teaser`는 플레이용 장면과 분리된 38초 촬영 시퀀스다. 함대 전경 → 연장포 사격 → 요격함 배면 돌파 → 날아오는 탄두와 실드 붕괴 → AM 발사·추적·명중·선체 분해 → 타이틀, 여섯 컷을 30 fps로 진행한다. 마지막 공격은 장면을 초기화하지 않는 10초 연속 촬영이다. 실제 어뢰의 비행을 추적하며 접근 구간을 슬로모션으로 보여주고, 실제 함체 접촉 이벤트가 발생해야 촬영용 두 동강 연출을 시작한다. 명중 후 카메라가 빠지며 같은 함선의 잔해를 보여준다.

모델·포탑·탄도·실드·잔해 렌더러는 실제 게임 것을 사용하고 카메라·조명·배치·피격 시점과 보조 궤적은 연출한다. 돌파 컷의 요격함은 촬영을 위해 실드를 복원하며 어뢰 표적은 실드·사격통제 센서가 미리 파괴된 상태다. 명중 후 두 동강은 촬영용 조건이므로 일반 플레이의 전투 결과나 AM 단발 격침 확률을 보여주는 영상은 아니다. 영상 상단에 개발 중인 실제 엔진 연출임을 표시한다.

```powershell
.\tools\shot.ps1 teaser_battery --teaser-preview=battery --teaser-time=1.68
```

MP4·실제 사운드 타이밍·편집 사운드·검증 정보는 지정한 `shots/<Name>/`에 저장한다. [Godot Movie Maker의 공식 설정](https://docs.godotengine.org/en/4.5/tutorials/animation/creating_movies.html)에 따라 `movie` 전용 viewport 설정으로 모니터 크기와 관계없이 1920×1080으로 촬영하며 일반 플레이 해상도는 그대로다. `tools/mix-teaser.py`는 기존 게임 효과음을 늘이고 필터링해 저역 질감·박자·전환 상승음과 실제 발사/충격음을 배치한다. 새 AI 음악 생성물이나 외부 음악은 사용하지 않는다. 모델·효과 수정 후 같은 촬영 스크립트로 다시 렌더링할 수 있다. `--teaser-preview`는 `fleet`, `battery`, `run`, `shield`, `torpedo`, `title`을 지원한다.

## Carbon Trinity 전투 효과

MIT로 공개된 [Carbon Trinity](https://github.com/carbonengine/trinity)의 폭발 시간표, 포신별 발사 효과 선택·지연, 함선 크기·화면 크기에 따른 착탄 파편 조절을 C#으로 이식했다. 출처·고정 커밋·원본·해시는 [third_party/carbon-trinity](third_party/carbon-trinity/README.md)에 보존하며 배포 시 [MIT 고지](third_party/carbon-trinity/LICENSE.md)를 포함한다.

## 블렌더 함선 모델

화성권 **아레스 전함·데이모스 호위함·포보스 요격함**이 별도 함체로 추가됐다. 출항 화면에서 아군·적군 설계를 각각 고를 수 있으며 Blue/Red 팀과 Earth/Mars 설계는 독립적이다. 기존 지구권 3종의 JSON·Blender·GLB는 보존했다. 화성 제작은 `tools/build-mars-models.py`, 수작업 수정 후 내보내기는 공통 `tools/export-ship-models.py --ship mars_battleship`을 사용한다. 함체 성능·AI·ECM 지원·검증 명령은 [화성 함대 문서](docs/MARS_fleet.md)를 참고한다.

지구권 전함·호위함·요격함의 편집 원본은 `art/blender/*.blend`, 게임용 모델은 `assets/ships/*.glb`다. 각진 분할 장갑, 레일건, 미사일 발사부, 센서·ECM, 근접방어, 실드 발생기, 방열판, 주·보조 추진기를 배치했다. 전함 44,574 / 호위함 37,012 / 요격함 14,108 삼각형이며 선체·주포·근접방어포의 수평/고저 회전 부품을 나눠 각각 23/13/5개 메시, 12/12/10개 고유 재질로 내보낸다. Godot 임포트에서 LOD를 생성한다. 요격함에는 반물질 격리 포드 2개와 전용 모듈·발사 소켓을 추가했다. `tools/fit-antimatter-pod.py`는 기존 편집 부품을 보존하면서 누락된 포드만 추가하며 기본 제작 스크립트에서도 같은 배치를 사용한다. 후방 상부 보조 포탑은 `tools/fit-interceptor-dorsal-pd.py`로 기존 부품을 보존하며 추가했고 기본 제작 스크립트에도 반영했다.

원본의 `editable parts` 컬렉션에는 개별 부품을 남겼다. 숨겨진 `module_*` 마커와 `module hit volumes (guides)` 컬렉션은 기존 피해 모듈의 중심과 범위를 나타낸다. `socket_*`는 주포·미사일·근접방어 위치, `fx_*`는 엔진·자세 제어 분사 위치다. Blender의 위 +Z / 전방 +Y는 GLB를 통해 게임의 위 +Y / 전방 -Z로 변환된다. 원본은 미터 단위이며 기존 1,200m / 300m / 30m 함종 규격을 기준으로 제작했다.

주포·미사일·PD와 피해 계산은 `data/ships`를 계속 사용한다. 외형 장식이 별도 무기나 새로운 드론 발사 기능을 추가하지는 않는다. 엔진·RCS 분사는 기존 출력·기동·파손 상태를 따르며, 청·적 진영에 따라 식별 띠·실드·엔진 발광색이 바뀐다. 물리·피해·비행 성능 수치는 이번 모델 교체로 변경하지 않았다.

블렌더에서 수정하고 저장한 후에는 **export** 도구를 사용한다. `module_*`와 무장 마커를 옮겼다면 대응하는 JSON 좌표도 함께 맞춰야 내보내기 검사를 통과한다. 포탑은 `turret_gun_* → elevation_gun_* → recoil_gun_* → muzzle_gun_*_*` 구조다. 중립 자세로 저장하며 피벗·포구·사각은 JSON의 `railgun.mounts`에 맞춘다. 사선을 가리는 포탑 하우징 범위는 `housingCenter/housingHalfSize`로 조정한다. 내부 모듈 안내 상자는 게임에 내보내지 않는다. UV 텍스처와 파손 외형은 후속 아트 작업이다.

2026-10-10 부품 정렬: 전함 첫 주포의 낮은 포신 축에 포탑 외피를 맞추고, 주포의 회전축까지 이어지는 연결부와 고각 회전 공간을 추가했다. 호위함 하부 포탑·PD·갑판·함교·배관·RCS에 실제 선체까지 닿는 받침을 넣고, 요격기 미익을 좌우 대칭으로 맞췄다. `tools/align-ship-parts.py`는 저장된 원본에 한 번 적용하며 소켓/회전축 변환 불변을 검사한다. 기본 제작 도구도 같은 보정을 사용한다. `tools/audit-ship-models.py --root <repo> --output <folder> --check --render`를 Blender로 실행하면 정적 연결 후보·포신 높이/축 연결·미익 대칭을 검사하고 중립/55도 고각 이미지를 저장한다. AABB 연결 검사는 넓은 후보 검사이므로 최종 접촉과 가림은 렌더 이미지도 확인한다.

지구권 전함은 상부 2기·하부 1기, 호위함은 상부 1기·하부 1기의 주포가 따로 선회·장전·발사한다. 연장포는 두 포신에서 한 발씩 동시에 발사하며 탄도·명중·탄약·열·전투 기록은 탄환별로 처리한다. 마지막 잔탄이 한 발이면 한 포신만 발사한다. 선회 속도는 전함 수평 24°/s·고저 18°/s, 호위함 48°/s·36°/s이며 모듈 손상과 무장 전력에 영향을 받는다. 포신 고저 범위는 포탑 갑판 기준 -5°~85°이며 하부 포탑은 축을 뒤집어 아래쪽을 맡는다. 탄약은 전함 포탑당 240발(총 720), 호위함 포탑당 320발(총 640)로 늘려 기존의 포탑당 120/160회 사격을 유지한다. 재장전은 포탑 단위이며 한 발의 피해와 발열은 유지하므로 두 발 사격의 순간 화력·발열은 이전의 두 배다.

자동 사격은 포탑의 포구 중심에서 선행 조준을 계산하고, 선회가 끝나고 양쪽 포신의 사각·선체·다른 포탑·아군 사선 검사를 통과한 포만 발사한다. 수동 교리에서는 커서를 따라 선회하며 좌클릭을 유지하면 준비된 포탑들이 커서 지점을 조준하고 두 탄환이 실제 포신 방향으로 나란히 출발한다. 한 포탑이 파괴돼도 다른 포는 작동한다. 사격 패널에 포탑별 준비·장전·파손·소진 상태를 표시한다. 요격함 전방포는 고정식 단발이다.

근접방어포는 전함 8기·호위함 4기·요격함 2기이며, 회전 제한을 실제 사격 판정과 외형에 함께 적용한다. 최대 수평/고저 속도는 전함 60/45°/s, 호위함 90/60°/s, 요격함 90/60°/s다. 각 포대의 담당 방향에서 좌우 110°(요격함 100°), 갑판 기준 고저 -5~85° 안에서 움직인다. 담당 방위는 `normals`의 수평 성분이며 수직 법선만 있으면 설치 위치의 앞뒤 방향을 따른다. 기존 선체 사각도 함께 적용한다. 사거리의 1.5배에서 미리 추적하지만 실제 사거리 안이고 포신 오차가 1.5° 이하여야 발사한다. 근접 고속 표적을 놓치거나 가동 한계 밖으로 나가면 사격이 끊기며 재포착 시 몰아서 쏘지 않는다. 무장 전력 증가는 정격 회전 속도를 넘기지 못한다. `tools/rig-point-defense.py`는 기존 Blender 부품을 보존하며 회전축만 추가한다.

다포탑 재현: `tools/shot.ps1 turret_broadside --control=BB-01 --ballistics-test=BB-X1 --test-distance=12000 --test-bearing=65 --test-elevation=30 --target-speed=0 --doctrine=Focus --no-ai --frames=300`. `test-elevation`으로 상하 표적 각도를 지정한다. 독립 사격 검사는 `dotnet run --project tests/SimChecks/SimChecks.csproj -- --turrets`로 실행한다. AM 비행 수정 후 40판 보고서는 탄약 증량 전 기록이며, 새 탑재량의 장기 승률은 재측정이 필요하다.

## 구조

7단계 전투 계측: `.\tools\battle-batch.ps1 -Seeds (1..20) -Mirror -Parallel`은 40판을 `shots/batch/` CSV로 남긴다. `-Minutes 25 -Label baseline -Profile`로 종료 시각·라벨·틱 계측을 지정한다. `.\tools\batch-report.ps1 <CSV>`로 같은 형식의 보고 표를 만든다. 배치·승패 규칙과 단계별 결과는 [BALANCE_stage7](docs/BALANCE_stage7.md)에 있다. 개발 화면의 `--seed=N`도 같은 배치를 쓴다.

시뮬레이션 최적화 계측: `-Profile`은 전체 틱과 AI·사격통제·함선·충돌·탄도·미사일·PD·드론·센서의 구간별 시간도 `.sections.csv`에 기록한다. 국면별 및 0~300초/300~540초/540초 이후의 시간은 **60 Hz 외부 틱당 µs**이며, 하위 틱 4회의 합이다. `Tick`은 전체, `AI`는 하위 4구간을 포함하므로 함께 더하지 않는다. 성능 비교는 `-Parallel` 없이 한 판씩 실행하고, 병렬 실행은 전투 결과 비교에 쓴다. 측정 상태는 스레드별로 분리된다.

모든 배치는 `.summaries.json`도 저장한다. `-CompareSummaries <기준.summaries.json>`은 같은 시드·미러 조합의 `BattleLog.Summary()`를 글자 단위로 비교해 다르면 실패한다. `-TickProfile`은 세부 측정 없이 전체 틱만, `-Configuration Debug`는 헤드리스 Debug 빌드를 측정한다. `--perf-trace` 게임 로그는 `sim-profile` 행에 같은 단위의 구간 시간을 출력하며, 시작 전 `--advance` 구간은 첫 화면 프레임에서 제외한다. `--perf-no-sim-profile`을 함께 주면 프레임 측정만 유지해 세부 계측 오버헤드를 비교할 수 있다. 측정기 회귀 검사는 `dotnet run --project tests/SimChecks -c Release -- --profiler`, 기준 보고서는 [BALANCE_perf](docs/BALANCE_perf.md)다.

`python tools/analyze-sim-profile.py <배치.csv> --output <분석.json>`은 `.sections.csv`의 국면/시간대 합계와 하위 틱 호출 수를 검증하고 틱 수로 가중한 평균을 계산한다. 출력의 p99 범위는 판별 p99의 분포다. `-Profile`/`-TickProfile`의 `.ticks.csv`에는 모든 판의 틱 표본을 합친 전체/국면별 평균·p50·p95·p99·최대값을 별도로 기록하며, 분석 JSON의 `pooled_tick_ms`에 포함한다. 판별 p99의 평균을 합산 p99로 사용하지 않는다.


7단계 AI는 양 진영 공통 접근→미사일→포격선→근접/이탈 태세를 쓴다. 교리 조정값은 src/Sim/FleetDoctrine.cs에 모았다. 플레이어 편대는 태세 명령으로 덮어쓰지 않는다. 실드 소진 후 추진·무장·자세 추진기를 정밀 조준한다. 실제 40판 흐름과 미달 목표는 docs/BALANCE_stage7.md에 기록한다.
