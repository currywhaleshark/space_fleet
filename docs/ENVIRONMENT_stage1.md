## 4차 — 관측 차폐와 60초 전술 추적 기억

- `SensorNet`/`SmallContactSensors`에서 관측함·프로브별 시선을 검사한다. 다른 각도의 관측과 아군 데이터링크는 유지하며, 화성 호위 재머도 각 관측자까지의 시선으로 계산한다. 미사일·프로브의 소형 접촉은 차폐 직후 유효성을 잃는다.
- `SensorMemory`는 마지막 관측 위치·속도·시각만 저장하는 별도 질의다. 차폐 때문에 접촉을 잃은 경우에만 생성하고, 60초 만료 또는 재획득 시 제거한다. 거리·신호만으로 소실된 접촉에는 생성하지 않는다. 오차 증가율은 `max(100m/s, 마지막 속력 × 0.5)`를 사용했다. 느린 주력함도 60초 뒤 최소 6km, 고속 요격함은 더 큰 오차를 갖는다. 보장된 도달 영역이 아닌 속도 불확실도 근사다.
- `SimAI`, 편대/화성 교리와 점령 명령은 기억된 표적을 유지하되 사격·반물질 준비는 중단한다. 점령 편대는 거점 대기점을 계속 지킨다. 구조물이 있는 전장에서 적 회피도 관측값/예측값을 사용한다. 숨은 실제 위치·속도·격침 여부가 기억 추적에 영향을 주지 않는 검사를 포함했다.
- `BattleLog.SensorOcclusion`과 별도 환경 CSV에 진영별 잠금 소실 횟수·시간·재획득을 기록한다. 시간은 여러 표적을 합산한 **표적·초**로, 전투 경과 시간을 초과할 수 있다.

## 5차 — 무기·프로브 차폐

- `SimBallistics`는 장애물 첫 교차를 같은 240Hz 구간의 함선·소형 표적·드론 충돌과 비교한다. 먼저 닿은 물체만 처리한다. 자동 주포는 각 포구→예측점이 막히면 `Obstructed`(지형 가림), 수동 주포는 실제로 발사되어 구조물에서 소멸한다.
- `SimMissiles`, `CounterMissiles`, `Antimatter`는 공통 선분 충돌을 사용한다. 일반·경량·AM의 함선 직접 충돌과 구조물 충돌 순서를 비교한다. AM의 장애물 충돌은 별도 결과로 기록하고, 기존 순간 섬광을 사용한다. 구조물에 맞은 폭발은 뒤쪽 함선으로 피해를 전달하지 않는다. 탐색기 시선도 가리며 우회 유도는 추가하지 않았다.
- `DroneCombat.ClearDefenseLine`와 PD 후보 광선에 차폐를 적용했다. 근접신관이 벽 반대편의 미사일에 피해를 주는 경로도 차단했다. AI의 미사일/AM 발사는 막힌 방향에서 보류한다.
- `ReconProbes`는 투사 목적지가 구조물 안이면 사출 방향의 앞 표면으로 옮기고, 이동 선분이 충돌하면 소멸한다. 전개 도중 마주치는 장애물을 우회하지 않는다. 기존 무기/센서 데이터는 수정하지 않았다.
- 신규 무기/프로브 검사 82개: 실제 수동 발사, 동시 하위 틱의 첫 충돌, 세 미사일 계열, 원거리 좌표, 공유 잠금 아래 자동 발사 보류, 실제 PD/드론의 차폐·개방 사격, 프로브 표면 정지·고속 충돌.

## 6차 — 지도·HUD·카메라

- `ContactMemory`가 시뮬레이션의 추적 기억을 받아 HUD/레이더/지도가 같은 예측 위치를 표시한다. 숨은 실제 위치·피해는 갱신하지 않는다. 기억 상태는 점선 마름모와 커지는 점선 오차 원으로 표현한다. 60초 만료 후에는 기존 화면용 회색 기록을 마지막 관측 위치에 남긴다.
- `MapObstacles`는 공통 구/캡슐의 투영 윤곽을 중립 회색으로 그린다. 정거장 고리의 빈 공간을 채우지 않으며 구조물 이름을 새로 붙이지 않는다. 프로브 전개 미리보기도 실제 지형에 의해 잘린 목적지와 일치시켰다.
- `EnvironmentSymbols`와 포탑 방위구는 지형 차폐를 황색 받침 있는 사다리꼴로, 기존 선체 가림은 적색 X로 구분한다. 공유 센서 잠금이 유지되는 상황에서도 지형 때문에 자동 발사가 보류되는 실제 렌더링을 확인했다.
- `ChaseCamera`는 double 세계 좌표로 자함→시점 선분을 검사해 근평면 여유를 두고 앞으로 당긴다. 조준 방향/FOV는 유지하며 다음 프레임의 정상 궤도를 다시 검사하므로 장애물에서 벗어나면 복귀한다. 망원 궤적은 기존 규칙을 유지한다.
- 실제 Godot 검증: 환경 표시 19개, 기존 접촉 기억 22개, 장면 흐름 49개. HUD/지도/카메라/지형 사격 보류 4장의 캡처 확인. 카메라 전용 장면에서 원하는 거리 **2447.53m → 1084.94m**로 당겨짐을 기록했다. 캡처는 거점과 함선을 가까이 배치한 검사 장면이며 실제 점령전 배치는 변경하지 않았다.
- 빈 전장 비용을 줄이기 위해 탄도·미사일 반복문은 값 형식으로 실행 경로를 특수화했다. 같은 물리 코드에서 JIT가 빈 전장의 장애물 분기와 충돌 임시 값을 제거한다. 관측 신호 계산은 기존 무장애물 경로를 유지하고, 회피 루프 밖에서 장애물 유무를 확인한다. 수치·판정 순서를 바꾸는 최적화는 하지 않았다.
- 성능 측정의 변동을 확인하기 위해 최초 단독 계측, 같은 프로세스의 전투 단위 교차 실행, CPU 고정 실행, 120틱 단위 교차 실행을 모두 보존한다. 짧은 구간 교차 측정은 동일 논리 CPU(마스크 4)에서 기준판과 수정판의 순서를 매 구간 바꾸며, 한 전투 예열 뒤 5쌍을 측정한다. 44,856틱과 최종 요약이 매번 같음을 검사하고 측정 중 다른 빌드·시험·내보내기를 실행하지 않았다. 이 결과는 해당 시드의 비교이며 모든 전장·장비에 대한 비용 상한을 입증하지 않는다.

최종 빈 전장 교차 측정 중앙값은 **224.595 → 222.616µs/틱(−0.88%)**로 1% 기준 이내다. 쌍별 변화는 **−0.61 / +0.34 / −0.88 / −0.38 / +1.24%**로 실행 편차가 남는다. 반복문 특수화 전 같은 방법의 중앙값은 224.194 → 230.387µs(+2.76%)였다. 초기 측정의 기준 초과를 확인한 뒤 최적화했고, 불리한 반복도 제외하지 않았다. 전투 단위의 앞선 측정은 CPU 고정 여부에 따라서도 큰 편차를 보여 보조 진단으로 남긴다.

전체 SimChecks **15,614개**, 최종 Godot 장면 49개·환경 19개·접촉 기억 22개 통과. Windows 배포 EXE에서도 **11개 검사군 2,099개**(모델·전투 효과·음향·입력·망원·접촉·센서 범위·AM·환경) 통과했다.

최종 섬멸전·기함전 **40/40판 기준 요약 바이트 일치**. 점령전 20판의 요약·함선·환경·AM·프로브 CSV는 5차와 모두 바이트 일치하여 위 5차 비교표가 최종 결과이기도 하다. Blue/Red 10/10, 판정 시각 중앙값 661.275초, 구조물 충돌 14건, 갇힘 2건, 레일건 253발·미사일 261발 차단이다. 20판의 균등 승수를 일반적인 밸런스 보장으로 해석하지 않는다.
